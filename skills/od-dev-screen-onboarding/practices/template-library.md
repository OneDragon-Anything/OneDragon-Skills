# 模板库采集(图鉴规模建库工序)

> 本 skill(`od-dev-screen-onboarding`)的场景实践。SKILL.md §5.1 情形 3(变化的多实例 → 模板库 + SIFT)命中且要**成库采集**时读。三个坑(混来源 / 行索引对齐 / 中文路径)的触发条件与后果已在 SKILL.md §5.1 判据行,本文件给完整工序 —— 即便不读本文件,那三道防线也不依赖本文。

## 1. 适用判据

- 要建**多实例模板库**(全角色头像 / 全装备图标 / 全立绘:数量大、实例成体系);或
- **版本更新后补采**(图鉴每版本新增 / 改动实例,重跑本工序)。

## 2. 采源:图鉴优先

- **模板库来源优先游戏内图鉴**(完整立绘 + 名 + 数据,canonical;图鉴 / 教学目录 / 攻略大全),非从游戏画面裁(部分 / 变 / 缺名)。
- 图鉴需解锁先找解锁途径;**未解锁项**(暗色 / 阴影 /「未解锁」/ 不显示)跳过,只采已解锁(亮)项 —— 锁定项需先解锁或从别的源(官方 wiki)补;按「有规范名 + 已解锁」过滤。
- **整库同来源**(混来源 conf 崩,见 SKILL.md §5.1 三坑):确需 wiki 补采时,与图鉴采的**来源差异要在 config / 文档标明**。

## 3. 采全判据(别只取首屏)

- 建库 / 采集**穷尽所有实例**(滚动 / 翻页 / 切分类)—— 库残缺 = 运行时遇未采实例识别不了;
- **判据:新一屏去重后 0 新增 = 采全**;没到判据就继续翻;
- 同适用于游戏数据采集(全角色 / 全装备 / 全羁绊,别采样)。

## 4. 采库脚本持久化(反复任务,别当一次性产物)

版本更新会重跑,裁剪脚本(定位 + 紧贴裁 + 按规范名存)**存进项目持久脚本目录**,别扔会被清理的临时目录:

- 脚本 docstring 写采集流程(图鉴源 / 解锁前提 / 滚动采全判据 / 标签对齐法),版本更新照着重跑;下次重写 = 上次没存;
- 产物模板落位守 SKILL.md §5.3 模板资产目录规范。

## 5. 定位与对齐实现

- **定位**:形状轮廓法自动定位卡牌(SKILL.md §4.4 的 CV 方法),别硬编码坐标(单图推断易截断);
- **标签↔图标按空间位置对齐,不按行索引**(坑见 SKILL.md §5.1):按 **OCR 名的 y + CV 检测的列中心** 对齐;x 取图标列中心(**不取名字中心**,名字长短不一偏心);
- **存图**:`cv2.imencode` + `ndarray.tofile`(非 `cv2.imwrite` —— Windows 中文路径挂),读回 `np.fromfile + cv2.imdecode`。
