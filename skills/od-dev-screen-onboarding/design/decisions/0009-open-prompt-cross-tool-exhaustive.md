# 0009. 探索未知画面:open prompt + 三工具交叉 + 穷尽自查(防 视觉大模型 以偏概全)

- **Status**: accepted
- **Date**: 2026-08-04

## Context

ADR-0004 确立「视觉大模型 必需 + 状态推理不可信」,补的是「OCR 看不见的要 视觉大模型 补」。实战暴露**对称的另一面:视觉大模型 也会漏看,要 OCR + click 补**,且漏看根因不止"不懂游戏":

1. **显著性驱动漏看**:onboard 一个含**画面底部一排可选角色卡 + 选中态为非文本发光边框**的画面时,视觉大模型 单看漏了底部整排(非显眼区域)+ 漏了选中态(非文本)。根因:VLM 注意力受显著性(saliency)驱动,对边缘 / 底部 / 小元素 / 非文本状态变化天然不敏感 —— 这是 VLM 这类工具的**固有认知特性,非某个模型怪癖**(换 VLM 一样漏)。
2. **leading prompt 压制输出**:对 视觉大模型 用窄 / leading 问法("X 在哪?""有没有 Y?")时,VLM 只答所问、不报题外信息 → 漏看没问到的元素。这是 instruction-following 模型共性(prompt 形态决定吐多少),非模型 bug。
3. **单工具 premature 求助**:没交叉 OCR / click 验证,仅凭单次 视觉大模型 就下"机制不明"、去问用户。

## Decision Drivers

- **不漏元素**:VLM 显著性漏看 + OCR 盲区(非文本)互为盲区 → 必须交叉。
- **prompt 形态是工具**:open 枚举发现未知,narrow 定位已知;探索阶段用错形态就漏。
- **穷尽工具再升级**:问用户是高成本动作,穷尽自查(免费)才升级。

## Considered Options

1. **只靠 视觉大模型(单工具)**:显著性漏看 + leading prompt 漏看 → 以偏概全。
2. **视觉大模型 + OCR 交叉,但不 click**:能发现元素,但"是否选中 / 点了跳哪"等交互态仍靠 视觉大模型 推断(不可信)。
3. **open prompt + 三工具交叉 + 穷尽自查(选中)**:探索阶段先 open 枚举,视觉大模型 / OCR / click 交叉,冲突挖根因,穷尽后才问用户。

## Decision

选 3。画面未知(搞清"有什么 / 怎么交互")时,三招兜底(写进 SKILL.md §2):
1. **先 OPEN 再 narrow**:先 open 枚举(「描述全部可交互元素 + 你看到的一切」)再按发现 narrow;别用窄 / leading 问法(压制题外输出 → 漏看)。
2. **三工具交叉,冲突即信号**:视觉大模型(视觉枚举 / 非文本状态)+ OCR(文字 ground truth)+ click(交互验证)各取所长;结论不一致时挖下去而非二选一(常指向漏看 / 状态变化 / 误读)。
3. **穷尽自查再问用户**:open 视觉大模型 + OCR 交叉 + click 验证都做完仍搞不清,才升级问用户。

状态 / 交互推断不可信 → click 验证,沿用 ADR-0004「视觉大模型 状态推理不可信」+ SKILL.md「可交互对象判据」(直接试交互键看结果画面),不重复。

## Consequences

- **正向**:防以偏概全(显著性漏看 / leading 漏看 / 单工具 premature 求助三类失败都堵);冲突即信号能把"工具打架"转成发现线索。
- **负向**:open 枚举 + 三工具交叉比单次 视觉大模型 贵(多几轮调用);已知画面类型可退回 narrow(SKILL.md §2 既有「用户给提示 → 偏向典型元素问题」在画面类型已知时仍适用,本条只管"画面未知"的探索阶段)。
- **边界**:open prompt 用于**探索未知画面 / 交互**;定位已知元素坐标(给 screen_info 补槽位 / 卡牌坐标)用 narrow grounding 是合理的,不套本条(见 `od-dev-ui-region-detect`)。
