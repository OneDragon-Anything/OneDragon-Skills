# 0018. area 齐 ≠ 交互验证完:逐个交互验证从 §4 方法论提升进进度模板硬完成判据

- **Status**: accepted
- **Date**: 2026-08-11

## Context

备战画面建档:area 已建 48 个(识别锚点 + 信息 area 齐)、webp 归档过、id_mark 测试过 —— 按「画面建档①」进度模板完成判据(webp + id_mark + 收尾判据)看算"完成"。但实际**从没逐个 click 验证每个可交互元素的行为**(点后跳哪 / 可不可点 / 纯显示),导致漏认知:漏概率表入口(实为商店面板底部常驻 5 个百分比条,非交互展示)、不知哪些 area 纯显示 / 不可点 / 可交互、交互后子面板的新交互没递归验。

§4 缺口分析 + 卡住画面协议第 3 步**都说了**「逐个交互验证行为(每个元素 click → 点后跳哪)」。但**进度模板「画面建档①」完成判据没列它** —— 完成判据是「归档 webp + id_mark 测试 + 信息源三层对齐 + 信息 area 齐」,没把「逐个交互验证行为」当硬门。

根因:

1. **area 坐标定位 = 元素存在,≠ 交互已知**。area 在 screen_info / analyze 命中只说明「这个坐标有东西」,不说明「点它跳哪 / 可不可点 / 纯显示」。存在 vs 行为是不同认知层,area 齐不等于行为已知。
2. **进度模板是硬门(驱动行为),§4 是方法论(不强制)**。按状态机 / 进度模板驱动建档时,完成判据驱动「算没算完」;§4 在「怎么做」层。把关键步骤放方法论不放完成判据 → 按模板走时跳过(正是本案:area 齐 + webp + id_mark 过 → 标完成,从没 click 验行为)。与 progress-tracking「判据该进哪」同源(完成判据 vs 方法论的驱动差)。
3. **交互有递归深度**。点元素可能触发子面板 / 子态,子面板里又有新可交互元素。只验第一层 = 把子面板当「死景」,漏里面的交互 / 信息。交互验证要递归到叶子。

**否决项(拟改「别预设信息呈现形式」)**:feedback 原提「找信息别预设它必是点击弹窗,也可能常驻显示」。但经审:**信息要么画面可见(§1 / §2 认知穷尽该看到)要么交互才出(§4 穷举交互覆盖)**,「别预设呈现形式」无独立价值。概率表漏的本质是「automation 要读信息」漏(显示信息),而建档①防跑偏点已写「automation 所需所有信息 area 都要建」—— 根因是防跑偏点没进完成判据(同根因 2),不需要新加「别预设呈现形式」。

## Decision Drivers

- **硬门驱动行为**:进度模板完成判据是「算没算完」的硬门;§4 方法论是「怎么做」不强制。按模板驱动时,只有进完成判据的才被守。
- **认知完整 = 行为已知**:建档 / 快修判据「能说出全部可交互元素 + 各自点后跳哪」要求行为认知,光 area 齐(存在)不够。
- **递归深探**:子面板里的新交互也是认知的一部分(ADR-0013 穷举的延伸)。

## Considered Options

1. **保持现状(§4 方法论,不进完成判据)**:按模板走时跳过(本案实证)(否)。
2. **进度模板「画面建档①」完成判据加硬门「逐个交互验证行为含递归」(选中)**:把 §4 的「逐个交互验证」提升进完成判据;配套 §3 doc 可交互元素节强化产出物(记行为 + 递归);§4 开头点睛「area 齐 ≠ 交互验证完」。
3. **加「别预设信息呈现形式」**:否决(见 Context 否决项),无独立价值,被认知穷尽 + 穷举交互覆盖。

## Decision

选 2。

- **进度模板「画面建档①」完成判据**加「§4 逐个交互验证行为(每个可交互元素 click → 点后跳哪 + 交互后子态递归深探)记入 doc 可交互元素节」;防跑偏点加「别把 area 齐当交互验证完(area=存在 ≠ 行为;每个可交互元素 click 验过,子面板新交互递归验到叶子)」。
- **§4 开头点睛**:加「area 齐 ≠ 交互验证完」(存在 vs 行为不同认知层)。
- **§3 doc「可交互元素」节强化产出物**:加「每个元素记点后行为 + 交互后子面板新交互递归验 + 记(到叶子)」。

## Consequences

- **正向**:area 齐 + webp + id_mark 不再误判完成;逐个交互验证(含递归)成硬门 → 行为认知完整;子面板新交互不漏。
- **负向**:每画面建档多一步(逐个 click 验行为 + 递归);简单画面也守(但本就是建档 / 快修判据要求,非新增负担,是提升到硬门)。
- **边界**:可交互元素的行为靠 click 验;显示信息(非交互)靠「automation 要读信息」+ 认知穷尽(建档①已有防跑偏点)—— 两者合起来才是建档完整。
