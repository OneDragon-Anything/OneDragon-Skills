# 0021 子态建模归属四问判据(独立屏 vs 父屏 area)

- **状态**:accepted
- **日期**:2026-08-17

## Context

项目首例「正交可叠加子态」(按钮文案替换 + 与另一子态可叠加、不遮挡、dispatch 相同)暴露判据缺口:此前 skill 只写「独立画面 vs 子态」的**文档归属**两类,screen_info 建模归属无判据;项目先例(弹窗/详情类)全是「互斥 + 遮挡 + dispatch 不同」碰巧四问全中的独立屏案例,照抄先例对正交态会组合爆炸(N×M 屏,叠加帧哪个都 `is_precise` 不了)。

反馈原案的四问中「遮挡 → 被迫独立建屏」经 review 补强:遮挡发生时父屏可能**换一组不被盖的 id_mark** 留子态在父屏;且被盖元素做「父屏含被盖元素」双向配合(ADR 同 skill 场景①④)本身是区分度正收益,机械「能换就换」反而损失。

## Decision Drivers

1. 归属判据必须是可执行的决策序,不是两类枚举。
2. 与 §3.5 id_mark 场景①④(故意用被盖元素)不矛盾——问②要给换锚 vs 留被盖锚的权衡口。
3. 公共 skill 泛化:不提具体游戏/项目案例细节。

## Considered Options

- **只补一句「正交态留父屏」**(否决:遮挡/换锚路径仍无判据,下一个遮挡可换锚案例照样即兴)。
- **四问但遮挡=无条件独立**(否决:漏「父屏换锚」中间路径,且与场景①④「故意留被盖元素」前后矛盾)。
- **四问 + 遮挡三段式(不盖→过 / 盖可换锚→比区分度收益再定 / 换不掉或故意留→独立)**(采纳)。
- 放 ui-region-detect(否决:那是坐标检测方法论,归属判据属建档流程决策点)。

## Decision

§3 开头新增「子态建模归属判据(四问)」:① dispatch(需不同分支→独立候选);② 遮挡三段式(含换锚权衡与双向配合收益);③ 正交一票否决独立屏;④ 粒度(元素级→父屏 area / 布局级→独立屏)。doc 归属同判据。配套「查找端纪律」:跨屏正交元素的消费端代码不得锁死单一屏查(叠加态按屏查落空),查多屏或全屏 OCR 兜底。联动:§3.5 id_mark 场景入口补「先过 §3 四问」前置;主流程第 5 步补指针。
