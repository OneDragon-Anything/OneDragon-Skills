# 0016. 跨玩法偏离协议:认知完整但非目标玩法 → 导航回目标(别停)

- **Status**: accepted
- **Date**: 2026-08-11

## Context

ADR-0012 的「卡住画面协议」覆盖「认知不完整(说不出画面全部可交互元素 + 各自点后跳哪)→ 强制探索补全」。2026-08-10 货币战争(CW)开发暴露一个**卡住协议没覆盖的相邻场景**:

调试 CW(玩法 A)时 `analyze` 命中模拟宇宙(玩法 B)位面选择画面 = **跨玩法偏离**。智能体**认得**这是模拟宇宙(认知完整),只是它**非目标玩法** CW。但 `description` 触发条件写「你不完全认识的画面」→ 「认得 B」没触发卡住协议 → 智能体当「环境状态(用户在玩 / 偏离)」跳过,直接**停**,没导航回目标。

根因三层:

1. **description 触发条件偏「认知不完整」**:「不完全认识画面」是卡住协议的触发词,但跨玩法偏离是「认知完整(知是 B)但非目标 A」—— description 没覆盖后者 → under-trigger → 智能体停了。
2. **没有「导航回目标」分支**:卡住协议的处理是「探索出口补全认知」(适用于不懂画面时)。但跨玩法偏离的问题不是「不懂 B」而是「该回 A」—— 探索 B 的出口是本末倒置(要离开 B 不是理解 B),需要的是**导航回 A**。
3. **心智锚缺失**:智能体把「偏离到别的玩法」归类为「环境状态可忽略」,而非「bot 职责内的可恢复状态」—— 缺「偏离 → 导航回,别停」的心智锚。

用户原则(2026-08-10):「就算偏离到别的玩法,也要想办法导航回目标玩法,而不是停」。

这是**通用方法论 gap**:任何玩法自动化遇跨玩法偏离都会停(非某具体玩法 / 模型特异)。判据是方法论(认知完整但非目标 → 导航回),非具体游戏例子。

## Decision Drivers

- **under-trigger 修复**:description 只触发「认知不完整」→ 需补「认知完整但非目标玩法」触发词,否则智能体遇到也不认。
- **与卡住协议区分(防混淆)**:两种场景触发面相似(analyze 命中非预期画面),但处理相反 —— 卡住 = 探索出口补认知;偏离 = 导航回目标。必须显式区分,否则智能体会拿卡住协议去「探索 B」而非「回 A」。
- **不停(用户原则)**:偏离是可恢复运行时状态,导航回目标是 bot 职责,不是中断 / 等指示理由。
- **建档闭环**:偏离路径 + 恢复导航链入 screen_info / doc → bot 后续自动恢复(而非每次人工导航)。这是 onboarding 角度,归本 skill。

## Considered Options

1. **当卡住协议处理(探索 B 出口后继续)**:问题是「该回 A」不是「不懂 B」。探索 B 的交互行为是本末倒置 —— 要离开 B 不是理解 B;且卡住协议的「穷举交互观察」会浪费在 B 上。**否**。
2. **停,等用户指示**:用户原则明确否决 —— 偏离可恢复,导航回目标是 bot 职责,不是中断理由。**否**。
3. **导航回目标 A(选中)**:独立分支 —— 回溯偏离源 → 找 B 出口到枢纽 → 导航 A 入口路径 → 回 A 继续 → 建档偏离 + 恢复供自动恢复。判据:认知完整(知是 B)但非目标 → 导航回(非探索)。
4. **不进本 skill(只进 gameplay-automation)**:**部分否**。运行时 bot 自主导航回(无人值守)归 gameplay-automation;但① description 触发 gap(under-trigger)是本 skill 的问题;② 调试 / 建档角度(dev 遇偏离怎么回 + 把恢复路径建进 screen_info / doc)归本 skill。两者互补,本 ADR 处理本 skill 部分。

## Decision

选 3(+ 4 的归属划分:运行时自主导航回 → gameplay-automation 另行;本 skill 处理 description 触发 + 调试 / 建档角度)。

- **SKILL.md `description`** 补触发词:「bot 运行 / 调试偏离到非目标玩法画面」(认知完整但非目标 → 导航回目标,别停)。
- **SKILL.md 新增「跨玩法偏离协议」节**(卡住画面协议的**并列分支**,非子节):① 与卡住协议的区分判据(认知完整但非目标 vs 认知不完整);② 5 步处理(回溯源 → 找 B 出口 → 导航回 A → 继续 → 建档防再偏);③「禁止停」禁令。
- **建档闭环**:偏离路径(A→B 误触入口)+ 恢复导航(枢纽→A 入口)链入 screen_info `goto_list` / area + screen doc 状态流转,复用既有建档机制,不引入新工具。

## Consequences

- **正向**:跨玩法偏离不再 under-trigger;智能体导航回目标而非停;偏离 + 恢复建档后 bot 可自动恢复。
- **负向**:SKILL.md 增 ~16 行(新协议节);跨玩法偏离的「导航回 A 路径」依赖 A / B 的画面档案齐全(若 A 入口路径未建档 → 导航可能卡,回退问用户)。
- **边界**:本协议是调试 / 建档角度;bot 自主运行时(无人值守)遇跨玩法偏离自动导航回 → gameplay-automation skill(待补,见 feedback「也该进 gameplay-automation」)。
- **与卡住协议关系**:并列分支,共享「analyze 命中非预期画面」触发,但认知状态 + 处理相反。先判「是不是跨玩法偏离」(认知完整但非目标 → 导航回),再判「是不是卡住」(认知不完整 → 探索)。
