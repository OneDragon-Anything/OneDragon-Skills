# 0020. 停机后画面已流转的离线降级路径(只剩存证截图:先判合法性再降级建档)

## Status

accepted(2026-08-16)

## Context

随机 / 条件态节(ADR-0017)的标准流程假设「停机钩子 = 画面停住、可当场穷举交互验证」。实战(SR 货币战争,2026-08-16 M37):停机钩子留画面后,开发者接管时游戏已自然流转(结算屏继续推进节点),只剩存档截图;skill 对「只有截图、画面没了」没有指引,接管智能体走了弯路:直接拿截图裁剪 + 视觉大模型认卡 —— 裁剪裁到纯背景(裁剪框选错,后续识别全废)、视觉大模型推测低置信来回矛盾。停机后画面流转并不罕见:bot 停了,游戏 UI 动画 / 结算 / 计时仍继续走。

## Decision Drivers

- 降级路径的正确序恰是本 skill 通用诊断序(§1 客观识别先行 → §2 视觉大模型只补客观描述 → 冲突客观仲裁),但接管语境(认卡 / 建档)下智能体没想到套用 —— 缺显式小节就会缺触发。
- 非法帧(钩子在收起态误触发所留)与合法帧(目标态真出现但画面已流转)处理方向完全不同:前者要修钩子前置门(见 `od-dev-gameplay-automation` ADR-0011),后者才降级建档 —— 必须先判画面态合法性再分流。

## Considered Options

1. **不补,视作个案**:否决 —— 停机后画面流转实际常见(结算 / UI 动画不因 bot 停而停);缺指引时接管智能体实测走了裁剪 + 视觉大模型推测弯路,可复现。
2. **补在 write-operation 钩子节(接管步)**:否决 —— 那是 op 级实现层;降级后怎么建档是画面建档路径,归 screen-onboarding,放那边要么双源要么越层。
3. **随机 / 条件态节补降级小节 + runtime-craft 接管步一行指针**:✓ 判据与降级建档流程在本节,接管入口(write-operation)只留指针,引用闭环。

## Decision

选 3。小节三步:① 离线 `analyze_screen` 判存证截图画面态合法性,非法 → 修钩子前置门、别拿非法帧建档;② 合法 → 视觉大模型客观描述补全,存证截图**原图直喂不先裁剪**;③ 按 §1-§9 建档但标「离线降级:交互验证缺」,交互行为标「待现场补」。

VLM 提问规范**引本 skill §2**(开放式枚举 / 只信客观描述),不引项目全局入口文件 —— 公共 skill 只能引用闭包内(已提交仓库)文件,项目 / 机器本地文件在别的机器 / CI 上不存在(规范 3 引用卫生 + 公共 skill 泛化约束;反馈原案写引全局 AGENTS,落地时修正)。

## Consequences

- **正向**:接管时画面已流转有章可循;非法帧被识别为钩子误触发证据(与前置门防线互补:前置门防运行时误触发,降级路径处理已发生的事实);裁剪弯路(裁错框全废)有显式禁令。
- **边界**:交互行为(点后跳转 / 穷举验证)离线做不了,只能标「待现场补」等下次遇该态 —— 降级不等于完整建档。
