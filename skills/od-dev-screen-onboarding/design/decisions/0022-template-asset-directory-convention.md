# 0022 模板资产目录规范(首建即守)

- **状态**:accepted
- **日期**:2026-08-17

## Context

首个玩法规模化后模板资产长到多处散布(模板根平级多个玩法目录之外,还有藏进源码包目录的),并出现同类同名双库(图鉴烘焙版 vs 手采版并存)——skill 建档流程讲到「存模板」但完全没讲「存哪、目录怎么组织」,每个 agent 首次建模板时即兴决定,规模化后必然散布。

## Decision Drivers

1. 规范必须在「agent 正要做存放决定的那一步」出现才会被遵守(首建时刻 = 建档流程裁模板/入档步骤)。
2. 散布的另一半根因是同名双库与来源混库,只写「统一目录」治不了。
3. 公共 skill 泛化:不提具体项目目录名 / 玩法名。

## Considered Options

- **放 od-dev-ui-region-detect**(否决:管坐标检测方法论,不管产物存放)。
- **放 od-dev-gameplay-automation**(否决:玩法 playbook 离执行点远一层——首个玩法建档的 agent 不会去翻 playbook 找「模板存哪」,而散布正是首次建档即兴决定的)。
- **新建独立「资产规范」skill**(否决:单一条目撑不起一个 skill,多一个检索入口稀释)。
- **只写「统一目录」不写双库/来源纪律**(否决:治不了同名双库与来源混库这半边根因)。
- **screen-onboarding §5 新增「模板资产目录规范」节**(采纳:与「怎么截/什么结构/怎么入档」同点,是同一决策缺的「存哪」维度)。

## Decision

按采纳方案落地:统一 `<模板根>/<玩法>/<类型>/`(类型名自明语义)+ 源码包内禁放资产 + 同类目标只一个库(禁无名分双库,并存须标来源与用途)+ 生成器产物标注来源 + 首建即落位(禁「先散放后迁」)。§5 情形 3 采库脚本条补产物落位指针。
