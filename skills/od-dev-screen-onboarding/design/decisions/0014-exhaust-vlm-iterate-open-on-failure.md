# 0014. 视觉大模型交互流程:画面不重复 + 让它提需求 + 交互失败迭代 + 穷尽才升级

- **Status**: accepted
- **Date**: 2026-08-07

## Context

视觉大模型是唯一能真正「看懂」画面的途径(OCR 看不见图形 / 图标 / 布局 / 状态;点击只验证已知坐标)。本 ADR 原立「交互无效不放弃,叠加失败迭代提问」(给的方式试了无效,继续问还有没有别的方式,到给不出新方式才算穷尽)。

实战(某玩法节点开发)暴露**更深的陷阱**:不只「交互无效要不要放弃」,还有「喂知识」本身会带偏 —— 模型(开发者 / agent)分不清「查来的客观知识」和「自己推理出的假设」,把假设当「理解了」喂给视觉大模型,带偏它(实测:带假设问视觉大模型多次全失败;改成只给客观知识 + 问题让它自己看 → 1 次解决)。根因:模型对「查来的」和「自己推理的」信心一样高,天然混淆。

进一步(讨论深化):连「判断视觉大模型缺什么知识」都别开发者做 —— 开发者以为「它缺玩法机制」也是主观假设。正解:**让视觉大模型自己提需求**(「你需要什么更多信息?」),只按它说的查 / 答,不假设它缺什么。

另两点:(1)**画面信息不重复告诉视觉大模型** —— 它自己能看画面,开发者替它描述(「画面上有 X」)= 开发者的理解,可能错带偏;让它自己看。(2)**查的来源**:本地代码 / 文档可能含**猜测污染**(开发中可能把猜测当事实记、没标「猜测」,尤其 agent 自主开发时),用时存疑 + 交叉验证,外部权威优先。

## Decision Drivers

- **去主观**:不假设视觉大模型缺什么(让它自己提需求);不替它描述画面(它自己看)—— 开发者主观判断(假设 / 复述)会带偏。
- **穷尽唯一看懂图的途径**:视觉大模型是认知画面的主线,穷尽前不放弃(交互无效迭代 + 按需补知识到穷尽)。
- **本地可能错**:代码 / 文档可能猜测污染,用时存疑 + 交叉验证,外部权威优先。

## Considered Options

1. **让视觉大模型提需求,只按它说的查 / 答(选中)** vs 开发者判断它缺什么然后喂:否 —— 开发者分不清客观知识 vs 自己的假设,把假设当知识喂会带偏(实测)。
2. **画面信息不重复告诉视觉大模型(选中)** vs 替它描述画面:否 —— 复述 = 开发者的理解,可能错带偏。
3. **交互无效不放弃,叠加失败迭代(选中)** vs 一次无效就放弃:否 —— 视觉大模型可能还有别的方式没问到(单次会漏)。
4. **查的来源:外部权威优先,本地存疑(选中)** vs 无脑信本地代码 / 文档:否 —— 本地可能猜测污染。
5. **永不放弃(无限迭代)** vs 穷尽才升级(选中):否 —— 要有判据(给不出新方式 + 提不出新需求 = 穷尽),否则无限循环。

## Decision

SKILL.md §2「探索未知画面」写成完整视觉大模型交互流程(认知元素 + 推进交互):

- **认知画面有什么元素**:开放式提问 + 三工具交叉(视觉大模型 / OCR / 点击)+ 穷尽自查。
- **画面信息不重复告诉视觉大模型**(独立原则):它自己看,别替它描述。
- **怎么交互推进**(让它提需求,别假设它缺什么):
  1. 首问零知识「画面怎么交互能推进?」。
  2. 给了方式 → 试;无效 → 叠加失败继续问(原 ADR-0014 核心)。答不出 → 问它「你需要什么更多信息?」,只按它说的查 / 答。
  3. 来源:游戏内图鉴 > 攻略网站 > 本地代码 / 文档(存疑 + 交叉验证)。
  4. 穷尽(给不出新方式 + 提不出新需求)才升级问用户。

**不进 skill 的**:具体玩法节点的机制(项目 doc);本地文档被污染的源头治理(怎么维护文档不污染 —— 另一问题,本 ADR 只管「用时存疑 + 交叉验证」)。

## Consequences

- **正向**:去主观带偏(让它提需求 + 画面不重复);穷尽唯一看懂图途径;本地猜测污染有防线(存疑 + 交叉验证)。
- **代价**:多轮交互(零知识首问 + 按需补),比「一次喂全」慢,但比「带偏后反复废 fire」省。
- **边界**:视觉大模型状态推理不可信依旧(认知元素时点击验证,见 §2);本地文档污染的源头治理是另一问题(本 ADR 只管用时)。
- **推翻它会碎什么**:删「让它提需求」→ 开发者又主观判断该喂什么 → 假设带偏;删「画面不重复」→ 替它描述带偏;删「穷尽迭代」→ 一次无效放弃,浪费唯一途径。
