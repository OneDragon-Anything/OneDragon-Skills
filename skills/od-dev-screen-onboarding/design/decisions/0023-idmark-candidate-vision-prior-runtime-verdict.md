# ADR-0023: id_mark 选锚流程(视觉枚举候选 + 跨帧验稳定 + 运行时匹配定谳)

## Status

accepted(2026-08-29)

## Context

id_mark 方法论成形于无视觉时代:候选靠全量 OCR 逐条翻、稳定性只给了定义(「每次进该画面都稳定出现 + 内容不变」)没给检测手段。具备原生视觉的模型加入后,两个 gap 暴露:

1. **动态内容位误选**。实机案例:某画面右上角的运营活动图标位(内容随版本/活动轮换)被选为 id_mark——单帧看完全满足「独有且稳定」,实际换一帧 conf 就从命中跌到不中。OCR / 模板匹配层**原理上看不出「内容变没变」**(它们只回答「当前帧匹配没有」),逐帧对比是唯一检测手段,而视觉正是做跨帧对比最便宜的工具。
2. **视觉先验与运行时判据的混淆风险**。视觉模型会判断「这个图标很独特 / 这行字很清楚」,但 bot 运行时用的是 OCR conf / LCS / 模板阈值——艺术字、低对比度、背景渐变、动画光效都会让「视觉看着没问题」的候选在运行时失配。视觉的「独有」判断只能当先验,不能当依据。

## Considered Options

1. **不加流程,维持「稳定」定义 + 事后 id_mark 测试兜底** —— 否。id_mark 测试用的是归档 fixture,测试通过只证明「在归档的那几帧上命中」;若归档帧与建档选锚同源同时间,内容位轮换要在下一次版本更新后才暴露,且表现为运行期识别失效而非测试红——排查成本远高于选锚时一次跨帧对比。
2. **把视觉判读直接作为 id_mark 依据(信任模型看图定锚)** —— 否。视觉判据与运行时判据(OCR conf / LCS / 模板阈值)不同源,视觉放行的候选运行时可能失配;且会随模型换代漂移,不可复现。
3. **视觉枚举候选 + 跨帧验稳定 + 兄弟屏粗筛 + 运行时匹配定谳的四步流程,视觉仅作先验** —— 采纳。各司其职:视觉补「候选发现与内容位识别」的效率缺口,运行时匹配保持唯一裁决地位,既有 id_mark 测试与碰撞场景①-④全部不变。

## Decision

§3.5「id_mark 怎么定」下新增**选锚流程(有视觉能力时)**四步:①视觉枚举候选(独有 + 静态);②跨帧验稳定——取 ≥2 张不同时间实拍帧视觉对比候选区域,**内容位(活动 banner / 新闻轮播 / 公告位)一票否决**;③兄弟屏归档帧粗筛碰撞;④运行时匹配定谳(§6 id_mark 测试不过就不选)。明确声明:视觉判读只是先验,最终资格由运行时匹配实测定谳。

## Consequences

- 正面:内容位误选在选锚当场被拦(跨帧对比),不再等到运行期识别失效;候选发现效率提升(视觉全景枚举替代逐条翻 OCR);碰撞从「事后测试抓」部分前移到「事前粗筛」。
- 代价/边界:多一次跨帧取图对比(候选帧通常已在 fixture / 历史截图中,增量成本低);「内容位」识别依赖视觉对槽位语义的判断,极端情况(首帧恰好是常驻内容的内容位)仍可能漏判——最终防线仍是 id_mark 测试 + 运行期 analyze 对账。
- 不改变既有裁决链:场景①-④、lcs_percent 阈值、id_mark 测试(真阳性 + 无碰撞)全部维持;本 ADR 只补「候选怎么找、怎么预筛」,不碰「怎么判合格」。
