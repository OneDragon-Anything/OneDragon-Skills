# 设计概览(what):外部审查循环

## 定位

AI agent 长期自主推进开发时的**他律看护层**:主 agent 按定时提醒,发起全新上下文的子 agent 对工作区工件做纪律审计与归因对抗审查,报告分诊消费。与主 agent 自身的纪律(进度树 checklist、行为校准)互补——本 skill 只管「外部新鲜上下文审查」这一层。

## 要解决的问题(机制)

1. **会话内自律衰减**:长对话里最初指令的权重被「当前最显眼的刺激」稀释,注意力窄化(逐帧观测冒充产出、陪跑注定失败的局);主 agent 审查自己时,会话上下文是负债。
2. **并行会话债**:多个会话并行开发时,任何单会话的自律管不到别的会话欠的债;工件级审计天然覆盖全工作区。
3. **归因未经攻击就被采信**:分析类结论的错误是逐补丁陷阱的源头,制度化对抗 = 把「采信前攻击」从自觉变结构。

## 边界(不管什么)

- **机械检测不归本 skill**:pattern/计数/阈值类监控写脚本哨兵(事件推送),见 ADR-0003;
- **主 agent 自身的进度纪律**(任务树写法/防偏离门)归 `od-dev-progress-tracking`;本 skill 的审计项以它为基准但不管它的内容;
- **worker 委派编排**(派活/审查 worker 产出)不在本 skill 范围——本 skill 只管「审查主 agent(及其并行会话)的工件与结论」。

## 构成

- 机制:定时提醒(30-60min)→ 主 agent 派发(可顺延/跳过/即时发起)→ 子 agent 审查 → 报告落盘 + 摘要推回 → 主 agent 分诊(仲裁/排期);
- 角色:纪律审计员 / 归因对抗审查员(攻击型);
- 配套:审查 prompt 模板落项目工作区、去重水位文件、报告目录(24h 清档)、会话恢复对账。

## 与相邻 skill 的关系

- `od-dev-progress-tracking`:主 agent 自律侧(任务树/防偏离门);本 skill 是外部他律侧,审计判据以其为基准;
- 项目专属进度 skill:审计子 agent 的纪律基准来源(prompt 内指示加载)。
