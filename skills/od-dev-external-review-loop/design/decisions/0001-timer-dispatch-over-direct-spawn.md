# ADR-0001 定时提醒+主agent派发,而非定时直启子agent

- **Status**: accepted
- **Date**: 2026-08-23

## Context

周期性外部审查需要一个触发机制。可选:①harness 的定时直启子 agent 专属机制(到点自动 spawn,不占会话回合);②标配的定时消息提醒 + 主 agent 收到后自己委派子 agent;③不定时,靠主 agent 自觉。

## Considered Options

1. **定时直启子 agent(专属插件)**——优点:到点必发、不依赖主 agent 记得;缺点:换 harness 就没了(可移植性差)、调度权不在主 agent(并发冲突/无新内容时照样烧)、配置是死的(派发指令随焦点过期)。
2. **定时提醒 + 主 agent 派发(标配组合)**——优点:可移植(提醒+委派是通用能力)、主 agent 保留调度阀(顺延/跳过/让位)、重大结论可**不等定时即刻发起对抗**、提醒内容随焦点换血;缺点:主 agent 被周期打断、理论上存在「提醒到了但主 agent 没派」的漏派风险。
3. **纯自觉不定时**——无机制保证,长会话自律衰减正是要解决的问题,不可用。

## Decision

选 2。定时是防遗忘的兜底,不是执行器;执行与调度权留在主 agent。

## Consequences

- 方法论跨 harness 可复用(用户点名的复用性要求);
- 对抗审查从「定时批量」升级为「即时+兜底」双模:重大归因落地即刻攻击,定时兜底防遗忘;
- 漏派风险由消费纪律对冲:提醒触发时必做派发或显式顺延,不静默吞掉;
- 主 agent 每周期被打断一次(读总判 1-3 行 + 派发),成本可接受。
