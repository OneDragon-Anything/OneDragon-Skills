# ADR-0002 审查角色两分:纪律审计 + 归因对抗

- **Status**: accepted
- **Date**: 2026-08-23

## Context

外部审查要覆盖两类不同性质的失败:①流程/纪律层(焦点漂移、决策记录欠账、临时钩子积压、逐补丁发散);②判断层(归因结论的证据链/替代解释/数据边界)。需要一个还是多个审查角色?

## Considered Options

1. **单一通用审查员**(一个 prompt 同时查流程+攻击归因)——prompt 混杂两类判据,报告噪声大;攻击姿态与审计姿态互相干扰(审计要全覆盖逐项报,对抗要深挖单点)。
2. **两角色:纪律审计 + 归因对抗**——判据、证据面、输出节奏都不同,分开各自设计;对抗天然低频(有新结论才有对象),配去重水位。
3. **更多角色**(如知识审计/进度审计再拆)——YAGNI,现有两类已覆盖实证失败模式;拆细 = 每角色冷启动成本×N。

## Decision

选 2。纪律审计(工件层全覆盖,周期必发)+ 归因对抗(攻击型,有新结论才发,去重水位防重复烧)。

## Consequences

- 两份 prompt 独立演化,互不污染;
- 审计员方差(两个干净上下文对同一债结论相反)是常态,消费侧以「证据指针仲裁」对冲——线索必须落规范登记处(进度树/决策记录),散在 commit message 或子会话 id 里谁查谁翻车;
- 对抗报告的方案建议标注「外部第二意见」:外部视角给方案是价值(不被主 agent 的历史包袱污染),执行决策归主 agent。
