# ADR-0003 机械检测归脚本哨兵,LLM 只做语义审查

- **Status**: accepted
- **Date**: 2026-08-23

## Context

建立外部审查循环时,容易把「周期性该查的东西」全部塞给定时子 agent(新工具显著性偏差:拿到定时编排工具,看什么都像钉子)。实例:用每 15 分钟一次的 LLM 子 agent 检查「日志同特征行 ≥10 次/10 分钟且无推进行 = 卡死」——判据是纯正则+计数。

## Considered Options

1. **LLM 周期子 agent 做机械检测**——延迟差(平均半个周期 vs 秒级)、每跳烧 token、每跳唤醒主 agent(NO_ACTIVE 类空转也是噪声)。
2. **脚本哨兵(事件推送)**:tail 日志/文件,命中判据即退出——harness 的 job 结束通知天然是推送通道;秒级、零成本、只在异常时打扰。
3. **不检测**——监控栈缺腿,卡死 30-50 分钟才发现的实证在案。

## Decision

选 2,判据:**「这事一个正则+计数+阈值能不能干?能就不进 LLM 审查。」** LLM 子 agent 只做需要语义理解的审查(纪律审计/归因对抗/报警后诊断)。

## Consequences

- 建立 checklist 第 1 步强制先分流机械/语义,防显著性偏差复发;
- 脚本哨兵自身也是代码会有 bug:水位文件修 0 值回落类潜伏 bug 要离线测试;哨兵单实例纪律(重武前查旧实例)沿用项目运维约定;
- 报警后的「为什么卡」诊断归主 agent(LLM),检测与判断分工——脚本报事件,LLM 做语义。
