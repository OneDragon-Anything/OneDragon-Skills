# 外部审查循环(定时审计 + 归因对抗)

> 读者 = 无会话历史的干净智能体。本 skill 建立「主 agent 自主推进、外部新鲜上下文定期审查」的看护循环:主 agent 的会话上下文在审查自己时是负债(自律随对话长度衰减,并行会话的债单会话自律管不到),新鲜上下文的子 agent 是结构化的他律。

## 必做 checklist(建立循环时按序做完;没做完这 7 步不算建成)

1. ☐ **分流机械与语义**:逐项过审查判据——纯机械(pattern/计数/阈值/存在性,输入是日志/文件/进程)→ 写脚本哨兵(检测即推送),**不进 LLM 审查**。**必做**
2. ☐ **定审查角色与证据面**:按 §角色 选角色;证据面 = 已提交工件(进度树/决策记录/版本历史/任务登记/临时采样目录),不依赖会话内状态。**必做**
3. ☐ **写自包含审查 prompt**:落项目工作区文件(路径/判据/输出格式写全,主 agent 到点引用它派发);prompt 内让子 agent 加载项目的进度类 skill 作纪律基准。**必做**
4. ☐ **登记定时提醒**:周期 30-60min;提醒内容 = 派发指令 + 行为校准,**不放状态查询**。**必做**
5. ☐ **建报告落盘与去重**:报告全文写工作区固定目录(清 24h 前旧档);对抗审查配去重水位文件。**必做**
6. ☐ **定消费与仲裁纪律**:按 §消费 分诊;报告间冲突先仲裁后采信。**必做**
7. ☐ **会话恢复对账**:定时提醒与任务登记易失,每个会话开始重建。**必做**

## 机制:定时提醒 + 主 agent 发起(不用「定时直启子 agent」类专属机制)

用 harness 标配能力组合——**定时消息提醒 + 主 agent 委派子 agent**——而非专属的「到点自动 spawn 子 agent」机制:

- **可移植**:提醒 + 委派是各 harness 通用能力,专属直启插件换环境就没了;
- **调度权在主 agent**:并发冲突时顺延、无新内容时跳过、worker 在飞时让位——直启机制没有这个阀门;
- **重大结论落地即刻发起对抗,不等定时**——对抗审查的价值随结论被采信的时间窗衰减,定时只是防遗忘的兜底;
- **提醒是活的**:派发指令随当期焦点换血,死的定时配置会过期误导判读。

## 角色(两个,按需启用)

| 角色 | 审什么 | 证据面 |
|---|---|---|
| **纪律审计** | 焦点一致性(声明焦点 vs 实际改动)/ 流程债(行为变更无决策记录)/ 豁免补偿(标记过「稍后补审」的欠账)/ 临时钩子积压(采样已达标但钩子还在)/ 逐补丁发散模式(连续多个不同根因的单点修) | 进度树 + 决策记录 INDEX + 版本历史 + 临时采样目录 |
| **归因对抗** | 最新判读/归因结论:证据链断点 / 同样兼容证据的替代解释 / 数据边界缺失 / 单局现象当跨局结论 | 进度树最新结论 + 其引用的遥测/日志/提交 |

- 纪律基准让子 agent 自己加载项目的进度追踪类 skill(OneDragon 系用 `od-dev-progress-tracking` + 项目专属进度 skill),**别在 prompt 里转述判据**——转述即第二源,会漂。
- 归因对抗是攻击型指令:礼貌性放行 = 失职;但每条攻击必须引具体证据,禁无根据质疑。

## 审查 prompt 要点(写给子 agent)

- **完全自包含**:证据文件路径、判据来源 skill 名、输出格式全部写死;子 agent 无会话历史;
- **结论必须带证据指针**(提交号/文件路径/内容摘录),禁无证据的叙述性判断;
- 报告全文落工作区文件供追溯,推回主会话只给**总判一行 + FAIL/洞察各一行**(低噪声,细节在文件里);
- 对抗类配**去重水位**(结论标识未变 → SKIP 一行,不重复烧);
- 审计发现与方案建议**分开呈现**,建议标注「外部第二意见,非约束性」——外部视角给方案是价值,执行决策归主 agent;
- 静默期预期要写明:进度树声明的阻塞/等待期不判 FAIL。

## 消费纪律(主 agent 侧)

- **PASS 秒过 / WARN 记账(进进度树)/ FAIL 当场定位**——子 agent 给证据不给方案,定位与修复归主 agent;
- **报告间冲突 → 先仲裁后采信**:抽一条证据指针实地核验(一次文件/版本库查验),不取「最新报告覆盖旧印象」——两个干净上下文的审计员对同一债得出相反结论是常态(方差来自各自搜的表面不同),仲裁 10 秒,误信成本一轮返工;
- **同债第三次重复出现 → 显式排期**(进度树记「已见,排期 X」)——恒报会脱敏,显式排期是防脱敏阀;
- 并发预算内**串行派发**(审计 → 对抗);worker 在飞时审查让位。

## 反模式(踩过的,别再踩)

- **LLM 干脚本的活**:机械判据的周期检测(卡死/静默/阈值越线)写脚本哨兵——事件推送秒级、零成本;LLM 周期查 = 贵 + 慢 + 每跳唤醒主 agent。判据:这事一个正则+计数能不能干?能就不进 LLM 审查。
- **无 backlog 的周期任务**:登记前确认有稳定的审查对象(如知识工程类审查只在有待处理语料时起,清了就撤);
- **独立性寄托在换模型上**:审查独立性主要来自**新鲜上下文**而非模型差异——默认继承主力路由即可(视觉任务才换);同模型新鲜上下文照样有效,但采信前的证据指针抽查不可省;
- **新工具显著性偏差**:拿到新的定时/编排工具时最想用它的时候,恰恰最该先问「这事脚本/既有机制能不能干」。

## 生命周期

- **试点闸门**:跑一天以上,抓到 ≥1 次「主 agent 自己没察觉的欠账」且误报不淹没信号 → 转常驻;否则收缩审查项或撤销;
- **会话开始**:重建定时提醒(易失),报告目录清旧档;
- **审查项随当期焦点增删**,提醒里的派发指令同步换血——过期指令误导判读;
- 主 agent 的自我校准提醒(产出密度三问:在找问题还是在等结果/轨迹还达标吗/哪条纪律正被违反)与本循环并存:自我校准管会话内行为层,外部审查管工件层,互补不冗余。
