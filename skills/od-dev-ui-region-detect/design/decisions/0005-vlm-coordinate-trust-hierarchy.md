# 0005. VLM 定位信任层级:默认信 VLM 坐标,别用未验证参照否定

- **Status**: accepted
- **Date**: 2026-08-10

## Context

验证「商店牌 SIFT 能否识别角色」时出现两类错:

1. **图快猜坐标**:定位肖像裁切区时,没让 VLM/CV 确定,而是从 screen_info 牌中心倒推出
   `x_center±95, y90-265` 直接用。
2. **拿未验证参照否定 VLM**:VLM 给了肖像坐标,却把 screen_info 的牌中心(377/646/…,实为
   **「文字带」的点击点 ≠ 肖像中心**)当 ground truth,判 VLM「系统性偏右 60-124px」,
   **没查 VLM 问法、没客观验证就否定 VLM**。

结论误判为「商店 SIFT 弱(6-14 内点)」。客观 SIFT 复核:VLM 坐标(肖像中心 501/754/…)才是对的,
内点 33-68 全中 —— **VLM 没错,是裁错位置 + 用错了参照系**。

根因:skill 已有「用 VLM 原生 grounding 别猜」「别用 VLM 当裁判(对齐判断)」,但**缺一条默认信任
姿态 + 怀疑时的升级路径** —— 没把「信 VLM 坐标」设为默认 → agent 习惯性①猜坐标(快)②用未验证的
旧参照(screen_info / 旧假设)否定 VLM。

## Decision Drivers

- **坐标是数据**:VLM grounding 是模型把视觉位置转成数值的训练能力(坐标 = 数据),与 VLM 的
  「空间关系推理」(对齐 / 居中判断 = 推理)是两类产出,可信度不同 —— 坐标可信,推理不可信。
- **失败是 agent 认知捷径**:猜坐标(图快)+ 确认偏置(倾向信已有状态)是通用 agent 失败模式,
  不是 VLM 能力问题(同模型坐标给得准)。
- **升级路径**:怀疑不该直接否,要先查问法 → 客观验证 → 无法验证才退回默认信。

## Considered Options

1. **各源等权 / 验证优先姿态(skill 此前隐含)**:没设默认信任 → agent 默认猜坐标 + 用未验证参照
   否 VLM(见 Context 的两类错)。
2. **默认信 VLM 坐标 + 怀疑升级路径(选中)**:坐标需求默认走 VLM grounding(别猜);怀疑先查问法;
   冲突做客观验证决定采纳谁;无法验证优先信 VLM;别拿未验证参照否 VLM。
3. **任何 VLM 坐标用前都必须客观验证**:太重、阻塞流程;只在「与已有坐标冲突」时才要求验证
   (见 Decision 第 4 条)。

## Decision

选 2。把「VLM 定位信任层级」写成 SKILL.md 靠前的硬规则(覆盖所有坐标定位),六条 + 一条
坐标-vs-判断的区分:

- 信 VLM **输出坐标**(grounding 数据);不信 VLM **空间判断**(对齐 / 居中 / 重叠 = 推理,精度差)。
- 后者正是 [ADR-0002](0002-numeric-verification-not-vision-judge.md)「别用 VLM 当裁判」
  + [ADR-0004](0004-vision-color-unreliable.md)「颜色不可信精确值」:本 ADR 补上**可信的那一维**
  (坐标),与二者拼成「VLM 各维度可信度」完整图景 —— 坐标可信、判断 / 颜色不可信。

## Consequences

- **正向**:堵住「猜坐标 + 用未验证参照否 VLM」的失败闭环;VLM 坐标当数据用,不再被习惯性推翻。
- **负向**:VLM 真错时(问法对、极少见)agent 会偏向它 —— 由第 4 条(冲突时客观验证)兜底;
  验证仍以数值对拍 ground truth 为准(不退回让 VLM 当裁判)。
- **边界**:本 ADR 只管「VLM 输出坐标」这一可信维度;VLM 判断(ADR-0002)/ 颜色(ADR-0004)
  仍不可信,规则不互相覆盖。
- **follow-up**:换 VLM 代际时(坐标格式随代际变),信任层级不变,只更新问法(查文档)。
