# 0006. VLM 归一化坐标系下,prompt 里不夹绝对像素信息

- **Status**: accepted
- **Date**: 2026-08-14

## Context

用 VLM grounding 定位时,习惯把图片宽高 / 分辨率 / 已知像素坐标写进 prompt(以为帮模型定位 /
方便它换算)。实测(2026-08,GLM-V 系归一化 0-1000):归一化与绝对像素是**两套坐标系**,同时给
→ 模型在两套间摇摆打架,输出坐标漂移、甚至计数错。

根因:skill 已有「用模型原生 grounding 格式」(管**输出**格式),但缺配套的**输入侧 prompt 坐标系
卫生**规则 —— agent 以为「多给信息(尺寸)更好」,反而注入冲突参照系。

## Decision Drivers

- **模型只在原生坐标系上被训练**:grounding 能力绑定单一坐标体系(如 0-1000 / 0-999);prompt 里
  出现另一体系 = 注入冲突参照,模型试图兼顾两者 → 摇摆。
- **像素还原是确定性计算**:`pixel = value / 归一化上界 × 宽/高`,调用方(智能体)自己算零误差,
  比让模型换算可靠(模型换算 = 让它跨体系推理,恰是弱项)。

## Considered Options

1. **prompt 里给尺寸,指望模型自己换算成像素**:两套坐标系打架,坐标漂移 / 计数错(实测,否)。
2. **归一化体系不给绝对像素信息,智能体拿到值后自己还原(选中)**:模型只在母语体系输出;
    还原是确定性算术。
3. **让模型同时输出归一化 + 像素双坐标**:扩大输出面(多一处可错),且模型内部仍要跨体系换算,
    本质同 1。

## Decision

选 2。SKILL.md「视觉大模型 路径」加硬规则:**模型用归一化坐标系时,prompt 里不出现绝对像素信息
(图片宽高 / 分辨率 / 已知像素坐标)**;像素还原由智能体自己做。绝对像素体系(如 Qwen2.5-VL)输出
即像素,同样无需给尺寸。

## Consequences

- **正向**:消掉一个系统性漂移源;还原路径确定、可复现(纯算术)。
- **负向**:智能体要自己知道图的宽高 —— 从图像元数据 / 读取时取,别反过来问模型。
- **边界**:本 ADR 管**输入侧**(prompt 里给什么);输出坐标的可信度与怀疑升级路径归
  [ADR-0005](0005-vlm-coordinate-trust-hierarchy.md),两者互补不覆盖。
- **follow-up**:换模型 / 代际时坐标格式可能变(先查官方文档),但「归一化体系别夹绝对像素」
  原则不变。
