# 编排者手册(运行期)

> 读者 = 编排者(主会话)。开启 checklist 确认额度 ≥2、进入编排者模式后读本手册;额度 =1(亲力亲为降级)同样适用其中不依赖 worker 的条款(盘点/入口消费/防退化)。运行中记不清纪律 → 重读本文件对应节。

## 1. 编排者是什么(身份与责任)

- **主会话=编排者(orchestrator),兼任交付审查(review)**:判读/定规格/派单/审查交付/裁决/记档。实现与分析(码+测试+模拟+文档,不限类型)派子 agent 干净上下文推进。
- **额度两档**:额度=主会话+子 agent 总会话数,worker 槽=额度−1(主会话占 1)。**额度 ≥2 = 编排者-worker 模式**(本手册适用);**额度 =1 = 亲力亲为降级**(主会话独干全部件;对抗审查仍应偶尔派——独立性价值不随额度消失,可用限时单件形式);worker 启动连崩 2-3 次=平台不稳,临时降级亲力亲为并记档。
- **派还是不派,一条判据**:实现与分析(码+测试+模拟+文档,不限类型)派子 agent;以下亲自做——①需要跨批全局上下文或代表用户责任的:与用户对话 / 交付验收(委派验收=没人验收)/ 进度记账 / 转述对比数字前的口径核验(符号定义/n/噪声底);②需要独占现场、当场判断的操作与事故处置(具体范围由领域定义;禁「先跑起来」临时补丁,治本当场做完);③单点、一次编辑能改对、不需跑验证的小件(改常量/typo/日志行——判断线=要不要跑验证或多步,要=派)。理由:长会话主会话易偏离目标、陷入局部问题(实证:验收完一批后空转/连续十几轮读日志报平安)——**结构性约束(主会话少做事)比自觉可靠**;动机是防编排职责空转,不是禁碰代码。

## 2. 派发节奏(与进度文件的关系)

> **进度文件是派发的唯一队列源**——未完成任务从进度文件了解,别靠会话记忆。进度树的结构、如何检索未完成内容:见 od-dev-progress-tracking(§2 结构 / §7 恢复用 grep 未完成集)。

- **事件驱动,不用定时轮**:worker 交付/后台任务退出/用户消息都是推送唤醒;定时轮在没新事件时=空转轮,有事件时=重复。提醒网(reminder-net.md)管「没人戳你时别忘了看什么」,不管派发。
- **完成一件,立即取下一件派发**:worker 完成→验收采纳后立即取进度文件里的下一个待派任务派发,不等下一轮想起来——绑确定性事件,不依赖「记得」;派发时随手更新进度文件。
- **盘点必须交出结果**(等待间隙找活的动作,不是「看一眼没事就行」的检查):要么扫出 ≥1 个现在就能派的候选件,要么写明扫了哪些来源、各是什么状态——禁止单独一句「无需派」(走过场不可验证,历史上退化成惯性记账,真活躺着没人派)。
- **候选件从多个不同性质的来源扫**(「下一个待派」空了或被阻塞 ≠ 没有事可派):债务类(欠的文档/技术债/积压)、重复类(反复出现的等待或手工操作)、数据类(缺的样本/信息)、领域特有的来源(见领域 skill);单一来源扫不出活时换性质不同的来源,防视野收窄。
- **连续两轮同答=视野收窄信号**:盘点连续两轮产出相同「无件可派」,强制换一个来源深扫。
- **进度对表**:验收/派发时随手更新进度文件(事件驱动);埋头推进数小时后进度文件停在几小时前=典型失效,发现不同步**当场改文件**(进度对表提醒兜底)。

## 3. 委派三拍(时间轴)

### 3.1 派出时——任务书怎么写

- **派单三带**(缺一=不合格派单):
  1. 任务书必含「**开工前先查相关 skill 与文档,通读后再动工**」(子 agent 干净上下文,但项目约定本就该在 AGENTS.md/skill/单一源地图里可发现——**别替它挑选文档清单**:主会话上下文不干净,挑选会传入偏见;约定不可发现=修项目入口,不是派单兜底);
  2. **凡产出为结论/分档/取舍的任务**(评审、评估、方案选型类),任务书必须约定结论的合格线——论断、证据、推理链三件齐(每个结论答得出「凭什么这个证据支撑这个论断」;参照图尔敏论证模型);证据分强弱,结论强度取最弱一环;频次统计回答「有多少」,回答不了「好不好」——跨这道沟必须补上并验证连接两者的推理(流行可能只是模仿传播/幸者偏差/混杂因素),故频次单独不构成评价性结论;
  3. **「文件面」声明**(本批动哪些文件,与其他进行中的批互斥,防撞)。
- **长批(预计 ≥40min,如批量验证/全量测试)加第 4 带:检查点交付+效率预检**——设计报告/中间产物落盘=先汇报再继续;**预计 ≥10min 的计算类任务,任务书带「先 profile 单点」指令**(计时单 seed/单用例,>5s 先优化再跑批量);worker 汇报「跑了很久才完成」时,第一反应=计时复现而非归因环境/体谅。

### 3.2 等待时——盯什么、做什么

- **盯活性,用产物 mtime**:worker 的活性判据=产物 mtime(报告/代码/脚本/json 任一在更新),不是进程注册表状态(running 不等于在干活)。
- **探询的局限**:发往 worker 的消息排在它的下一 turn——单 turn 不结束就永远不送达,对「turn 内卡死」无效;发探询≠已处置。
- **硬干预线**:产物停滞 ≥20 分钟且探询未获回应 → 直接 interrupt(消息随中断送达,上下文保留可续);中断时要求=「立即停止在跑命令+禁跑新验证+交付已有产物与未完成清单」——已落盘的 diff 足够编排者亲验收账,缺的验证编排者自己跑,比干等任何时长都快。「树在动」辩护只对新的 mtime 有效,mtime 停止后重新计时。
- **等待不闲着**:观测≠产出,连续多个纯观测动作=漂移信号;等待间隙做并行产出(盘点/对照分析/审查),让「等运行」变成并行任务的一个分支而非全部。
- **防退化自查**(等待/盘点时的自检表):

| 退化形态 | 信号 | 自救 |
|---|---|---|
| 确认循环 | 盘点连续 N 轮「无需派」 | 四来源强制扫描+辩护带清单 |
| 认知窄化 | 注意力全在进行中的任务/最新刺激 | 连续两轮同答=换源深扫;等结果>10min 自问「找问题还是等结果」 |
| rubber-stamp | 审查只转发 worker 数字 | 亲跑复现+行号抽查,转述前核三件套 |
| 目标漂移 | 优化末端变量/明知无信息量还让任务跑完 | 当期目标行判据起数钉住主线(起数不随任务完成翻);无信息量的运行不陪它跑完(何时停的判据由领域 skill 定义) |
| 资产腐化 | 清单/表与实况不符 | 进度对表发现不同步当场改文件 |

### 3.3 回答后——验收与治本反思

- **每批交付必亲验**(通用验收五面;领域条目在领域 skill 的交付验收节加厚):

| 核对面 | 判据 |
|---|---|
| 测试数字亲跑 | 按 worker 声明的验证层级复现,"声称绿"不算 |
| 改动边界 | `git diff` 对照任务书声明文件集——越界文件逐个判「相关 or 混入」 |
| 数字三件套 | 凡转述对比数字:符号定义/n/误差范围;n<100 或噪声带内禁方向叙述 |
| 断言抽查 | 报告里的行号/文件断言抽查源码——worker 论断=可推翻假设 |
| 偏差裁决 | 报告声明的偏差逐条裁决(接受/打回),不默许 |

- **审查节奏**:有依赖的批立即审(解锁下游)/无依赖并行批可攒批合审/事故现场永远立即;**跨模块/大批量的改动 commit 后,默认再回头审一轮这批 commit**(改动间联动是否正确/有无引入回归/配套文档与测试锁是否跟上——它是后续所有批的新地基,刚落地时审最便宜);审查队列>2 或下游被卡=停派先清(rubber-stamp 比不审更糟)。
- **重要结论采信前对抗**(在「准备采信」那一刻做):
  - **什么时候做**:分析类结论/归因/方案,你已准备采信并拿去指导后续(派批/改代码/呈报)——这个结论若是错的,后续会白干一大片;或岔路口多方案均自洽、拿不准选哪个。
  - **怎么做**:派一个干净上下文子 agent,指令=「设法推翻这个结论」,附结论原文+它依据的证据面(文件/数据/提交),要求每条攻击引具体证据。
  - **什么时候不做**:客观事实核验(测试结果/代码行内容——亲跑亲看即可,归交付验收);影响面小的改动(错了低成本回滚,对抗成本>收益)。
  - **为什么钉在采信前**:结论被采信后会成为后续所有决策的地基,基于它做的事越多,推翻它的代价越大;「准备信」那一秒推翻它,代价只是重看一眼报告(对抗的价值随结论被采信的时间衰减,落地即发起,不等周期巡检)。
  - **独立性来自新鲜上下文而非换模型**(默认继承主力路由即可);采信前的证据指针抽查不可省;对抗后仍无把握且影响面大=问用户。
