# 提醒网方法论(定时任务角色集)

> 读者 = 编排者(主会话)。建网动作发生在开启时刻(用本文件的角色表+提示词模板);各角色行的详细内容在运行期由提醒词指针消费。运行中记不清角色职责 → 重读本文件。

## 角色集(四角色)

间隔彼此错开且量级不同(防齐发=信息稀释);**提醒放角色不放当期细节**(防过期误导),**不放状态查询**(状态走事件通道):

| 角色 | 间隔级 | 类型 | 盯什么→怎么查→答什么 |
|---|---|---|---|
| 值守兜底 | ~10min | **自执行** | 盯后台任务与运行环境是否健康。查:①长跑的程序(构建/测试/批量任务/对接真实环境的运行)还在推进吗——看它的输出文件更新时间,不是看进程在不在(进程活着≠在干活);②派出去的子任务(Worker)最近 20 分钟有产出文件更新吗——没有就发消息问;问了还没回应就中断它,要求「交出已完成的部分+列出没做完的」。答:每轮必执行,给出「健康/已干预」结论 |
| 派发盘点 | ~15min | **自执行** | 盯**「还有没有其他该做的事」**+**审查积压**(产能的专职提醒)。查:①待审的交付积压几件——**>2 件就停止派新单先清审查**(盖章式审查比不审更糟);②盘点找活——按 orchestration.md「派发节奏」节执行(必须交出结果:扫出可派件或扫描痕迹;从多个不同性质的来源扫)。答:≥1 个**现在就能派**的候选件(不依赖任何进行中的任务)派出去;「暂缓一拍」不是盘点结果,槽由可派件填充,不等被阻塞件;实在没有,写下「扫了哪些来源,各是什么状态」——禁止只回一句「无需派」 |
| 回顾 | ~20min | **自执行** | 盯自己的注意力与工作方式(对「还有没有事」的二次兜底,与 15min 盘点形成双保险)。查四问:①刚才 10 分钟是在「找问题」还是「干等结果」(只有看状态没有产出=干等);②最近的工作和哪些 skill 相关,有遵循按 skill 规范吗?重点扫「当时根本没想到有 skill 管」的操作(纪律失效最常见形态不是知道规范没遵守,而是没意识到这动作有规范)——没对照权威文档的判断、没遵循 skill 的操作,当场补;③闲置的任务槽——**答案是一次发散搜索,不是一个理由**:先横向枚举「现在还有哪些不依赖进行中任务的事可做」,搜出就派;「某任务在等 X」「暂缓一拍等下一事件」永远不是空槽的终止答案(任务会等,槽不等);终止态只有两种:已派,或零候选+扫描痕迹;④连续两轮回答相同=思维窄化信号,强制换一个来源深扫。答:逐问回答,第③问答枚举结果而非辩解 |
| 子 agent 审计 | ~45min | **派 agent** | 盯需要**独立视角**的工作(提醒只做触发器,触达后派干净上下文的子任务,主会话只收裁决——自己审自己会带偏见)。查:①skill 反馈队列里待裁决的条目(第三方判「真通用还是特例」);②可晋升进公共 skill 的候选做法;③自己最近拍板但没被攻过的结论/方案(给攻击型指令:设法推翻它);④采信未攻的存量结论清单。答:裁决清单;轮空也要写「扫了什么」 |

## 提示词模板(建定时任务时直接用)

- **值守兜底**(间隔 10min):
  > 【值守兜底】看一眼后台:①长跑的程序还在推进吗(看输出文件更新时间,不是看进程在不在)?②派出去的子任务最近 20 分钟有产出更新吗——没有就问,问了没回应就中断它要已完成部分。
- **派发盘点**(间隔 15min):
  > 【派发盘点】看一眼进度文件的待办,把活派满:①有待办、worker 槽空着 → 马上派;②待审交付积压 >2 件 → 停止派新单先清审查;③队列空了别闲着,从多个不同性质的来源发散扫(欠的债/重复的手工操作/缺的数据);④实在没有 → 记一行「扫了哪些来源,各是什么状态」,禁止只写「无需派」。
- **回顾**(间隔 20min):
  > 【回顾】问自己四个问题:①最近 10 分钟是在「找问题」还是「干等结果」?②最近的工作和哪些 skill 相关,有遵循规范吗?有没有没对照权威文档就下的判断?③闲置的任务槽——横向枚举现在还能做什么,搜出就派;④连续两轮答案相同=该换个来源深扫了。
- **子 agent 审计**(间隔 45min):
  > 【子agent审计】派一个子 agent(干净上下文)做审计,对象从当前积压里挑:①skill 反馈队列待裁决条目;②可晋升进公共 skill 的候选;③最近拍板但没被攻过的结论(攻击型指令:设法推翻它)。结论回来后逐条裁决。

(领域有特有监控对象时——如对接真实环境的运行监控——在本表四角色之外按需增补,间隔与本表错开。)

## 提醒词的写法(用户可见的持久化文本)

提醒列表的原文会直接显示在用户界面上,用户随时可能读到——提醒词不是 agent 内部速记。写每条提醒词时按一句话判据自检:**「用户冷不丁看到这条提醒,能读懂它在提醒什么吗?」**答不上=重写:要点用大白话;自造的流程速记词(对工作环节的压缩说法)要么换成直白说法,要么当条带一句定义。**细节不进提醒词**:具体查什么/怎么答留在本文件各角色行,提醒词只承担「触发 + 一句大白话要点 + 指向角色行的指针」——细节进提醒词会过期(上方条款管的),速记进提醒词会看不懂(本条管的),两条互补。

## 自执行 vs 派 agent 的判据

触达后**几分钟内可出动作且判据可内化**的(查状态/扫表/自问/触发预定义响应链)→ 自执行;**需要干净上下文或长时间专注**的(独立审查/偏见敏感的裁决/批量材料处理)→ 提醒触达后**派 agent 执行**,编排者只收裁决——提醒本身只做触发器,不承载这类工作(带着主会话上下文做=偏见污染)。

## 「还有没有其他该做的事」的双保险设计

15min 派发盘点是专职提醒(必须产出候选件或扫描痕迹);20min 回顾第③问二次兜底(检验「没有事」这个结论本身)。两者有意冗余——盘点防「没扫到」,回顾防「扫了但用同一双眼睛看到同样的东西」(连续两轮同答=视野收窄信号)。

## 长任务自校准(防重心漂移)

回顾问「监控动作的产出密度」——观测≠产出,连续多个纯观测动作=漂移信号;等待间隙做并行产出(对照分析/审查/判读),让「等运行」变成并行任务的一个分支而非全部。
