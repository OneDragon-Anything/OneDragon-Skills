# 提醒网方法论(定时任务角色集)

> 读者 = 编排者(主会话)。建网动作发生在开启时刻(用本文件的角色表+提示词模板);各角色行的详细内容在运行期由提醒词指针消费。运行中记不清角色职责 → 重读本文件。**提示词模板的措辞基准**:模板里的「你」一律指编排者;需要子 agent 做的内容以「开工令/写进任务书」显式标注转写,任务书内才以「子 agent」称呼——提示词里禁出现指代子 agent 的「你」。

## 角色集

间隔彼此错开且量级不同(防齐发=信息稀释);**提醒放角色不放当期细节**(防过期误导),**不放状态查询**(状态走事件通道)。检查项与答案格式的**唯一全文源=下方提示词模板**(本表只留设计定位,不复制检查细则):

| 角色 | 间隔级 | 类型 | 盯什么 |
|---|---|---|---|
| 值守兜底 | ~10min | 自执行 | 后台任务与运行环境健康(长跑程序/子 agent 真在产出吗,零产出本身=报警) |
| 派发盘点 | ~15min | 自执行 | 还有没有该做的事+验收积压(产能的专职提醒) |
| 回顾 | ~20min | 自执行 | 自己的注意力与工作前提(对盘点结论的二次审计)+ 进度文件防退化(第 6 问) |
| 代码审计 | ~45min | 派 agent | 对抗式攻击周期内改动的代码缺点(自己审自己会护短,需独立视角) |
| 文档审计 | ~60min | 派 agent | 文档与开发同步性 + 文档规范符合度(同样需要独立视角) |

## 提示词模板(建定时任务时直接用)

> **模板是唯一合法形态:建/重建定时任务必须逐字复制对应角色的完整代码块**,禁止改写、精简、合并、调整顺序或「保留大意重述」——清单里每一项都是真实踩坑换来的检查判据,删任何一项=重新打开那个坑(实证:重建提醒时按大意转写,砍掉了防盘点凭记忆作答的强制项,该坑立刻复发)。觉得某项不适用 → 不许当场砍,走 skill 反馈队列提交后由维护方裁决。

- **值守兜底**(间隔 10min;逐字复制下方代码块):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【值守兜底】当前任务:请按下述步骤严格执行。

1. 长跑的程序(构建/测试/批量任务/对接真实环境的运行)还在推进吗——**看输出文件的更新时间,不是看进程在不在**。进程活着 ≠ 在干活;输出文件很久没更新 = 停滞,记下停滞时间
2. 派出去的子 agent——**先查子 agent 状态清单**(每个子 agent 当前「运行中」还是「空闲」;顺带核对名单,多出/少了当场对上),按状态处置:
   - **运行中**:状态 ≠ 产出(回合卡死也显示运行中)——看它的产物文件(报告/代码/脚本)更新时间;**停滞 ≥20 分钟 → 直接中断**(中断时要求:立即停在跑命令、交出已完成部分+未完成清单;上下文保留可续)。**别先发消息问**:消息要等它当前回合结束才送达,那轮等待纯属白烧;已落盘的部分够验收,缺的验证自己跑比干等快
   - **空闲**:它现在没在干活——任务没完却空闲 = 提前停了或收尾通知被漏了;**发消息**让它继续或交代现状(空闲的收消息立刻开新一轮,没有送达延迟);干完了的就去收账
3. 什么都没在产出(没有运行在跑、没有子 agent 在动)**不是平安无事——零产出本身就是报警**:该派活派活、该起跑起跑,或者写明为什么两者现在都不该做

每步结论必须带本轮工具输出的证据(文件 mtime 时间/子 agent 状态原文/进程行),拿不出当轮输出=没查过,不算数。结论只有两种:「健康」(一行,说清各自在干什么)或「已干预」(动了什么)。一切正常时一行结论,不写别的。(细则源=od-dev-agent-autonomous-mode skill references/orchestration.md「等待时」节)
```

- **派发盘点**(间隔 15min;逐字复制上方总则约束下的完整代码块):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【派发盘点】当前任务:请按下述步骤严格执行。

1. **检测空位**:看当前 agent 额度上限和正在运行的子 agent 数(子 agent 状态清单)——还有空槽 → 继续第 2 步找活派;额度已满 → 直接跳到第 4 步记录,本轮不派
2. **找待办**:记忆中的内容一律不作数,本轮必须重新执行并留下证据:
   ① 按 AGENTS.local.md「进度入口」记录的路径定位迭代目录;
   ② 执行状态词 grep:`grep -rnE "未做|进行中|锁定|部分过|待激活" --include=进度.md <迭代目录>/`;
   ③ 从 grep 结果中摘录与本轮盘点相关的行原文(至少一行)作当轮证据;
   ④ 有可派待办 → 马上派;没有 → 该证据行照样留档,进入第 3 步发散来源
3. 进度文件外重新找活:继续从下面的来源里找**现在就能派、不依赖任何进行中任务**的活。**每个来源都要本轮真的打开文件/执行搜索来看,以本轮读到的内容作答**——上一轮的结论、记忆里的状态一律不作数,代码和文档随时在变,「跟之前一样」不是看过的证据:
   - 欠的债:代码 TODO/到期没还的临时补丁、没跟上代码的文档、复杂逻辑缺「为什么」注释
   - 算法效率:上一个操作结束到下一个决策执行完成的延迟,是否慢到使用者看到自动化卡顿
   - 测试等待:开发过程是否每次都花大量时间等测试跑完
   - 重复手工:每次都手敲的命令序列、固定的多步操作
   - 该测试锁住但没锁的行为;复制粘贴的重复逻辑(该抽公共)
   - 攒够没消化的样本、该清理的临时文件
   - 踩了没记档的坑
4. 都没有(或额度满) → 记录本轮的实际动作:第 2 步的 grep 摘录原文 + 每个来源搜了什么路径 + 命中了什么或确认为空;拿不出某个对象本轮的证据摘录 = 它就没被查过,结论不算数
5. 结论为零候选(非额度满)且当前有空槽 → 派一个**干净上下文的找活子 agent**快速找有什么能做。任务书三件:①当前自主推进的目标与进度入口路径(运行时从 AGENTS.local.md「目标」「进度入口」字段抄全文,别凭记忆转述);②找活方法引用 od-dev-agent-autonomous-mode skill references/reminder-net.md「派发盘点」模板第 2、3 步,让它照着来源与方法找——指针写全文件与节名,别只写步骤号(子 agent 看不到这条提醒);③产出=候选清单,每条带出处与理由,只找不派。候选回来由编排者逐条裁决

禁止只写「无需派」;禁止复述上一轮扫描的记忆下结论;「暂缓一拍」「等某任务结束」不算盘点结果,槽不等被阻塞件。一切正常时一行结论,不写别的。(细则源=od-dev-agent-autonomous-mode skill references/orchestration.md「派发节奏」节)
```

- **回顾**(间隔 20min;逐字复制上方总则约束下的完整代码块):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【回顾】当前任务:请按下述步骤逐问回答:

1. 最近 10 分钟是在「找问题」还是「干等结果」?只有看状态、没有产出 = 干等
2. **如果长时间都在「等/守/暂缓」:等的东西本身还对吗?**——守夜、等用户、等批次收尾,这些前提本身可能是错的;连续多轮维持同一个等待状态 = 必须挑战这个前提,而不是再确认它一遍
3. 最近的工作和哪些 skill 相关,有遵循规范吗?重点扫「当时根本没想到有 skill 管」的操作(纪律失效最常见形态不是知道没遵守,而是没意识到有规范)
4. 复核上轮盘点的结论:「没有可派的」是你自己几分钟前的判断,不是事实——**去一个和上轮不同的地方再找一遍**(上轮翻了进度文件,这次就去翻:代码里的 TODO 和临时补丁、没消化的报告文档、挂账清单),同样要当轮真打开看才算找过;翻出活 = 上轮错了,当场纠正;仍没有 = 零候选成立,记一行这次找过哪些地方
5. 连续两轮答案相同 = 视野窄化信号,强制换一个地方深扫
6. **进度账本体检**:跑 `progress.py check <迭代目录>`(脚本=od-dev-progress-tracking skill scripts/ 下)拿机械体检结果(行文法/状态-字段一致性/叙事特征词/超长报警);人工只判读 check 抓不到的两项——①新型叙事形态(特征词之外的流水账苗头)②待激活行的条件真实性。发现退化 → 读 od-dev-progress-tracking skill 对照规范清理(判定标准以 skill 为准,不凭印象)
7. **代码与注释规范抽查**(有近期代码改动时;没有 → 一行跳过):打开项目 AGENTS.md 的代码规范/注释规范相关节,抽取最近 1-2 个改动文件的 diff 对照检查——典型违点:类型注解缺失/注释复述代码没写为什么/注释里留会话局部标识符/关键字段缺定义注释(以项目 AGENTS.md 实际条款为准,不凭记忆);发现违规 → 当场修或记进度账本,别攒

一切正常时逐问一行,不写别的。(细则源=od-dev-agent-autonomous-mode skill references/reminder-net.md)
```

- **代码审计**(间隔 45min;逐字复制上方总则约束下的完整代码块):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【代码审计】当前任务:请按下述步骤严格执行。

1. 当轮真看 git status / git diff / 最近 commit,确定本审计周期内改动的代码(多批并行时挑改动量最大、或最近一次没被攻过的那批)——拿本轮命令输出作证据,不凭记忆
2. 派一个干净上下文的子 agent 做对抗式代码审计(自己审自己的代码会护短,必须独立视角)。开工令必含:
   - 任务=**无情攻击这份代码的缺点**:立场=假设代码有错、设法证明它;不是找优点、不是复述改动做了什么;攻不破的角度才允许写「攻过未破」
   - 攻击面至少覆盖:逻辑错误/边界条件与异常路径/运行时崩溃/死循环/资源泄漏/重复逻辑该抽未抽;叠加该项目 AGENTS.md 的代码与注释硬约束(编排者把路径写进任务书,子 agent 自己读)
   - 输入=本轮抄录的改动文件清单与 diff 范围(别让子 agent 自己猜改了什么)
   - 产出=问题清单,每条带文件/位置/发作场景/严重级,按严重级排序;「无问题」结论必须附攻过哪些角度
3. 结论回来逐条裁决:成立 → 记进度账本并派修(单点小件可亲手);不成立 → 记一行为什么不成立,别为安静而改
4. 本周期无代码改动 → 写一行「扫过 git status/diff,无新改动可审」,不硬凑审计

(细则源=od-dev-agent-autonomous-mode skill references/orchestration.md「采信前对抗」)
```

- **文档审计**(间隔 60min;逐字复制上方总则约束下的完整代码块):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【文档审计】当前任务:请按下述步骤严格执行。

1. 当轮真看 git diff / 最近 commit,列出本审计周期内代码改动涉及的文档面(改动模块 → 对应文档在哪;docs 结构与规范入口由该项目 AGENTS.md 定义)——拿本轮命令输出作证据,不凭记忆
2. 派一个干净上下文的子 agent 做文档审计(写文档的人审自己的文档会护短)。开工令必含两个检查面:
   - **同步性**:文档说的和代码现在做的一致吗——接口/行为/字段/流程改了,文档跟上了没;文档描述的落点在代码里还存在吗
   - **规范性**:文档本身符合该项目的文档规范吗——编排者把项目 AGENTS.md 与文档规范路径写进任务书,子 agent 逐条对照(典型违点:正文混入进度标记/变更叙述/规划状态位;术语首现无定义;该进决策记录的内容散在正文)
   - 输入=文档路径清单+对应代码落点(编排者本轮抄录)+规范入口
   - 产出=问题清单,每条带文档路径/节/问题类型(失同步 or 违规范)/修改建议
3. 结论回来逐条裁决:该修的记进度账本并派修;刻意保留的记一行理由,不默许也不硬改
4. 本周期无代码改动、文档也无失同步嫌疑 → 写一行扫描范围与结论,不硬凑审计

(细则源=od-dev-agent-autonomous-mode skill references/orchestration.md「采信前对抗」)
```

## 提醒词的写法(用户可见的持久化文本)

提醒列表的原文会直接显示在用户界面上,用户随时可能读到——提醒词不是 agent 内部速记。写每条提醒词时按一句话判据自检:**「用户冷不丁看到这条提醒,能读懂它在提醒什么吗?」**答不上=重写:要点用大白话;自造的流程速记词(对工作环节的压缩说法)要么换成直白说法,要么当条带一句定义。

消息内容两条边界(方向相反,互补):

- **角色义务必须进消息**(查什么/怎么判/答什么格式/漏洞封条):提醒被当成「需应答的消息」而非「需执行的指令」、以及凭标题缓存应答,都发生在义务不在消息里时——消息自包含,每轮到达都自带完整检查清单,不依赖会话记忆或回读文件。前缀统一为「⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。」——把消费方式钉进消息本体,抗上下文压缩。
- **当期细节不进消息**(额度数/在跑什么/当期焦点):会过期,过期后误导。这类信息到进度文件/事件通道拿。

消息与角色集表的分工:**模板=唯一全文源**(检查项/判据/封条/答案格式都在这,建定时任务逐字复制、禁精简改写,运行中记不清职责重读这里);角色表=设计速览(角色构成/间隔/类型/一句话定位,不复制检查细则——改职责只改模板,无第二同步面)。

## 自执行 vs 派 agent 的判据

触达后**几分钟内可出动作且判据可内化**的(查状态/扫表/自问/触发预定义响应链)→ 自执行;**需要干净上下文或长时间专注**的(独立审查/偏见敏感的裁决/批量材料处理)→ 提醒触达后**派 agent 执行**,编排者只收裁决——提醒本身只做触发器,不承载这类工作(带着主会话上下文做=偏见污染)。

## 「还有没有其他该做的事」的三重保险设计

15min 派发盘点是专职提醒(必须产出候选件或扫描痕迹);20min 回顾的第 4 问二次兜底——**不是重做盘点,是审计它的结论**:盘点的「没有可派的」只是几分钟前自己的判断,去一个不同的地方再找一遍验证它;盘点结论为零候选时再升级一道——按盘点第 5 步派干净上下文的找活子 agent 重扫。前两道都是编排者自己的同一双眼睛(换的只是搜索地点),第三道换的是上下文——无会话记忆,从目标与进度账本重建视野。三层有意冗余且分工不同——盘点**产出**结论,回顾**审计**结论,找活子 agent 用**独立上下文**复核结论;防的是「扫了但用同一双眼睛看到同样的东西」(连续两轮同答=视野收窄信号)。

## 长任务自校准(防重心漂移)

回顾问「监控动作的产出密度」——观测≠产出,连续多个纯观测动作=漂移信号;等待间隙做并行产出(对照分析/审查/判读),让「等运行」变成并行任务的一个分支而非全部。
