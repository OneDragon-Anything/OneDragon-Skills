# 提醒网方法论(定时任务角色集)

> 读者 = 编排者(主会话)。建网动作发生在开启时刻(用本文件的角色表+提示词模板);各角色行的详细内容在运行期由提醒词指针消费。运行中记不清角色职责 → 重读本文件。**措辞基准**:提醒词里的「你」一律指编排者,需要子 agent 做的内容以「开工令/写进任务书」显式标注转写,任务书内才以「子 agent」称呼——提醒词里禁出现指代子 agent 的「你」。

## 角色集

间隔彼此错开(防齐发=信息稀释);**提醒放角色不放当期细节**(防过期误导),**不放状态查询**(状态走事件通道)。检查项与答案格式的**唯一全文源=下方提示词模板**(本表只留设计定位,不复制检查细则——改职责只改模板,无第二同步面):

| 角色 | 间隔级 | 盯什么 |
|---|---|---|
| 值守兜底 | ~40min | 后台任务与运行环境健康(长跑程序/子 agent 真在产出吗,零产出本身=报警) |
| 派发兜底 | ~30min | 派发防漏+综合判断该做什么——形态 A 编排者自执行/形态 B 直启子 agent(互替,只建其一):①漏派(ready×空槽→首行派;[打回]=返工) ②验收积压(pending_review 无结论) ③打回积压(rejected) ④综合判断(目标×账本×仓库现状→候选,成立者 add 立项) |
| 最近改动三审 | ~60min | 已提交改动的代码/文档/测试三面最严格攻击(事后兜底;形态 A 派 agent/形态 B 直启,只建其一;测试面含最大程度减少测试) |

(领域有特有监控对象时——如对接真实环境的运行监控——在本表角色之外按需增补,间隔与本表错开。)

## 触发形态与选择规则(定时任务怎么建)

- **形态 A · 定时提醒编排者**:到点把提醒词送进编排者会话,由编排者自己执行检查——模板=下方「提示词模板」。
- **形态 B · 定时直启子 agent**(环境支持「到点自动 spawn 全新上下文子 agent、结果自动回会话」的机制时可用):到点由机制直接派无记忆子 agent 执行自包含任务书,结果自动回到会话由编排者消费。

**选择规则:同一角色两形态互替不叠加,只建其一;两形态职责等价。** 派发兜底:形态 A=编排者自执行全查;形态 B=直启无记忆子 agent 产出处置单(综合判断不受编排者上下文偏见污染),派单执行仍归编排者。最近改动三审同为两形态:形态 A=编排者收提醒后派干净上下文攻击者,形态 B=到点直启自动审(免编排者中转)。形态 B 任务书纪律与提示词模板同款:逐字复制只填实例位、产出回会话、任务标签用户可见过「提醒词的写法」自检;领域增补角色任务书格式由领域 skill 定义。

**登记约束——不设触发次数上限**:建周期任务时不要设触发次数封顶(环境的 maxFires 类参数留缺省/不限)——定时任务的寿命由模式收口管理(停止 checklist 撤提醒网),不靠次数自我了断;多触发只是多一份被消费的报告,不存在无人消费的失控输出。次数封顶反而引入新失效面:网到限悄悄停摆,没人知道少看了什么。

## 提示词模板(建形态 A 任务时逐字复制对应角色完整代码块)

> **模板是唯一合法形态:禁止改写、精简、合并、调整顺序或「保留大意重述」**——清单里每一项都是真实踩坑换来的检查判据,删任何一项=重新打开那个坑。觉得某项不适用 → 不许当场砍,走 skill 反馈队列提交后由维护方裁决。

- **值守兜底**(间隔 40min;逐字复制下方代码块):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【值守兜底】当前任务:请按下述步骤严格执行。

1. 长跑的程序(构建/测试/批量任务/对接真实环境的运行)还在推进吗——**看输出文件的更新时间,不是看进程在不在**。进程活着 ≠ 在干活;输出文件很久没更新 = 停滞,记下停滞时间
2. 派出去的子 agent——**先查子 agent 状态清单**(每个子 agent 当前「运行中」还是「空闲」;顺带核对名单,多出/少了当场对上),按状态处置:
   - **运行中**:状态 ≠ 产出(回合卡死也显示运行中)——看它的产物文件(报告/代码/脚本)更新时间;**停滞 ≥20 分钟 → 直接中断**(中断时要求:立即停在跑命令、交出已完成部分+未完成清单;上下文保留可续)。**别先发消息问**:消息要等它当前回合结束才送达,那轮等待纯属白烧;已落盘的部分够对账与再派,缺的验证由再派批补跑
   - **空闲**:它现在没在干活——任务没完却空闲 = 提前停了或收尾通知被漏了;**发消息**让它继续或交代现状(空闲的收消息立刻开新一轮,没有送达延迟);干完了的就去收账
3. 什么都没在产出(没有运行在跑、没有子 agent 在动)**不是平安无事——零产出本身就是报警**:该派活派活(照账本 ready 首行)、该起跑起跑,或者写明为什么两者现在都不该做

每步结论必须带本轮工具输出的证据(文件 mtime 时间/子 agent 状态原文/进程行),拿不出当轮输出=没查过,不算数。结论只有两种:「健康」(一行,说清各自在干什么)或「已干预」(动了什么)。一切正常时一行结论,不写别的。(细则源=od-dev-agent-autonomous-mode skill references/orchestration.md「等待时」节)
```

- **派发兜底**(间隔 30min;逐字复制下方代码块):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【派发兜底】当前任务:请按下述步骤严格执行。

1. **跑账本**:执行 `dag.py --file <迭代目录>/dag.jsonl list` 与 `ready`(路径按自主推进指令文件「进度入口」字段;两个输出各摘录一行作当轮证据,拿不出输出=没查过)
2. **漏派检查**:ready 有货且有空槽(额度上限 − 运行中子 agent 数 > 0)→ 照 ready 首行派(套 od-dev-agent-autonomous-mode skill references/orchestration.md「派出时」的任务书模板;带 [打回] 标的=rejected 返工泊位,先 `rejected→doing --assignee <返工者>`——原 worker 活着 send_message 续派,没了 spawn 新工);ready 空或槽满 → 本步一行「无漏派」
3. **验收积压**:list 里的 pending_review 行——对应 reviews/ 结论文件已存在的,按结论行处置(accept 已 done 则无事;reject 已 rejected 则并入第 4 步);结论文件不存在 = reviewer 漏派,补派(验收批任务书模板)
4. **打回积压**:rejected 行积压且有空槽 → 排返工派工(处置同第 2 步 [打回] 项)
5. **综合判断该做什么**(前四步都无漏之后做):「目标」字段的判据对照账本任务——要达成目标还缺哪些任务?账本外有没有该做的(欠的债:TODO/到期临时补丁/没跟上代码的文档;效率卡顿;重复手工;该测试锁住没锁的行为;临时件)?有 → `dag.py add` 立项(写优先级与依赖,进 ready 队列同规则竞争);没有 → 并入「无漏派」

本提醒多数轮次的结论就是「无漏派」一行——这不是空转:事件推送会丢、会话压缩会掉事,定时核对是防漏的最后保险。一切正常时一行结论,不写别的。(细则源=od-dev-agent-autonomous-mode skill references/orchestration.md「派发节奏」「回答后」节)
```

- **最近改动三审**(间隔 60min;逐字复制下方代码块):

```markdown
⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。

【最近改动三审】当前任务:请按下述步骤严格执行。

1. **定审集**:当轮真看 `git log`/`git diff`,取**最近 60 分钟内**的已提交改动(与提醒间隔一致)。审集为空 → 写一行「最近 60 分钟无提交,三审空」,不硬凑
2. **派一个干净上下文子 agent** 做三面最严格攻击(立场=假设有错、设法证明;开工令输入=审集[提交清单+diff 范围]+对应规范入口路径,禁实现者自述):
   ▶ **代码面**——目标:治本、不屎山。攻:逻辑错误/边界条件/运行时崩溃/死循环/资源泄漏/该抽未抽的重复逻辑/叠床架屋的补丁/魔数/绕过既有抽象;对照 AGENTS.md 代码与注释硬约束;每条发现定性「治本 or 症状+排期」
   ▶ **文档面**——目标:与代码同步、符合文档规范、核心理念不偏离。攻:文档说的与代码做的不一致;文档规范违点(直白表述/进度标记与状态位不入正文/术语首现无定义);偏离对应内容核心理念之处(对照领域权威文档)
   ▶ **测试面**——最严格找出可以删减的测试,保证套件不只增不减。判据:测试纪律文档逐条对照;**之外还要发散思考**——规范没写到的膨胀形态、套件结构级的精简机会;产出「可删/可并清单」+预估节省时长
3. **裁决与闭环**:发现逐条裁决——成立 → `dag.py add` 立项并派修(测试面可删清单批准后执行,删前跑全量证覆盖不降);不成立 → 记一行为什么不成立,别为安静而改

每步结论必须带当轮命令输出作证据,拿不出当轮输出=没查过。
```

## 直启型任务书模板(形态 B · 定时直启子 agent)

> 任务书是唯一合法形态:建形态 B 定时任务必须逐字复制对应角色的完整代码块、只填 `<角括号>` 实例位,禁精简改写——同「提示词模板」节纪律。任务书里的「你」指被直启的子 agent(干净上下文,看不到会话历史)。

- **派发兜底(直启)**(=派发兜底的形态 B;间隔 30min;任务标签示例「自主推进·派发兜底(自动子agent)」;逐字复制下方代码块,只填 `<角括号>`):

```markdown
你是自主推进模式的「派发兜底」子 agent。本任务书是你的完整指令;最终输出直接送达编排者,严格按【产出格式】写,不写寒暄、不复述任务书。

【职责边界】你只做两件事:①**机械核对**账本派发状态(漏派/验收积压/打回积压),产出处置单;②**综合判断**「当前应该做什么」,产出候选清单。你不派活、不改任何文件(本任务只读)——派单执行与立项裁决权在编排者。

【输入定位】迭代目录 = <创建时填:迭代目录绝对路径>。若该目录不存在,读项目根的自主推进指令文件(AGENTS.local.md;无则 AGENTS.md)「自主推进模式」节的「进度入口」字段,以其当前迭代目录为准,并在产出第一行注明你实际使用的目录。

【开工令】动工前先完成两件阅读,再开始核对与判断:
1. 加载 od-dev-progress-tracking skill,读账本结构、状态词、未完成集检索规范(以 skill 正文实际章节名为准,别凭本任务书猜);
2. 跑 `dag.py --file <迭代目录>/dag.jsonl list` 与 `ready`(输出为判读底稿),并读项目根自主推进指令文件的「目标」字段——你的综合判断以目标为锚。

【机械核对】(处置单素材;每条带账本输出原文,拿不出原文=没查过)
1. **漏派**:ready 有货且有空槽 → 处置项「照 ready 首行派」;带 [打回] 标的 = rejected 泊位,处置项 =「rejected→doing --assignee 后派」
2. **验收积压**:pending_review 行的结论文件不在 reviews/ → 处置项「补派 reviewer(验收批任务书模板)」
3. **打回积压**:rejected 行积压 → 处置项「排返工派工」
4. **wait 行**:外部条件已满足(引证据)的 → 处置项「可激活(→todo)」

【综合判断】(候选单素材;每条结论以本轮读到的内容为准,禁止凭空假设)
1. **目标对照**:「目标」判据与账本任务比对——要达成目标还缺哪些任务?缺口 = 候选
2. **账本外来源**(每条候选注明出处:文件:行或路径):欠的债(TODO/到期未还的临时补丁/没跟上代码的文档)/效率(慢到使用者可感知的卡顿)/重复手工(手敲第二次的命令序列)/该测试锁住但没锁的行为/复制粘贴的重复逻辑/攒着没处理的临时件/踩了没记档的坑

【产出格式】最终输出 = 送给编排者的处置单+候选单。第一行固定为「【派发兜底】处置 N 项+候选 K 条,请逐条执行或裁决」或「【派发兜底】无漏派、无候选(实际用目录:你解析出的路径)」。处置项 = 动作+账本原文摘录;候选按建议优先级排序,每条五件齐:
- 任务:一句话说清做什么
- 出处:账本 <T-N> 摘录 / 文件:行 / 现象描述
- 为什么是现在:证据(引账本或文件原文短摘录)
- 建议优先级:一句话理由
- 裁决请求(固定格式):「→ 请裁决:立项(add 进账本) / 缓(写明等什么) / 不立(写明理由)」

单子末尾固定加结语(逐字复制):
「本单是定时自动产物,不需要回复本单;处置单各项由编排者执行(派单照 orchestration.md「派出时」模板),候选成立 → `dag.py add` 立项进账本(写优先级与依赖,进 ready 队列与其它任务同规则竞争槽位),不成立 → 逐条写明原因,只回『收到』不算裁决。候选不经账本不得直接派——账本是派发的唯一队列源。本单不到达时派单也不停——ready 首行补派的纪律照常,本单只是防漏与综合判断的兜底。」

无漏派且零候选时:列出本轮 list/ready 的原样输出与读过的文件清单——没有这些证据,结论不算数;并固定加一句「本结论不构成暂停派单的理由」。

【结论合格线】每条论断+证据+推理链齐,缺一件不写。所有状态判断只以本轮读到的文件内容为准,禁止假设任何本轮没读到的现状。
```

- **改动三审(直启)**(=最近改动三审的形态 B;间隔 60min;任务标签示例「自主推进·改动三审(自动子agent)」;逐字复制下方代码块,只填 `<角括号>`):

```markdown
你是自主推进模式的「改动三审」子 agent。本任务书是你的完整指令;最终输出直接送达编排者,严格按【产出格式】写,不写寒暄、不复述任务书。

【职责边界】你只做一件事:对仓库最近 60 分钟内已提交的改动做三面最严格攻击审(代码/文档/测试)。你不派活、不改任何文件(只读)、裁决权在编排者。

【输入定位】仓库绝对路径 = <创建时填:仓库绝对路径>。审集 = 该路径下 `git log`/`git diff` 最近 60 分钟内的已提交改动(与调度间隔一致);审集为空 → 最终输出写一行「最近 60 分钟无提交,三审空」即结束。

【三面攻击】(立场=假设有错、设法证明;直调仓库文件与规范原文,禁凭 diff 猜)

【产出格式】问题清单按面分组,每条 = 文件:行 + 严重级(阻断/应修/存疑/低)+ 发作场景 + 直调证据;每面附攻过未破角度清单。清单落盘 <创建时填:问题清单落盘路径>,最终输出 = 各面发现计数 + 阻断与应修条目摘要 + 落盘路径。
```

## 提醒词的写法(用户可见的持久化文本)

提醒列表的原文会直接显示在用户界面上,用户随时可能读到——提醒词不是 agent 内部速记。写每条提醒词时按一句话判据自检:**「用户冷不丁看到这条提醒,能读懂它在提醒什么吗?」**答不上=重写:要点用大白话;自造的流程速记词(对工作环节的压缩说法)要么换成直白说法,要么当条带一句定义。

消息内容两条边界(方向相反,互补):

- **角色义务必须进消息**(查什么/怎么判/答什么格式/漏洞封条):提醒被当成「需应答的消息」而非「需执行的指令」、以及凭标题缓存应答,都发生在义务不在消息里时——消息自包含,每轮到达都自带完整检查清单,不依赖会话记忆或回读文件。前缀统一为「⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。」——把消费方式钉进消息本体,抗上下文压缩。
- **当期细节不进消息**(额度数/在跑什么/当期焦点):会过期,过期后误导。这类信息到进度文件/事件通道拿。

消息与角色集表的分工:**模板=唯一全文源**(检查项/判据/封条/答案格式都在这,建定时任务逐字复制、禁精简改写,运行中记不清职责重读这里);角色表=设计速览(角色构成/间隔/一句话定位,不复制检查细则——改职责只改模板,无第二同步面)。

## 自执行 vs 派 agent 的判据

触达后**几分钟内可出动作且判据可内化**的(查状态/跑命令/自问/触发预定义响应链)→ 自执行;**需要干净上下文或长时间专注**的(独立审查/偏见敏感的裁决/批量材料处理)→ 提醒触达后**派 agent 执行**,编排者只收裁决——提醒本身只做触发器,不承载这类工作(带着主会话上下文做=偏见污染)。环境支持形态 B 时,这类角色可进一步把触发也交给定时直启(免提醒中转),选择规则见「触发形态与选择规则」。
