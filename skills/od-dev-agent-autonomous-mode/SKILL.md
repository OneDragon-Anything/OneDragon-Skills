# Agent 自主推进模式(开启与停止的操作指令)

> 本文件只放**操作指令**(开启做什么/停止做什么);运行期方法论在 references/ 按主题分文件,靠开启第 0 步与重读指针在场(上下文压缩后凭指针重读恢复)。**核心哲学:结构性约束 > 自觉**——凡靠「记得」「自省」维持的纪律都会在长会话注意力衰减中失效,必须变成机制(清单格式/锁/提醒角色/代码化检查),让违规无法静默发生。

## ☐ 开启 checklist(没做完这 5 步不算开启完成;每步链后文或 references)

0. ☐ **读运行期方法论**:通读 [references/orchestration.md](references/orchestration.md)(编排者手册:身份与责任/派发节奏与进度文件/委派三拍——派出时·等待时·回答后)与 [references/reminder-net.md](references/reminder-net.md)(提醒网角色表/两触发形态与选择规则/提醒词与任务书写法)——没读完不开工——**必做**
1. ☐ **加载领域专属 skill,了解自主推进全貌(开启第一动作)**:找本任务所属领域的 skill,读它的**自主推进说明**(定时任务角色与提示词模板/要写进指令文件的自主推进纪律/派单规范/监控布防等)——它是本领域开自主推进的具体说明书,**领域规则优先于本 skill 的通用默认**;未命中领域 skill → 按本 skill 通用形态自建专属资产(建完成为该领域的说明书)——**必做**
2. ☐ **建自主推进纪律**(按领域 skill 的说明落地两处):
    - **AGENTS.md 类指令文件写自主推进节**:按下方模板逐字复制各字段 + 领域说明要求增补的自主推进纪律——**每条把判断内容写进指令文件**(动作本身完整可读,如「改策略前先读玩法文档」),指针只作细则入口附带,不是拿一句「见某 skill」代替内容;经用户逐条批准;
    - **创建定时任务**:以本 skill references/reminder-net.md 的通用角色表为**基线**,叠加领域 skill 的特殊要求(领域角色/间隔/提示词差异)——领域有定义 ≠ 跳过通用内容,除非领域 skill 显式声明完全替代;**各角色提示词逐字复制模板全文,禁精简改写**(细则见 references/reminder-net.md 模板节);**按 reminder-net.md「触发形态与选择规则」为每角色选触发形态**——环境支持定时直启子 agent 的用形态 B 任务书(同样逐字复制、只填实例位),否则用形态 A 提醒模板,检查职责等价;创建时刻错开+间隔取不同量级——**必做**
3. ☐ **对齐进度**:进度账本(运行状态单一源)与查看已有改动对得上;**恢复会话(非冷启动)先做「账本-产物对账清欠」**:`pending_review` 态任务逐一核结论文件存在——交付已落盘但状态未流转的欠账(旧会话中断遗留)当场补记或补派验收,清完欠账再取活,防按 todo 重复派工(单日三案实证);**账本不存在 = 新迭代冷启动(非异常)——直接对 `<迭代目录>/dag.jsonl` 跑第一条 `dag.py add`(目录自动建)**(走 od-dev-progress-tracking §2 结构/§7 脚本)——**必做**
4. ☐ **第一波派发**:主会话=编排者,不亲验交付;空子 agent 槽(=额度−1,主会话占 1)按账本 `dag.py ready` 首行分发(排序=优先级→关键链→挡下游),派单套 references/orchestration.md「派出时」的完整任务书模板——**必做**

## ☐ 停止 checklist(用户宣布退出/叫停自主推进时执行;没做完不算收口完成)

1. ☐ **撤提醒网**:删除全部定时任务——形态 A 提醒与形态 B 直启登记都要撤(易失机制也撤,防残留触发)——**必做**
2. ☐ **收尾进行中的批**:逐个处置——快完成的等它完成并验收采纳;停滞/卡死的 interrupt 中断,要求「交付已完成部分+列出未完成清单」;收不回的记档(任务/进度/证据指针)——**必做**
3. ☐ **迭代入口标记终态**:目标未完→入口记「已暂停+下一步恢复点」;迭代完结→按 od-dev-progress-tracking 封存(入口状态改已封存)——**必做**
4. ☐ **删指令文件的自主推进节**:AGENTS.md 类指令文件里开启时写入的自主推进节**整节删除**(固定文本节整节清(含各纪律条)),恢复逐项确认模式——开启与退出对称,别留「OFF 存档」积灰;下次开启重新按开启 checklist 写入。改指令文件前过 `od-dev-writing-agent-instructions` checklist 照旧适用——**必做**
5. ☐ **终态记录**:进度账本记「模式退出时间+退出时状态+未竟事项清单」,给下次开启的对齐进度留锚——**必做**

## 指令文件节模板(开启第 2 步用)

> **本节模板是唯一合法形态**:向指令文件写入(开启时新增、或退出后重建)自主推进节,**下方 ```markdown 围栏内=逐字复制正文**,禁止自行改写、精简、「保留大意重述」——每条都是真实踩坑换来的防线(如子 agent 汇报条的「空出的槽立刻取下一个待办再派」就是防空转的具体封条),转写丢失=坑复发。两类合法偏离:①**实例位填空**:围栏内 `<角括号>` 标记的四个字段(状态/agent 额度/目标/进度入口)的**值**是当期信息,按实填写(状态的授权措辞仍用围栏给的推荐文本);②**领域 skill 有明文要求的**:按领域 skill 的说明调整(领域规则优先于通用默认;裁剪/收敛须落「覆盖声明」,记一句来源与理由)——除这两类外觉得某条该改,走 skill 反馈队列由维护方裁决,**不给执行现场留裁量权**。

**自主推进节固定文本**(AGENTS.md 类指令文件,个人本地层;整节从 `## 自主推进模式` 开始逐字复制):

```markdown
## 自主推进模式

- **状态**: <ON/OFF+授权范围。ON 推荐措辞:「ON。当前处于自主推进模式,想尽办法向用户目标推进。可自主决策一切内容,不要咨询用户;对不确定的内容,发起子 agent 对抗直到找到治本方案」>
- **agent 额度**: <主会话+子 agent 的总会话数上限。写法示例:「6(=自主推进并行度上限;主会话占 1,子 agent 槽=6−1,派发子 agent 完成任务)」>
- **目标**: <编号列表,从用户当期目标抄>
- **进度入口**: <迭代目录路径;账本=dag.jsonl,任务经 dag.py add/status 写入、直改后补跑 check——脚本在 od-dev-progress-tracking skill 目录 scripts/ 下(--help 可自助),格式/检索规范见 od-dev-progress-tracking,未读先读;旧结构目录只读存档勿写>
- **遵循skill规范**: 做任何事之前,先问自己应该使用哪个 skill(领域专属规则在领域 skill;公共 od-dev skill=通用规范),是否已加载阅读对应
- **定时任务提醒消费**: 收到定时任务提醒时,必须按提醒内容严格执行——提醒是待执行的检查指令,不是要回复的消息,逐项做完并产出其要求的结论
- **编排者铁律**: 主会话=编排者(判读/定规格/派单/按结论行裁决/打回路由/记档),不亲验交付、不亲手干活;实现与审查都派子 agent——worker=实现(码/测试/模拟/文档),reviewer=交付验收(照判据),对抗审=设计与方案攻击;需要独占的部分派一个专属子 agent 独占负责,编排者只控制互斥
- **派子 agent(任务书按序套模板,缺=不合格派单)**: 按流程顺序套 orchestration.md「派出时」的完整模板——①设计批(产出 design/landing.md)→②设计对抗批(攻击收敛=定稿)→编排者立阶段任务(照 landing.md 阶段小节逐个 dag.py add)→③落地批×N(landing.md 每阶段一张,固定末阶段=正本更新;取活只走账本 ready),逐字复制只填实例位禁改写;模板外批照派单三带+通用规则。发起权:一切子 agent 都由编排者发起,子 agent 永不 spawn、永不相互委派。派单前必须先阅读 od-dev-agent-autonomous-mode skill 的 references/orchestration.md「派出时」节
- **worktree 批隔离**: 设计定稿后、进入实施前,`tools/wt.ps1 new <change-id>` 建树,并照设计文档的阶段小节逐个 `dag.py add --worktree wt/<change-id>` 立阶段任务;任务书【工作区】填两树路径;设计批/对抗批、不派子 agent 的活,不建树
- **子 agent 汇报(交付到达即走完闭环)**: 编排者先对账(报告文件存在/任务 id 对上,不过=打回重交)→派 reviewer 验收(每次都是全新 agent,禁续用之前的 reviewer 继续审;输入=任务书+交付报告,编排者不读交付正文);accept(reviewer 自闭环:worktree 任务置 `pending_merge` 交合并者批,其余置 done)→空出的槽立刻照 `dag.py ready` 首行取下一个待办再派,不等下一轮想起来;reject(reviewer 自登记 `rejected` 打回泊位)→排到返工再由编排者 `doing --assignee` 派出;同一任务打回≥3轮=停派立「规格重审」;报告未尽事项当场立项或记不立缘由。必须先阅读 od-dev-agent-autonomous-mode skill 的 references/orchestration.md「回答后」节
- **合并者(单例)**: 全局至多一个合并者子 agent;取活=账本 `pending_merge` 段,照 orchestration.md「派出时」的「合并者任务书」模板派单执行;全程只 commit 不 push
- **树的建/并/删只经 `tools/wt.ps1`**: 手工删树会丢树内遥测,按事故处理
```

**占位符约定**(全 skill 通用):`<角括号>`=实例填充位,开启时按实填写;填写信息一律来自**用户当期明示**(开启指令/对话原话),禁止 agent 自造或沿用上一次迭代的旧值。

**填充指南**(每个占位符的值从哪来、怎么算填对):

| 占位字段 | 值从哪来 | 填充判据 |
|---|---|---|
| 状态 | 用户开启授权的措辞;无明示措辞时用围栏内 ON 推荐文本 | OFF 仅退出清理期临时标注,平时恒 ON |
| agent 额度 | 用户当期裁定的数字 | 格式=「N(=主会话+子 agent 上限 N;主会话占 1,子 agent 槽=N−1)」;未裁定时向用户要,不默认 |
| 目标 | 用户当期目标原话(编号列表) | 与用户说的逐字等价,禁止 agent 改写提炼;判据定义不在目标行展开,只放指针 |
| 进度入口 | 迭代目录路径 | 新迭代=填将用的目录路径(随首条 add 自动建);存量迭代=含 dag.jsonl 的目录;占位内 CLI/规范指引文字**原样保留**,只填路径 |
| 领域纪律条(可选) | 领域 skill 的说明列出的条目 | 每条=完整动作判断+自包含指针(写全 skill 名/文件/节),禁裸编号;没有=不添加 |

**固定文本之外仅可放经用户逐条批准的自主推进纪律**(每条 = 完整的动作判断写进文件(如「改策略前先读玩法文档」),细则入口指针附带——不是只写一句指针让读者跳转;判据=纪律作用于行动冲动瞬间,那一刻 skill 未必加载、提醒有空窗,只有指令文件永远在场;领域 skill 的说明列有哪些纪律该写入;**指针必须自包含可解析**——写全「哪个 skill 的哪个文件/节」,禁裸编号或短名引用)。

**不放**:运行机制说明/单一源声明(双源,机制在本 skill);周期性回看类纪律(走提醒网)。

**改指令文件前先过 `od-dev-writing-agent-instructions` 的 checklist**(判层/判层内归属/指令本体/纯度自检/改动流程)——指令文件是常驻 token 成本,别越写越肥;方法论细节往本 skill 沉。

## 通用写全、领域叠加(专属资产的形态规范)

本 skill 各机制自带完整默认形态,无专属资产的任务直接照用即可运转;领域 skill 的编排资产**只写叠加项,不复制通用原文**(复制=双源,通用层演进后领域侧即成旧版)。三类合法叠加:
1. **项目化映射**:通用条目在本领域的名字/间隔/提示词/文档集实例化,标注对应通用层哪一项;
2. **增量条目**:本领域新增的规则,标注「通用层没有」;
3. **覆盖声明**:裁剪/合并/收敛通用内容时(如角色集七→四),记一句来源与理由,别让读者以为通用层只有这些。

读者约定:**通用层=基线,领域编排文件=只读差异**。
