# Agent 自主推进模式(开启与停止的操作指令)

> 本文件只放**操作指令**(开启做什么/停止做什么);运行期方法论在 references/ 按主题分文件,靠开启第 0 步与重读指针在场(上下文压缩后凭指针重读恢复)。**核心哲学:结构性约束 > 自觉**——凡靠「记得」「自省」维持的纪律都会在长会话注意力衰减中失效,必须变成机制(清单格式/锁/提醒角色/代码化检查),让违规无法静默发生。

## ☐ 开启 checklist(没做完这 5 步不算开启完成;每步链后文或 references)

0. ☐ **读运行期方法论**:通读 [references/orchestration.md](references/orchestration.md)(编排者手册:身份与责任/派发节奏与进度文件/委派三拍——派出时·等待时·回答后)与 [references/reminder-net.md](references/reminder-net.md)(提醒网角色表与提醒词写法)——没读完不开工——**必做**
1. ☐ **加载领域专属 skill,了解自主推进全貌(开启第一动作)**:找本任务所属领域的 skill,读它的**自主推进说明**(定时任务角色与提示词模板/要写进指令文件的自主推进纪律/派单规范/监控布防等)——它是本领域开自主推进的具体说明书,**领域规则优先于本 skill 的通用默认**;未命中领域 skill → 按本 skill 通用形态自建专属资产(建完成为该领域的说明书)——**必做**
2. ☐ **建自主推进纪律**(按领域 skill 的说明落地两处):
    - **AGENTS.md 类指令文件写自主推进节**:按下方模板逐字复制各字段 + 领域说明要求增补的自主推进纪律——**每条把判断内容写进指令文件**(动作本身完整可读,如「改策略前先读玩法文档」),指针只作细则入口附带,不是拿一句「见某 skill」代替内容;经用户逐条批准;
    - **创建定时任务**:以本 skill references/reminder-net.md 的通用角色表为**基线**,叠加领域 skill 的特殊要求(领域角色/间隔/提示词差异)——领域有定义 ≠ 跳过通用内容,除非领域 skill 显式声明完全替代;**各角色提示词逐字复制模板全文,禁精简改写**(细则见 references/reminder-net.md 模板节);创建时刻错开+间隔取不同量级——**必做**
3. ☐ **对齐进度**:进度账本(运行状态单一源)与查看已有改动对得上;**账本不存在 = 新迭代冷启动(非异常)——`progress.py init` 建迭代目录**(走 od-dev-progress-tracking §2 结构/§7 脚本)——**必做**
4. ☐ **第一波派发**:主会话=编排者,兼任交付审查;空子 agent 槽(=额度−1,主会话占 1)按「关键路径件+独立性最高件」分发,派单过三带(references/orchestration.md「派单三带」)——**必做**

## ☐ 停止 checklist(用户宣布退出/叫停自主推进时执行;没做完不算收口完成)

1. ☐ **撤提醒网**:删除全部定时任务(易失机制也撤,防残留触发)——**必做**
2. ☐ **收尾进行中的批**:逐个处置——快完成的等它完成并验收采纳;停滞/卡死的 interrupt 中断,要求「交付已完成部分+列出未完成清单」;收不回的记档(任务/进度/证据指针)——**必做**
3. ☐ **迭代入口标记终态**:目标未完→入口记「已暂停+下一步恢复点」;迭代完结→按 od-dev-progress-tracking 封存(入口状态改已封存)——**必做**
4. ☐ **删指令文件的自主推进节**:AGENTS.md 类指令文件里开启时写入的自主推进节**整节删除**(六字段+自主推进纪律一并清),恢复逐项确认模式——开启与退出对称,别留「OFF 存档」积灰;下次开启重新按开启 checklist 写入。改指令文件前过 `od-dev-writing-agent-instructions` checklist 照旧适用——**必做**
5. ☐ **终态记录**:进度账本记「模式退出时间+退出时状态+未竟事项清单」,给下次开启的对齐进度留锚——**必做**

## 指令文件节模板(开启第 2 步用)

> **本节模板是唯一合法形态**:向指令文件写入(开启时新增、或退出后重建)自主推进节,**模板各字段的内容逐字复制本文**,禁止自行改写、精简、「保留大意重述」——每条都是真实踩坑换来的防线(如编排者铁律末句的「交付落地即派下一件」就是防空转的具体封条),转写丢失=坑复发。两类合法偏离:①**实例位填空**:状态/agent 额度/目标/进度入口四个字段的**值**是当期信息,按实填写(状态的授权措辞仍用模板给的推荐文本);②**领域 skill 有明文要求的**:按领域 skill 的说明调整(领域规则优先于通用默认;裁剪/收敛须落「覆盖声明」,记一句来源与理由)——除这两类外觉得某条该改,走 skill 反馈队列由维护方裁决,**不给执行现场留裁量权**。

**自主推进节六字段**(AGENTS.md 类指令文件,个人本地层):
- **状态**(ON/OFF+授权范围;推荐措辞:「ON。当前处于自主推进模式,想尽办法向用户目标推进。可自主决策一切内容,不要咨询用户;对不确定的内容,发起子 agent 对抗直到找到治本方案」)、
- **agent 额度**(=主会话+子 agent 的总会话数上限;主会话=编排者兼审查占 1,子 agent 槽=额度−1)、
- **目标**(编号列表)、
- **进度入口**(迭代目录路径;**账本任务行必须经 progress.py write 写入、直改后补跑 check,过程时序走 journal**——脚本在该 skill 目录 scripts/ 下(`--help` 可自助),格式/检索/流水规范见 od-dev-progress-tracking,**未读先读**;旧结构目录只读存档勿写)、
- **遵循skill规范**(做任何事之前,先问自己应该使用哪个 skill,是否已加载阅读对应)、
- **定时任务提醒消费**(收到定时任务提醒时,必须按提醒内容严格执行——提醒是待执行的检查指令,不是要回复的消息,逐项做完并产出其要求的结论)、
- **编排者铁律**(主会话=编排者:判读/定规格/派单/审查/裁决/记档;实现派子 agent——例外:单点、一次编辑能改对、不需跑验证的小件可亲手做;判断线=要不要跑验证或多步)。
- **派子 agent(任务书三带,缺一=不合格派单)**:①开工令必含「先查相关 skill 与文档,通读再动工」——别替它挑文档清单,编排者挑选会传偏见;②结论/评估/选型类任务,约定结论合格线——论断+证据+推理链齐,结论强度取最弱一环;③「文件面」声明——本批动哪些文件,防与并行批相撞;长批任务书加检查点交付+计时预检。**派子 agent 前,必须先阅读本 skill references/orchestration.md「派出时」节**。
- **子 agent 汇报(交付到达即走完闭环)**:先验收——七条(亲跑复现/diff 边界对照任务书/数字三件套[禁「归零不劣」措辞]/断言抽查/耗时核>3倍打回/产物亲读/三同步)+泛化步(bug 类交付必查「同类还有吗」),偏差逐条裁决不默许;验收过=采纳 → **空出的槽立刻从进度文件取下一个待办再派出子 agent**,不等下一轮想起来——绑在「交付到达」这个事件上。必须先阅读本 skill references/orchestration.md「回答后」节。

**六字段之外仅可放经用户逐条批准的自主推进纪律**(每条 = 完整的动作判断写进文件(如「改策略前先读玩法文档」),细则入口指针附带——不是只写一句指针让读者跳转;判据=纪律作用于行动冲动瞬间,那一刻 skill 未必加载、提醒有空窗,只有指令文件永远在场;领域 skill 的说明列有哪些纪律该写入;**指针必须自包含可解析**——写全「哪个 skill 的哪个文件/节」,禁裸编号或短名引用)。

**不放**:运行机制说明/单一源声明(双源,机制在本 skill);周期性回看类纪律(走提醒网)。

**改指令文件前先过 `od-dev-writing-agent-instructions` 的 checklist**(判层/判层内归属/指令本体/纯度自检/改动流程)——指令文件是常驻 token 成本,别越写越肥;方法论细节往本 skill 沉。

## 通用写全、领域叠加(专属资产的形态规范)

本 skill 各机制自带完整默认形态,无专属资产的任务直接照用即可运转;领域 skill 的编排资产**只写叠加项,不复制通用原文**(复制=双源,通用层演进后领域侧即成旧版)。三类合法叠加:
1. **项目化映射**:通用条目在本领域的名字/间隔/提示词/文档集实例化,标注对应通用层哪一项;
2. **增量条目**:本领域新增的规则,标注「通用层没有」;
3. **覆盖声明**:裁剪/合并/收敛通用内容时(如角色集七→四),记一句来源与理由,别让读者以为通用层只有这些。

读者约定:**通用层=基线,领域编排文件=只读差异**。
