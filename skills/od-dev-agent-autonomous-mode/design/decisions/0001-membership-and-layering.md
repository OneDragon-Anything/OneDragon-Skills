# 0001. 只收自主推进专属内容;操作指令与方法论分层存放

- **Status**: accepted
- **Date**: 2026-08-27

## Context

本 skill(管理 AI agent 长时间自主开发的框架)此前的内容按「实战中有效就收录」的方式生长:某次实战证明了某条纪律有用,就写进 skill。数月后 SKILL.md 累积到约 150 行,混入了大量与自主推进无关的内容——例如「验证要分层跑」「文档变更要留决策记录」「模拟环境能验证的就不占用真实环境」这类**任何开发模式都适用的工程纪律**,以及只在具体项目里才有意义的**领域运行细节**(如某游戏玩法的对局早停条件、某项目的盘点来源清单)。

用户逐条审问这些内容后判定:它们不属于本 skill,并全部移除或迁移。同时本 skill 的结构也做了重排(见 Decision 第 2 条)。旧的决策存档(design/decisions/ 全部 11 条 ADR)因与重整后的现状大面积矛盾,整体废弃删除;本条为新存档的第一条。

背景事实(影响 Decision 第 2 条):skill 被触发加载后,其内容会在 agent 的上下文中存活**一段时间**,但 agent 的上下文会周期性压缩(compaction)——压缩后哪些内容仍在场不可保证。因此不能假设「skill 读过一遍,运行期就一直有效」。

## Decision Drivers

- 内容越塞越多导致 context rot:注入上下文的指令越长,单条指令被遵守的概率越低;
- 无成员判据的收录标准使 skill 变成杂物层,维护者无法判断「新内容该不该进」;
- 上下文压缩使「一次加载终身有效」的假设失效。

## Considered Options

1. **维持全内联**(所有方法论都放 SKILL.md):否——压缩后在场的概率不可保证,且内容越长指令衰减越严重;
2. **删掉运行期方法论,只留操作指令**:否——方法论本身有消费场景(见 Decision 第 2 条的再注入通道),删等于知识蒸发;
3. **方法论按「消费时刻」分文件**(收账时读什么/盘点时读什么):否——内容的消费时刻会随流程演进而变(实例:早停相关内容先被当作「停止自主推进时用」,后被重新判定为「运行中反复发生的动作」),按时刻切会反复错位;按**主题**切则稳定;
4. **操作指令与方法论分层存放,方法论按主题分文件**(选中,见下)。

## Decision

两条不变量:

1. **内容成员判据**:一条内容收进本 skill,必须因为它**只在「用户不在场」或「任务长时间运行」的场景下才需要**——这两点是自主推进区别于普通开发的全部特殊性。通不过判据的,按性质归位:
   - 任何开发模式都适用的工程纪律 → 项目入口文件(如 AGENTS.md)或对应主题的 skill;
   - 具体项目的规矩 → 该项目的领域 skill;
   - 具体项目的运行细节(早停条件形态/盘点来源/提醒间隔)→ 领域 skill;
   - 委派子 agent 的通用手艺(任务书怎么写/交付怎么验收)→ 暂留本 skill(自主推进是当前唯一高频委派场景);出现第二个高频委派场景时独立成 skill。
2. **分层存放**:SKILL.md 只放「模式开关时刻的操作」——开启 checklist、停止 checklist、指令文件节模板;运行期方法论放 references/ 按主题分文件。方法论靠四条通道保持在场:开启 checklist 第 0 步强制通读(开启时刻全量在场)/ 指令文件里的自主推进纪律(行动冲动时刻)/ 定时任务提醒词(周期时刻)/ SKILL.md 末尾的重读指针(上下文压缩后按需恢复)。

## Consequences

- **正向**:维护有了可操作的准入判据;SKILL.md 从约 150 行缩到约 60 行;方法论在四个在场通道支撑下不依赖「读过就一直在」。
- **负向**:开启多一步(第 0 步通读);运行中遇到纪律问题需经重读指针多一跳。
- **本次同时移除的内容清单**(判据的实例,便于后续维护者对照):「资产组/点名册/收账依据」(指向不存在的实体,已查证)、「分层验证/分层落位/资产维护回路/治本三纪律」(通用工程或项目纪律)、「运行期早停节」(领域运行属性,判据归领域 skill)、「四来源盘点」(项目清单,已迁回领域 skill)、旧 ADR 存档全部(与现状矛盾)。
