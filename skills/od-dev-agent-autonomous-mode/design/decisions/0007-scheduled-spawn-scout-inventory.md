# ADR-0007:找活盘点增设定时直启子 agent 形态(两触发形态并存)

- Status: accepted(试点)
- Date: 2026-09-01

## Context

提醒网定时任务此前全部为「定时提醒编排者」形态:到点把检查指令送进编排者会话,靠编排者读到并执行。实战暴露两类失效(2026-09-01 用户观察):①提醒代劳的中间跳依赖模型自觉——提醒送达后编排者不照做时检查静默丢失,违反本 skill 核心哲学「结构性约束 > 自觉」;②大量提醒诱发仪式性作答——编排者到点习惯性回答盘点提醒(「扫过了,无需派」),找活退化成仪式,实际派单停摆。

环境侧存在另一种定时机制(如 DSH 的定时直启子 agent):登记后到点由环境自动 spawn 全新上下文子 agent 执行预设任务书,不占编排者模型请求,结果自动回会话唤醒编排者。但该机制并非所有环境都有(可移植性约束),skill 不能硬绑。

## Considered Options

- **维持单一提醒形态,继续加固提醒词**:否决——ADR-0002 已把消息自包含做到位,失效点不在消息而在「编排者选择执行」这一跳;措辞救不了机制缺口。
- **全部角色改直启**:否决——值守兜底/回顾依赖会话内状态(子 agent 状态清单、干预权、对会话自身注意力与工作前提的自审),子 agent 无权也无从看到;派单裁决权必须留编排者(ADR-0005)。
- **两形态并存 + 按角色与环境选择(选中)**:找活这类「周期性、范围可自账本自定、产出=报告待人裁决、受益于干净上下文」的角色,在支持直启的环境改由定时直启子 agent 承担;不支持的环境保留提醒形态,检查职责等价。
- **与 ADR-0005 否决项的关系**:0005 曾否决「每轮盘点无条件派找活 agent」,理由是占用同预算子 agent 槽与 token 的机会成本;形态 B 由环境调度直启、不占派单槽,成本收敛为每次短命 agent 的 token,被试点接受为保费——机制变了,当时否决的理由不再成立;间隔(15min)若运行数据显示成本过高可放大,由数据裁决。

## Decision

- reminder-net.md 增设「触发形态与选择规则」:形态 A=定时提醒编排者(既有模板);形态 B=定时直启子 agent(新增任务书模板)。环境支持形态 B 的角色用 B,不支持用 A,职责等价;选定形态 B 的角色不再建形态 A 提醒(替代实现,不是叠加)。
- 试点范围=派发盘点(找活盘点子 agent):创建时传入迭代目录(附指令文件进度入口自愈);只做一件事——实扫账本未完成集、按依赖排出当前可开工候选;只产候选不派活、只读不改文件;产出=催办单(每候选带固定格式裁决请求,末尾固定催办结语,「只回收到不算裁决」钉进消息本体,与 ADR-0002 同思路)。
- 形态 B 下,形态 A 盘点模板第 5 步(零候选升级找活子 agent)由周期找活盘点本身替代——独立上下文已常驻,无需二次升级;该步保留且仅适用形态 A。ADR-0005 的原则(子 agent 只产候选、派单权不上交)不变并继承。
- 代码审计/文档审计的形态 B 版本待盘点试点验证后按同框架补,本次不动。

## Consequences

- 正:找活从「编排者被提醒后自查」变为「编排者消费现成候选单」,找活端不再依赖模型自觉;ADR-0004 的防记忆作答封条在形态 B 由无记忆上下文构造性满足,任务书不抄封条只留证据要求(避免双源)。
- 负/残余风险:消费端仪式化(候选到达仍不派)——由产出格式的催办结构压制,试点成败判据=「候选到达→实际派单」转化;若候选源源到达仍不派,问题在裁决/验收端,另立决策收紧,不在本 ADR 范围内加封条。
- 账本状态词的单一源=od-dev-progress-tracking skill;两形态模板中的 grep 状态词串都是该源的示例镜像,演进时以 skill 为准。
- 周期找活盘点连续多轮零候选=目标接近饱和信号(承 ADR-0005):编排者应向用户回报饱和,不继续空转。
- 可移植性:环境缺直启机制时不丢检查(形态 A 兜底),符合 design/overview「不绑具体定时机制」边界。
