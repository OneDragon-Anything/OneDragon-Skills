# ADR-0006: 采信前对抗按「采信错了的代价」分三档

## Status

accepted

## Context

「重要结论采信前对抗」原先是单形态:单点结论派一路干净上下文攻击者(设法推翻)。两场大型多批实施战役实证该形态对两类产物不够:

1. **设计稿指导多批实施**:单次攻击通过后,实施期再无对抗——问题在多批写完后才暴露,推翻代价是整批返工;
2. **重大方向选型**:只有单一作者论证+一路攻击,竞争方案的发现面(如「整体去掉某部件更优」)与裁决可信度(谁的效果上限更高)都不足。

## Considered Options

- **只保留单路攻击**:否——两类产物的失败形态都发生在单路覆盖之外(实施期与选型期),不是单点结论场景的失败。
- **三档拆成独立小节/独立流程**:否——三档是同一判据(对抗强度与采信代价成正比)的强度梯度,拆开会割裂总则、重复表态。
- **写成固定 checklist**:否——档位选择是连续判断(产物重大程度是分布,不是枚举),不是步骤序列。

## Decision

采信前对抗按产物代价分三档:

- **档 1 单点结论** = 单路攻击(维持原节内容不变);
- **档 2 设计稿与成批实施** = 每轮修订配一路攻击;再攻击第一步逐条复核上轮修复质量(三判:真解决/表面绕过/修复引入新问题);提不出新的实质问题才实施;实施期每批攻击并行,禁「全部写完再统一审查」;
- **档 3 重大方向选型** = 多路竞争独立方案+互攻+无锚攻击,裁决=各方案证据支撑内可达成效果的上限。

总判据(对抗强度∝采信代价;裁决只看证据与实测效果,不看说服力与票数)写进节首统辖三档。

## Consequences

- 编排者派产物批前需先判档(单点/设计稿/重大选型);档 2/3 的攻击批会占子 agent 槽——实施期并行度被攻击批分走是**设计内的代价**,换取推翻前置(整批返工率下降)。
- 实证与案例留在消费方项目本地(反馈队列/进度账本),本 skill 文本保持零案例、零项目专名。
