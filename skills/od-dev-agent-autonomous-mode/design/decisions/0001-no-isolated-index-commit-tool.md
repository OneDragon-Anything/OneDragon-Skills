# 0001. 多 agent 并行提交不引入 GIT_INDEX_FILE 私有索引提交工具

- **Status**: accepted
- **Date**: 2026-09-12

## Context

自主推进模式下,一个编排者主会话带多个子 agent 并行干活,它们会在**同一个仓库工作区**里各自提交自己被授权的文件。git 的提交默认经过仓库共享的暂存区(index,即 `.git/index` 文件,`git add` 写它、`git commit` 读它),它是所有并行 agent 的竞争点:并发 `git add` 互相抢锁、互相污染,笼统的 `git commit` 会把别人暂存的改动卷进自己的提交。

当时讨论的提案:用环境变量 `GIT_INDEX_FILE` 把单次提交的暂存区指到一个私有副本文件(计划放 `.debug/git-index/`,该目录已 gitignore),配合 git 低层命令(plumbing,直接操作对象库与引用的命令,如 `read-tree` / `write-tree` / `commit-tree` / `update-ref`)实现「每次提交恰好只含点名的文件」,并已写出一版带防线的 PowerShell 脚本。

实现过程中在一次性临时仓库里实测了 git 2.52 的裸行为,发现两种**静默**损坏形态(见 Considered Options B);最终用户裁定不引入此类工具,已写代码全部删除(从未 commit,无 git 历史可考古,本 ADR 是唯一存档)。

## Decision Drivers

- 保护必须机制化:本 skill 核心原则是「结构性约束 > 自觉」,靠记忆执行的防线在长会话里必然失效。
- 采用率:一个「记得去用才安全」的工具,漏用一次的危害是否反而大于不用。
- 提交原子性:并行场景下一次提交必须恰好等于声明的文件集,多卷入、少提交都是事故。
- 不许静默破坏别人的提交:git 层要么报错要么拒绝,不能悄悄改写别人已提交的内容。

## Considered Options

**A. 维持现状:共享暂存区 + 流程契约**

各 agent 按任务书契约逐文件点名 `git add`(禁 `-A`/目录级)后 commit;reviewer 验收时用 `git show` 逐 commit 对照文件面(该批被授权改动的文件集合)核查,没夹带、没少交才算过。
- 优点:零新机制;安全边界长在派单/验收流程里,天然 100% 覆盖(每个 commit 都有任务书与验收)。
- 缺点:并发窗口内共享暂存区仍可能互相污染,拦截靠纪律与验收,不是提交时刻的机械校验;`.git/index.lock` 竞争由 git 自身报错暴露。

**B. 私有索引·裸配方(`GIT_INDEX_FILE` + `read-tree` + `git add` + `git commit`)** —— 实测否决

在临时仓库实测出两种静默损坏:
1. **静默删除别人的提交**:私有索引的基线是从构造时刻的 HEAD 读入的;构造期间另一 agent 提交了新文件后,前者照常 commit,结果新提交的树里没有那个文件——对方刚提交的内容被从提交树里抹掉,git 不报任何错,提交看起来完全正常。
2. **提交后被回退**:私有索引提交不更新共享 `.git/index`,其中残留的旧内容相对新 HEAD 变成「待提交的反向改动」(status 显示 `MM`);此后任何人做一次普通 commit,都会把刚才的提交回退掉。

**C. 私有索引 + 四道防线**(写到语法校验通过,未投产)—— 否决

防线:① 发布前校验「本次树相对基线的差集 == 点名文件集」,不等即中止;② `update-ref` 带旧值做比较交换,期间 HEAD 被推进则自动重建重试;③ 提交后把共享索引里**点名路径**的条目对齐到新提交,防 B-2;④ 私有索引目录未 gitignore 即拒绝运行。
否决理由:全部防线的有效性依赖 **100% 采用率**。只要有一个 agent 或人忘记用脚本、走了普通 commit,B 的两种损坏原样发生;且混合使用时防线 ③ 会改写共享索引,反而新增「普通使用者暂存内容被悄悄替换」的形态。「用不用」本身就是靠记忆执行的动作,直接违反本 skill「结构性约束 > 自觉」:一个必须记得才安全的工具,比没有工具更糟。

**D. git hook 层防线(如 pre-commit 拦截粗粒度提交)** —— 未深入评估即终止

记录为将来重启此问题时的入口判据:任何方案要成立,必须把「普通 `git commit` 在并行场景不安全」变成**不可绕过**的机制,而不是提供一个更安全的可选项让 agent 自选。

## Decision

不引入任何私有索引提交工具,维持方案 A。并行提交的安全边界留在既有流程契约(任务书逐文件点名 + reviewer 边界核查),不在 git 层加机制。

## Consequences

- **接受的代价**:并发窗口内共享暂存区仍可能互相污染,拦截依赖纪律与验收;`.git/index.lock` 竞争由 git 报错自然暴露。
- **沉淀的硬知识**(将来重新提案者先过这关):裸 `GIT_INDEX_FILE` 配方有 B 节两种静默损坏;混合采用比不采用更糟;新方案必须做到「绕过即报错」才有资格进入方案比较。
- 已写的一版带防线脚本(含临时仓库实测)已删除,未提交、未投产;本 ADR 是其唯一存档。
