# ADR-0009:提醒词按「用户可见的持久化文本」写——大白话+指针,判据=谁会看到

- Status: accepted
- Date: 2026-08-25

## Context

消费方实战反馈(用户第三次批评黑话,原话「你这个 schedule 里也全是黑话」):提醒网创建时,提醒词全部使用会话内速记词(对工作流各环节的压缩说法)。提醒工具会把提醒列表原文直接显示在用户界面,用户随时读到。此前本 skill 对提醒词只有**内容稳定性**约束(「放角色不放当期细节」,防过期),没有**语言**约束——写提醒的 agent 默认用自己当下的速记语境,产出对用户是不可读的密码。三次批评同根:策略呈报黑话 → 提醒内容错位 → 提醒语言黑话,共同病根是「用户可见面靠枚举产出类型来触发语言自检,枚举永远落后于下一个没见过的新面」(提醒词既非对话也非文档,两边的枚举清单都没覆盖它)。

## Considered Options

- **只在消费方入口文件扩枚举**(把「提醒词」加进需过语言自检的产出类型清单):否决——枚举落后于新面,第三次翻车即实证;且入口文件随消费方走,管不到本 skill 被其它项目/协作者使用时的提醒词产出。
- **提醒词照旧,用户问了再解释**:否决——用户可见即用户沟通面,不可读的提醒词直接损害信任,事后解释不消除读取瞬间的不可懂。
- **skill 层硬规范:大白话+指针化(选中)**:提醒词按「用户可见的持久化文本」对待,过一句话判据「用户冷不丁看到这条提醒,能读懂它在提醒什么吗」;规则细节(查什么/怎么答)留在 §5 各角色行,提醒词只写「触发+一句大白话要点+指针」。与既有「放角色不放当期细节」互补:那条防**过期**,这条防**看不懂**。

## Decision

§5 提醒网节(角色表后)新增「提醒词的写法(用户可见的持久化文本)」硬规范段。

## Consequences

- 正:任何 harness 里用户可见的提醒/任务标签类文本有了可执行判据;速记语义仍在 skill 正文/角色行单一源存在,提醒词只是展示层,不产生双源。
- 负:提醒词比速记长(大白话+指针占字数)——用指针控制长度,细节不内联;提醒创建时多一道自检(一句话判据,成本低)。
