# ADR-0007:三类工作分类(主线/发现轨/持续流程)——按触发器分,不按可并行性合

- Status: accepted
- Date: 2026-08-25

## Context

用户梳理:「当前推进的事在进度文件按依赖派发没问题;但推进以外还有可并行的事——sim 找问题、代码文档 review、设计对抗——有些是长期周期性的,有些是短期目标内周期性的;跟着短期目标走的周期性事要有提醒更新」。此前 skill 的两分法(一次性件/持续性件)漏了中间态:**发现轨的单个任务是次性的,但这一类工作是周期性的**(永远值得再 review 一轮)。

## Considered Options

- **统一成「可并行的工作」一种**:否决——用户提出的备选,但并行性是调度属性不是工作本质;统一后丢触发器:主线靠依赖驱动不会忘,发现轨不周期扫就永远排在主线后(重要不紧急),持续流程不监控健康就静默死。
- **两分法(一次性/持续性)**:否决——发现轨被错分到一次性(单个任务是)或持续性(类是),两处都别扭,正是此前「待办清单」设计混乱的根源。
- **三分法按触发器(选中)**:主线(依赖驱动)/发现轨(周期扫描)/持续流程(健康监控)——行业术语:critical path 与 dual-track 的交付轨/discovery track 与使能工作/run work(项目 vs 流程)。CW 实例验证三分互斥完备。

## Decision

skill §3 增三类工作表(定义+触发机制+例子),§4 关注面节按三栏记,进度对表提醒按三栏语义查偏移。发现轨的供给=四来源盘点+大 commit 后 review 默认动作。

## Consequences

- 正:每件工作有明确触发器(丢不了);盘点空转时优先从发现轨找活(重要不紧急的护位);持续流程有健康线不靠记。
- 负:三栏要求维护时判类型(约 2 秒/件)——由关注面节重写频率低兜底(事件驱动为主)。
