# ADR-0002:提醒消息自包含与统一前缀

- Status: accepted
- Date: 2026-08-27

## Context

自主推进的提醒网(定时任务)原设计:提醒词只承担「触发+一句大白话要点+指向角色行的指针」,检查细则留在 skill 文件的角色表里——防止细节复制后过期漂移。实证失效:一夜自主推进中,主会话 20+ 轮提醒全部以盖章式空回复消费(「状态未变」「守夜设计态确认」),五小时零动作;提醒词内明明写着「禁止只写无需派」也被绕过。失效机制:①提醒被分类为「需应答的消息」而非「需执行的指令」;②凭标题缓存应答,正文不重读;③上下文压缩后「消息→角色行」的指针链断裂,重建成本高且每步都可偷懒。

## Considered Options

- **维持指针依赖(修消费纪律)**:让执行者「按指针重读角色行再执行」——否决:连消息正文都没读,指望它多走一步读文件不现实;指针链三步(收到→打开文件→找到行)每步都是失效点。
- **消息自包含(选中)**:角色义务(查什么/怎么判/答案格式/漏洞封条)全文进消息,每轮到达自带完整检查清单,零外部依赖;配统一前缀把消费方式钉进消息本体。
- **妥协版(要点+指针并存)**:正文带要点、细节仍指文件——否决:与指针依赖同病,且两处内容重叠无同步价值。

## Decision

- 提醒消息 = 前缀 + 完整角色义务 + 一行来源标注。前缀统一:「⚠️ 自主推进执行提醒:你在自主推进模式中。这条不是要回复的消息,是系统发来的待执行检查指令,现在执行。」——改变消息类别(分类发生在读正文之前),抗上下文压缩(压缩后消息本体仍自带契约)。
- **当期细节仍禁入消息**(额度数/在跑什么/当期焦点):会过期,过期后误导——与角色义务的「稳定方法论不过期」相反,两条边界方向相反互补。
- 角色集表瘦身为设计速览(角色/间隔/类型/一句话定位),检查细则唯一全文源=提示词模板;改职责只改模板,无第二同步面。
- 提醒词同时是用户界面可见文本,过白话自检(「用户冷不丁看到能读懂吗」)。

## Consequences

- 正:消费失效的两个根(类别误判/缓存应答)都在消息本体层面封死;重建定时任务=整块照抄模板,部署动作机械化。
- 负:消息变长(多行);消息与 skill 演进存在滞后窗(改模板后需重建在飞任务才同步)——接受,改提醒网本来=重建网。
