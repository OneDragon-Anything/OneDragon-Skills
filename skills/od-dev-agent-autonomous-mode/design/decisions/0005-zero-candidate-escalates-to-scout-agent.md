# ADR-0005:盘点零候选升级派干净上下文找活子 agent

- Status: accepted
- Date: 2026-08-28

## Context

「还有没有其他该做的事」原有两道保险:派发盘点产出结论 + 回顾第 4 问换地复核(ADR-0004 让两道都建立在当轮实扫上)。但两道仍由编排者**在同一会话上下文里**执行——换的只是搜索地点,不是眼睛。实测(CW 自主推进)零候选结论连续多轮成立时,编排者的视野已被当期焦点框住:进度树里跨域的待办(别的 app 池/文档债/基建件)被系统性漏看,而「换地方再找一遍」的纪律补不了上下文偏见——这正是本 skill 核心哲学(结构性约束 > 自觉)指出的失效形态:靠自觉换视野不可靠,要换成机制。用户提案(2026-08-28):盘点最终结论为零候选时,发起干净上下文的子 agent,把当前自主推进的目标告诉它,让它快速找有什么能做。

## Considered Options

- **维持两道保险,不加第三道**:否决——盘点与回顾共享同一会话上下文,视野收窄是结构性的,加严措辞救不了;且零候选时段恰是子 agent 槽全空的时段,有免费产能不用。
- **每轮盘点无条件派找活 agent**:否决——有活可派时白白占一个槽和一份 token;条件应绑在「零候选」这个结论上,触发时机天然无机会成本。
- **零候选且有空槽 → 升级派干净上下文找活子 agent(选中)**:编排者只交出目标与进度入口,重扫交给无会话记忆的子 agent;候选回来仍由编排者逐条裁决——找活可以外包,派单权不上交。
- **任务书复述找活方法** 对比 **引用模板第 2、3 步(选中引用)**:复述=第二份来源清单,模板演进后找活 agent 拿的是旧版;引用保持单一源。引用须写全文件与节名由子 agent 自行读文件——子 agent 是干净上下文,看不到提醒词本身,裸步骤号不可解析。

## Decision

- 派发盘点提醒模板加第 5 步:结论为零候选(非额度满)且有空槽 → 派干净上下文的找活子 agent。任务书三件:①目标与进度入口运行时从指令文件(AGENTS.local.md 自主推进节)字段抄全文——当期细节不进提醒词,与 ADR-0002 一致;②找活方法引用本文件「派发盘点」模板第 2、3 步(指针写全文件与节名,子 agent 自行读文件;来源清单单一源,模板演进自动跟上);③产出=候选清单,每条带出处与理由,只找不派。
- reminder-net.md「双保险设计」节改「三重保险设计」:盘点**产出**结论、回顾**审计**结论、找活子 agent 用**独立上下文**复核结论。
- orchestration.md「派发节奏」节同步一条细则(零候选升级换眼睛),与模板第 5 步对齐。

## Consequences

- 正:零候选结论从「同上下文自查」升级为「异上下文复核」,与子 agent 审计的独立视角同型;空闲期空槽自动投入找活,「零产出=报警」的面收窄。
- 负:真无活可做时每轮盘点(15min)多一个短命找活 agent 的固定开销——被接受为保费。若找活 agent 也连续多轮报零候选,说明问题不在「找」而在目标本身接近饱和,编排者应向用户回报目标饱和,而不是继续空转找活。
- 模板逐字复制总则(ADR-0004)不变:第 5 步随块复制,重建定时任务时自动带上。
