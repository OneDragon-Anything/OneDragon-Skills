# ADR-0006:schedule 提醒分两类——自执行 vs 派 agent(判据:内化判据 vs 需干净上下文)

- Status: accepted
- Date: 2026-08-25

## Context

用户点破:「哪些 schedule 是提醒你能做好的,哪些是提醒你也做不好、要派 agent 跟进的」。审视发现全部 5 个提醒都默认编排者自执行,漏了一类:提醒触达后**工作本身**需要干净上下文/长时间专注/偏见敏感裁决的——编排者带着主会话上下文自己做会污染(如审自己刚写的方法论、巡自己刚产出的判读)。

## Considered Options

- **全部自执行**:否决——偏见敏感的裁决(反馈队列通用性审查/实例层晋升扫描)由编排者做=自己审自己。
- **全走定时子 agent**:否决——违背「schedule 统一、并行度在编排者手里」的既定决策(定时 spawn 撞额度失控)。
- **提醒双类型(选中)**:提醒表加「类型」列;自执行类=触达后编排者几分钟内出动作;派 agent 类=提醒只做触发器,触达后编排者派干净上下文 worker 执行、只收裁决。判据:判据可内化+短时→自执行;需干净上下文/偏见敏感→派 agent。边缘(语料积累触发)并进四来源 D,不单独设提醒。

## Decision

§5 提醒网表加类型列+判据段;新增「深度巡检 ~2h/派 agent」角色(反馈队列逐条审+实例层→skill 晋升扫描)。

## Consequences

- 正:偏见敏感工作获得独立性(新鲜上下文);额度控制权留在编排者(触达后派,不是定时 spawn)。
- 负:深度巡检类角色的价值依赖巡检目标的持续存在(队列空/无晋升候选时轮空)——由「产出型盘点」的扫描痕迹条款兜底(轮空也要留「扫了什么」)。
