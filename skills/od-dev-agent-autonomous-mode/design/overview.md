# od-dev-agent-autonomous-mode · design overview

## 定位

用户授权 agent 长时间自主决策推进(不逐项确认,直到叫停)时的**开启与停止操作指令 + 运行期方法论库**:SKILL.md 只放操作(开启 checklist/停止 checklist/指令文件节模板),方法论按主题下沉 references/(开启第 0 步必读,运行中凭重读指针恢复)。跨领域通用(任何项目/玩法);领域操作细节归各领域 skill(如货币战争的 sr-od-currency-war-dev)。

## 内容成员判据(什么内容收进本 skill)

一条内容的存在,必须是因为**「用户不在场」或「长时间运行」**——自主推进区别于普通开发的只有这两点。通不过这条判据的,归各自正确的层:

- 通用工程纪律(验证分层/文档同步/资产维护)→ 项目 AGENTS.md 或对应 skill;
- 项目纪律(具体到某项目的规矩)→ 该项目的入口文件;
- 领域运行属性(早停判据的形态/盘点来源清单/提醒网间隔)→ 领域 skill;
- 委派手艺(派单/验收/监控)→ 目前留在本 skill(自主推进是当前唯一高频派单场景);出现第二个高频场景时分家。

历史教训:本 skill 曾按「实战有效就收」生长,积压了大量前三类内容(资产组/点名册/收账依据/分层验证/分层落位/维护回路/运行期早停节),于 2026-08-27 大重整中逐条清除——后续维护者遇到「这条好像有用想加进来」时,先过上面的判据。

## 结构

| 文件 | 内容 |
|---|---|
| SKILL.md | 开启 checklist 5 步(第 0 步读方法论→第 1 步加载领域 skill 全貌→第 2 步建自主推进纪律[指令文件节+定时任务,按领域说明]→第 3 步对齐进度[冷启动则建迭代入口]→第 4 步第一波派发)+ 停止 checklist 5 步 + 指令文件节模板(六字段+自主推进纪律规则)+ 通用写全领域叠加 + 重读指针 |
| references/orchestration.md | 编排者手册(叙事序):①身份与责任(两档/派还是不派)②派发节奏(进度文件=唯一队列源/事件驱动/完成即取下一件/盘点交结果+多来源)③委派三拍(派出时=三带/等待时=活性监控+干预+防退化/回答后=验收五面+对抗+治本) |
| references/reminder-net.md | 提醒网:四角色表(值守兜底 10min/派发盘点 15min/回顾 20min/子 agent 审计 45min)+提示词模板、提醒词写法(用户可见面)、自执行 vs 派 agent、双保险设计、长任务自校准;领域有特有监控对象时按需增补角色 |

## 核心设计

- **结构性约束 > 自觉**:凡靠「记得」「自省」维持的纪律都会在长会话注意力衰减中失效,必须变成机制(清单/锁/提醒角色/代码化检查);
- **事件驱动**:子 agent 交付/后台任务退出/用户消息=推送唤醒;提醒网管「没人戳你时别忘了看什么」;不用定时轮驱动推进;
- **再注入通道**:运行期纪律不靠「skill 读过就一直在场」(上下文压缩后会丢)——靠指令文件里的自主推进纪律(冲动时刻)/提醒词(周期时刻)/重读指针(按需恢复)。

## 边界

- 不管领域操作(怎么建档/写 op/判读——归领域 skill);
- 不管单人单任务(无多轮自主推进的走普通流程);
- 不管进度树内部结构(归 od-dev-progress-tracking,本 skill 只消费);
- 不绑具体提醒工具(定时任务/定时器/任何会话级提醒机制,按环境取用)。
