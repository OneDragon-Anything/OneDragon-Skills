# 0003 降级双条件(证据结论 + 用户点头);禁绕过清单为纠正型主体

- **状态**:accepted
- **日期**:2026-08-20

## Context

同一天三次错误处理同一停机钩子(见 [ADR-0001](0001-standalone-skill-for-stop-hook-lifecycle.md)):①视觉模型一问一答被当证据,按误读(把占槽物品归因旁边 UI)加了错误守卫;②钩子被降级成留证带病跑;③降阈值宽匹配把未知物硬配成「大概是典籍」。共性 = **进度压力下的绕过变形**,表面各异、根因同一。同项目另有一次**降级做对了**的对照:某读数回退停机钩子三度触发阻断实跑 → 排查者拿 274 张存证离线重放,定位根因(合成动画窗内同图重读,非识别失败)→ 加防抖修复误报源 → 带着结论降级为留证。两次降级差异不在动作,在**有没有证据结论、经没经用户决定**。

## Decision Drivers

1. form-to-failure:三误是「压力下明知故犯」型失败(知道钩子该停机,仍找理由绕过)→ 禁令 + 合理化反驳 + red flags 才有效,软建议会被「先跑起来要紧」谈判掉。
2. 合理降级真实存在(读数回退案例),全禁会把「三度阻断实跑」的钩子变成永远阻断——规则要能区分两种降级,不能一刀切。
3. 「降级是用户决定,不是 agent 逃生口」——用户是项目 owner,实机证据的取舍权在其手。

## Considered Options

- **软建议「prefer 停机,别急着降级」**(否决:纠正型失败对软建议免疫,三误者每次都觉得自己是例外)。
- **全禁降级**(否决:误报源已修复的钩子继续停机 = 反复阻断实跑,伤害真实;读数回退案例证明合理降级有价值)。
- **降级双条件 + 禁绕过清单**(采纳):降级提案必须携带证据结论(触发分析 / 离线重放定位根因且误报源已修复)+ 用户点头,agent 只能提案;反向升级(留证→停机)同理。绕过变形逐条列为禁令并配 red flags 原话。

## Decision

落进 SKILL.md §1.2(禁绕过清单:自行降级 / 降阈值硬配 / 单源归因 / 删钩删 flag 续跑,各配「为什么是绕过」)+ §2.3(降级治理双条件)。三误与读数回退案例作为论据留本 ADR,不进 SKILL.md(公共 skill 泛化,规范 4)。
