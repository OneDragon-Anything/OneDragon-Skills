# 单个 Operation 的测试(reference)

> 本 skill(`od-dev-write-operation`)的 situational reference。**何时测**(SKILL.md 主线⑥三层:mock 快测抓结构逻辑 → 实机验证识别/时序 → 回归测试锁行为)+ **TDD vs 刻画策略**(本文件后半)+ 玩法级测试编排(`od-dev-gameplay-automation`)分层各管一段;本文件主体给 op 级测试**机制**(怎么单跑 / 怎么 mock / 怎么断言)。

## 1. 实机单跑(最快定位)

写完一个 op,先用 MCP 后台单跑它,确认这一步行为对,再接入主流程:

```
run_operation(op_id='<module>.<ClassName>', args={...}, block=false)
```
- `op_id` = `<dotted module path>.<ClassName>`(可从 `list_operations` 取)。
- `block=false` 立即返回,`get_run_status` 查进度(实现-测试流水线:后台跑前一个 op,等待时写下个)。
- 单跑道:同时只能一个 op 在跑,别并发。

## 2. 单元测试:mock 截图 + 断言

op 的单元测试在测试仓(独立测试仓库,放消费方仓库根目录)。**看现有 op 测试抄测试骨架**,别从零搭。核心模式:

- **注入 mock 截图**:op 每轮 `self.screenshot()` 实际由测试喂 fixture 图(项目用 mock 截图注入 helper,如 `add_mock_screenshot`,喂**序列**fixture 模拟跨多屏推进)。跨多屏的流程 op 喂序列;单画面 op 喂一张。
- **断言客观输出**:节点流转(走到哪个节点)、OCR 结果、检测函数返回值、决策函数选了哪个。**别断言不可观测的运行时副作用**(click 是否真落地 / 时序)。
- **写断言前先读 node 返回类型**(踩坑固化):`round_success` / `round_by_find_area` 命中判 `is_success`;`round_wait` / `round_retry` 判 `status`(匹配词)—— 先读被测 node 代码确认返回类型再写断言,别照搬别的 app 的测试(不同 op 主态可能返回不同 `OperationRoundResult` 类型,照搬 = 断言键名错、恒红或恒绿)。

## 3. TDD vs 刻画测试(分情况)

- **新写纯逻辑**(reader / OCR 解析 / 决策函数):**先写 fixture 测试断言期望输出,再实现**(TDD)。改前跑、改后跑,锁回归。
- **改存量 op**:先补**刻画测试**(用真实截图 fixture 锁当前行为)→ 改 → 重跑 → 无回归才提交。
- **每个画面状态 1-2 张典型 fixture**:别凭一两种状态写整个流程;漏状态 = 回归。改 reader / 解析前把所有相关状态 fixture 跑一遍。

## 4. TDD 锁得住什么、锁不住什么(关键)

- **锁得住**:**纯逻辑回归** —— 给定截图,检测对不对 / 该点哪 / 纯函数算对不对。
- **锁不住**:**运行时 bug** —— click 时序被判拖拽(项目相关,见 framework-pitfalls)、MCP 异步、真机 OCR 抖动。
- → **绿测试 ≠ 实机能跑**。单元测试过之后,仍要实机 `run_operation` 验(看 → 动 → 等 → 验)。别拿绿测试当"实机通了"的证据。

## 5. 测试红的归因:先验「测的是不是同一棵树」

- **并行批在飞编辑期间跑出的红,先验树稳定性再归因** —— 伪红特征签名:红集合逐轮漂移 / 读源码文本的锁成批红 / 单跑绿、全量红且复跑消失。命中 → 推迟到编辑批结束的稳定窗口复测,**禁在移动树上修测试或补桩**(伪红误当真红修 = 在移动树上做无效功 + 污染)。
- 需要在编辑窗口内拿测试结论时,用**冻结工作树**隔离测量(如 `git worktree` 挂到 commit 快照):主工作区保持零触碰;跑前比对两侧环境指纹(随机种子 / 数据快照版本),不一致=作废;工作树内含与被测改动无关的必要修复,显式声明内容与边界。

## 6. 实机验证时

- 决策点开**临时日志 + debug 截图**(OCR 摘要 / 点击坐标 / 分支结果),一次实跑就能复盘每个决策点发生了什么(信息密度论,详 `runtime-craft.md`)。验证通过后逐步去掉(减运行时开销)。
- 失败先读 MCP server 日志(项目 `.debug/` 下;实际 OCR / 节点流转 / 决策状态),别盲改。
