# 探索文档模板(operation-explore 三份设计稿)

> 落点 `.debug/temp/operation-explore/<yyyy-MM-dd-<简述>>/`(gitignore 临时区,寿命 = op 开发期)。SKILL.md 主线①②③各产出一份,④设计确认后才算定稿。写作纪律:**正文只写当前认知的事实**——摸的过程推翻了需求假设,直接改正文,不写「假设 vs 修正」的过程叙事。

## 1. requirement.md(需求,①产出)

要素 + 来源指针:

- **目标**:一句话,合格判据 = 动词 + 对象 + 结果形态(读数类 = 读到什么;操作类 = 做完后状态变成什么);
- **起点 / 结束**:画面名,或「任意起点」;从前置来源收拢,不许上游戏瞎摸代替问;
- **中间大致操作**:粗粒度动词级(A → B → C);
- **红线**(有则):零消耗 / 永不代点某控件 / 不碰不可逆操作;
- **放置位置**:判定依据一句话 + 目标路径(跨 app 复用 → 项目顶层 operations 包;单玩法域 → 该域 application 包);
- **来源**:一句指针(用户任务原话 / 玩法文档路径 / app 编排上下文)。

完成判据:粗流程线画得出来(起点 —大致操作→…→ 结束)。

## 2. screen-flow.md(画面流转,②产出,按走查实况记录)

四节:

- **主干**:逐跳的流转线——`<画面A> --[点 <区域>]--> <画面B>`;停留本屏的动作写 `[读 <区域>,不流转]`;**每段末尾带现成 op 复用标注**(来自②2.1 查地图):`[复用: <op 名> 覆盖到哪 / 缺什么]` 或 `[复用: 无现成]`;
- **变体 / 子态**:每画面不同形态下各读什么、差异是什么(来自②的变体枚举);
- **入口假设**:起点集合 + 终点(实机核对后修正 requirement 的对应项);
- **未知项**:没见过 / 没验证的形态,一句一项——⑥实测逐项盯防的清单。

事实与设计分离:画面事实(area / goto 边 / 子态形态)**即时进 screen_info 与画面 doc**,本文件只记流程编排,不做建档的第二份记录。

## 3. nodes.md(节点拆分,③产出)

- **节点总览**:流转图,`<开始节点> → <节点B> —(status: X)→ <节点C>`,意外兜底路径标出;
- **节点卡**:每节点一张,格式与分支链字段见 SKILL.md ③「节点卡格式」(格式单一源在 SKILL.md,此处不重复展开)。

## 4. 生命周期

- 创建时机:①需求确认要新建 op 后,建目录 + 写 requirement.md;②③随主线长出对应文档;
- ④设计确认是唯一的人类裁决点(汇报四件套见 SKILL.md ④);
- 收尾:⑥交付后,有价值的画面样本进正式归档,其余清理——设计稿的持久镜像是代码里的 docstring 契约与 `@node_from` 节点图,修改 op 时若稿已删,从代码反推现状(SKILL.md「修改与调试」B 路径)。
