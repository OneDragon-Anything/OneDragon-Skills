# 0007. op 进出状态核对:op 边界契约(入口识别 + 出口验证转移,出口不可推卸)

- **Status**: accepted
- **Date**: 2026-08-05

## Context

反馈指出 op 没系统教"开始和结束要做什么":入口不识别预期屏就盲点、出口转场 click 后不验证就 `round_success`(点了 ≠ 进了)。曾一度被判"已被看动等验 / 节点图覆盖"而删,复核后确认是**真 gap** —— 粒度不同(看动等验是 per-node 节奏,本条是 op 边界契约)。

## Decision

补「op 进出状态核对」方法论(写进 `SKILL.md`):

- **入口**:op / 节点开始先识别预期屏(id_mark / 独有关键词),不在 → `round_fail` / bail,别错屏盲点。(首动作 `round_by_find_and_click_area` 先找再点 = 天然识别,例外。)
- **出口**:转场 click 后必须验证"状态真转移了"才 `round_success` —— 用**任一可靠转移信号**(目标屏 id_mark 命中 / 本屏 id_mark 消失 / 刚点元素消失 / 锚变化);信号没出现 = 没转移 → `round_retry` / `round_wait` 自己 retry 到转移;出现 = 真转移 → success。
- **判据**:op 进 = 确认在预期屏;op 出 = 确认真转移了。"做了动作" ≠ "达成结果"。

**出口验证为默认 / 不可推卸**(关键决策,见下)。

## Decision Drivers(为何出口验证默认开 + 不可推卸)

- **下游无法替你兜底**:op `round_success` 后交出控制权,若没完成(转场没落地),下个 op 的入口验证**只能发现"画面不对",没法替你重做这次转场**(不是它的职责、也不知点哪)→ 流程卡错屏。故"验转移 + 自己 retry 到转移"是 op 不可推卸的职责,不能指望下游。
- **检测可靠**:屏转移有稳定信号(id_mark 命中 / 消失、刚点元素消失、锚变化),比选中态(难认、强验添乱,见 [ADR-0006](0006-selection-screen-methodology.md))可靠得多 → 默认开**不属过度验证**。子态无 id_mark 时用元素消失等信号,别只认 id_mark(见 od-dev-screen-onboarding §3.5)。
- **失败代价大**:没验证就 success = 对下游撒谎 → 错屏卡死,代价远大于多一次截图 + OCR。

## Considered Options

### A. 补 op 边界契约,出口默认验证(本决策)
- ✅ 堵住"点了 ≠ 进了"的撒谎;出口不可推卸(下游兜不了)。
- ✅ 检测可靠(id_mark),非过度验证。

### B. 不补(判"已被看动等验 / 节点图覆盖")
- 否决:① 看动等验是 **per-node 节奏**(节点内部 看→动→等→验),不是 **op 边界**契约 —— 粒度不同;② 节点图下游重读是**被动发现**(查出不对但替你重做不了),非恢复 —— 出口撒的谎下游兜不住。

### C. 出口验证按需(只在观察到"success 了但没转移"时加)
- 否决:下游兜不了 → 错屏卡死代价大;检测可靠 → 没理由默认放。按需等于默认欠妥。

## Consequences

- **正向**:op 不再"做了动作就 success";转场必自验转移,堵住错屏卡死。
- **代价**:每个转场多一次截图 + OCR(默认守;代价远小于卡死)。
- **推翻它会碎什么**:退回 B → op 继续撒谎、下游兜不住、错屏卡死;退回 C → 同。
