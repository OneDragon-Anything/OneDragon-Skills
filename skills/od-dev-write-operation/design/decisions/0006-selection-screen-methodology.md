# 0006. 选择类画面方法论:建档三件 + op「默认选择→推进,不多选重试不检测选中态」

- **Status**: accepted
- **Date**: 2026-08-05

## Context

选择类画面(从 N 个选项单选 / 多选)的「选中态识别 + 推进按钮 + 点击位置」此前在 skill 里没系统化(反馈踩坑:op 点选项后 OCR 没变误判「没选中」、点到选项上别的子区域误判选中)。补方法论时有两个决策都带实质备选,记此 ADR。

## Decision 1:落点 = screen-onboarding(建档)+ write-operation(op);不含 ui-region-detect

- **screen-onboarding §3.6**:选择类画面建档三件 —— ① 选中态呈现多样,**别预设单一**(OCR 文字 / 视觉高亮 / 勾选 / 推进按钮灰→实 / 角标,OCR + 视觉大模型 + click 验都试);② 推进按钮(未必叫「确认」)记灰 / 实两态;③ 点哪选中,避开选项上触发别交互的子区域(图标开详情 / 按钮刷新 / 预览图开大图)。
- **write-operation**:选择类 op 的「选择→推进」+ 何时检测选中态(见 Decision 2)。
- **备选(否决)**:反馈原提「或 od-dev-ui-region-detect 加选中标记检测」。否决:ui-region-detect 的核心是 UI 区域**坐标**检测(槽位网格 / 图标阵列);选中态是**状态**检测,不是坐标 —— 范围错位。且状态指示图标(选中 / 未选中)的模板建模 screen-onboarding §5 已有(每态一模板),不重复造。

## Decision 2:op「默认选择→推进,不检测选中态」;只有多选重试要取消重选时才检测

- 选择类 op 正常流程 = 点选项 → 点推进按钮,**不必检测选中态**。只有**多选 + 某次 click 没落地(没选中)→ 选不够 / 没法推进 → 流程重试 → 要先取消原选择再重选**时,才需识别当前选中态。
- **备选(否决)**:反馈原拟「op 点选择类要『点→验选中→确认』三步」(默认每次点后都验选中态)。否决理由:① 选中态往往没明显标记、不好认,**强验反而容易判错添乱**(把没选中判成选中 / 反之);② 多数单选 / 顺利场景选择→推进就够,默认验是过度工程;③ 真正需要识别选中态的场景很窄(多选重试取消重选),按需引入即可。
- **与「op 转场状态自检」的区别(防误读为矛盾)**:本决策「不检测选中态」**只针对选中态**(难认,按需例外);**不否定**一般的「转场点击后自检状态真的转移」(那是验**屏**转移,不是验选中态,是另一回事)。两者不冲突。

## Consequences

- **正向**:选择类画面建档 + op 处理有了系统方法论;op 不过度检测选中态(避免判错添乱),只在真需要时(多选重试取消重选)才引入。
- **代价**:选中态识别方法在 screen-onboarding §3.6(不在 write-operation 本身),write-operation 引用它。
- **推翻它会碎什么**:若退回「默认点→验选中→确认」(Decision 2 备选),重新把难认的选中态检测铺到每个选择 op → 判错添乱;若把选中态检测塞进 ui-region-detect(Decision 1 备选),范围错位 + 与 §5 重复。
