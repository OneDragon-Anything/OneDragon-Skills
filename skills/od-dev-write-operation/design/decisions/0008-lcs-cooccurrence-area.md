# 0008. 多屏共现关键词必用 area —— 揭露 `lcs` 收紧对全等子序列无效(0004 follow-up)

- **Status**: accepted
- **Date**: 2026-08-06

## Context

[0004](0004-region-detection-default.md) 立「**固定位置 → area(压倒性默认),全屏 OCR = rare last-resort**」为选型判据,并把 LCS 子序列误匹配机制写进 SKILL.md 警告框 + `round-by-helpers.md`。但 0004 落地后,实战**又复发 2 次**同模式 LCS 误匹配(算上 0004 引证的 1 次,共 3 次):

1. **短关键词共享 2 字子序列**(0004 引证 / 首次):4 字关键词与邻屏相似标签共享 2 字 → 2/4=0.5 命中默认阈值 → flat loop 卡死。
2. **不同屏共享 2 字子序列**(复发 2):4 字关键词与**另一屏**的文字共享 2 字 → 0.5 命中 → 该屏被误吞、handler 在错误画面瞎点 → loop 卡死。止血靠 `lcs` 收紧到 0.8(低重叠,有效);备选 area 化根治留待建档。
3. **不同屏全等子序列**(复发 3,关键):4 字关键词同时是**目标屏标题**与**失败结算屏的对局信息**(4 字全等)。作者在复发 2 后已把 `lcs` 提到 0.8,但**全等子序列 LCS=1.0** → 阈值提多高都误匹配 → handler 误派、点错处 → loop 卡死(iter 340+)。最终改 id_mark area(位置区分)根治:失败结算屏的同名文字在对局信息区(不同 `pc_rect`),不在目标屏 id_mark area → 不命中。

(具体玩法 / 关键词 / 决策见该玩法的决策日志;本 ADR 不引跨仓 / 本地路径,只抽方法论。)

两次复发暴露 [0004](0004-region-detection-default.md) 的两点不足:

- **(a)「位置固定吗」判据没在作者写 op 时触发自查。** 作者写 `round_by_ocr(keyword)` 时想的是「我要找这文字」,习惯性选全屏 OCR,没退一步问「这文字在画面上位置固定吗」。需要一个**更前置、更直接**的误匹配预测信号触发自查。
- **(b) 「全屏 fallback 必带 `lcs` 0.7~0.9」给人「`lcs` 能止血」的印象,但没说清局限。** 复发 2(`lcs` 止血成功)后易形成「提 `lcs` 就行」的习惯;复发 3 全等子序列打脸 —— **`lcs` 收紧只杀低重叠假匹配,对全等 / 高重叠子序列无效**。这个局限不说清,作者会重复踩全等坑。

## Decision Drivers

- **复发即判据力度不足**:同一误匹配模式 3 次复发 = 现有判据没在写 op 时触发 → 需补更易触发的自查信号,而非再加一遍「固定位置 → area」。
- **`lcs` 局限必须显式**:「`lcs` 能止血」的半真相比「全屏危险」更有害 —— 作者以为提了 `lcs` 就安全,反而在全等场景失效。揭露局限才能让作者在全等可能时直接 area。
- **泛化**:「关键词共现性」(别的屏 / 同屏别处有没有)+ 「全等子序列 `lcs` 档不住」是框架 LCS 机制 + op 设计的通用规律,不绑具体玩法 / 关键词。

## Considered Options

1. **只补 `round-by-helpers.md` reference,不改 SKILL.md 正文**:pro 是保持 SKILL.md compact;con 是 LCS 误匹配高频复发,主判据必须落在会被注入执行上下文的 compact 正文,埋进 reference 等于 lost-in-the-middle,作者读 SKILL.md 时看不到 → 复发继续。**否**。
2. **把具体案例(玩法 / 关键词)写进 SKILL.md 警告框**:pro 是具体例子最易记住;con 是违反 od-dev-writing-skills 规范 4(skill 正文 + 智能体读的辅助文件不写具体项目例子,会以偏概全)。案例作论据归本 ADR(design/ 允许具体例子)。**否**。
3. **激进:SKILL.md 声明「全屏 `round_by_ocr` 默认禁用,需显式 opt-in / 注释理由」**:pro 是强制纠偏;con 是过激 —— 位置真运行时漂移 / 动态弹出的场景(随机提示等)确需全屏 OCR + 高 `lcs`(见 [0004](0004-region-detection-default.md) option 3),一刀切禁用剥夺合法 fallback。**否**。
4. **补强判据进 SKILL.md 正文(compact)+ `round-by-helpers.md`(详细)+ 案例进本 ADR**(选中):正文加「写前自查共现 → 是则 area」+「`lcs` 救不了全等」+ 短词量化;reference 展开两个独立高危信号 + `lcs` 局限;ADR 记复发论据。

## Decision

选 **4**。在 [0004](0004-region-detection-default.md)「固定位置 → area」之上,补两条:

- **「多屏共现」是独立高危信号 + 比「位置固定吗」更前置的误匹配预测自查**:写 `round_by_ocr(keyword)` 前先问「这词在别的屏 / 同屏别处也会出现吗(子序列 / 全等)?」是 → 必用 area 位置区分(id_mark area 的 `pc_rect` 把目标屏关键词与别屏同名文字隔开)。理由:全屏 OCR 无法区分同名文字属于哪个屏,只有 area 的位置约束能区分。
- **显式揭露 `lcs_percent` 收紧的局限**:只杀低重叠假匹配(2/4=0.5 这类);对全等 / 高重叠子序列(4/4=1.0)无效,阈值提多高都误匹配。故「关键词可能在别屏全等出现」→ 只有 area 根治,`lcs` 档不住;「全屏 fallback 必带高 `lcs`」加前提「先确认该词不在别屏全等 / 高重叠出现」。
- **短词量化**:`lcs` 机制说明补「≤4 字关键词天然高危」(共享 2 字即触默认 0.5 阈值)。

SKILL.md 警告框 + 自检清单各补一条;`round-by-helpers.md`「LCS 匹配机制」段展开「两个独立高危信号」+「`lcs` 局限」+ 自查。

## Consequences

- **正向**:作者写全屏 OCR 前有更直接的自查信号(共现),且不会再误以为「提 `lcs` 就全安全」;全等 / 高重叠场景直接走 area。
- **负向**:SKILL.md 警告框略变长(token 微增);自检清单多一条。
- **follow-up**:GREEN 验证 —— 写 op 时是否对「可能在别屏出现的关键词」默认走 area、不再依赖 `lcs` 止血;是否仍有「明知 area 更好但偷懒用 `lcs`」的复发。
