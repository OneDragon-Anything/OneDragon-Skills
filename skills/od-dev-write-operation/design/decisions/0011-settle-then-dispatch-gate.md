# 0011 settle-then-dispatch(画面定型门):等画面定型归 op 代码

- **状态**:accepted
- **日期**:2026-08-20

## Context

某自走棋对局玩法(肉鸽)的战斗循环在场景切换过渡帧(结算→备战:主体先渲染、节点类型 overlay 后弹)分发行动,两类实锤失败:①半开帧误点(结算推进按钮的点击落进刚渲染的备战主体);②停机钩子在 overlay 帧误采(「备战槽占用认不出」= 占用标记 overlay 还没弹)。此前同类修法全是点状且互不知同根:结算推进 wait 2→3s、同帧标题词门(后被证不可达删)、角色特效探针。用户点破机制(渲染主体先出、overlay 后弹)并定调修法(连续多秒子态稳定再分发);随后补充根因层:**agent 可观测性约束**——人类能看着画面数出「约几秒弹 overlay」,agent 经工具往返慢、只有离散快照,不知道下一画面何时出现;且 op 入口 / 出口同样需要「等预期画面定型才开始 / 才算成,等不到就异常退出」。

## Decision Drivers

1. **可观测性不对称是根因**:等待必须编码进 op(op 循环每迭代采样 = 代码在"看画面");agent 侧 sleep 是猜时长,时序一变就碎。三个点状修全是 agent 侧猜时长的变形。
2. **半开帧同时骗过两层**:识别层(锚点从将弹 overlay 下透出 → 识别对了但状态没定型)与出口验证层(转移信号出现过 ≠ 定型)——单修任一层不够。
3. **等不到必须有界退出**:无限 `round_wait` 不计 retry(既有 ADR-0009 同机制坑),兜底纪律同构(「点了≠成了」三层完成验证)。
4. 与坑 8(瞬态残影)机制相反(旧世界残留 vs 新世界未弹完),必须显式分流防混修。
5. 公共 skill 泛化:稳定窗数值 / 实现细节归项目;skill 只写原则与判据。

## Considered Options

- **扩坑 8(瞬态残影)覆盖本场景**(否决:机制相反——坑 8 是读到的还是旧世界、修 fresh 重读;本门是新世界没弹完、修定型等待;混写会引导混修)。
- **放 framework-pitfalls 坑清单**(否决:坑清单收「框架行为反复发作」,本条是游戏 UI 时序模式 + op 设计手法,归 runtime-craft 运行时工艺单源)。
- **只写分发层稳定门,op 入口 / 出口不动**(否决:入口识别只查一次 / 出口验「信号出现过」都会被半开帧假阳满足——两个消费面共享同一「等定型」语义,拆开写就是同一坑两处各猜)。
- **只给判据不给实现原则**(否决:连续性追踪[首命中时间戳 + 上轮分支标志]、分支切换重计时、链式 overlay 逐个消化是实现核心,不写 agent 会退化成点状 sleep)。
- **runtime-craft 新节含根因 + 两消费面 + 分流 + 分工 + 升格纪律**(采纳)。

## Decision

按采纳方案落地。节名带根因(「等画面定型归 op 代码,不归 agent」)防读者只记手法忘根因;与坑 8 互指分流;与坑 2 sleep / round_wait / ADR-0007 出口验证划正交分工;升格纪律(点状修 ≥2 次升格)与「手动操作 2 次建 op」同构。联动:gameplay-automation runtime-iteration 过渡帧家族句补指针;loop-driven-op-structure flat loop 描述补「分发层」指针。SKILL.md 必守不变量不另加条(该节属 situational,SKILL.md 已有指针层覆盖)。
