# 选择类画面 op:选择 → 推进;多选重试才需识别选中态

> 本 skill(`od-dev-write-operation`)的最佳实践。SKILL.md「最佳实践」索引表给触发特征;本文件给完整做法。

**适用**:画面由「选项(单选 / 多选)+ 推进按钮」构成——配队选择 / 难度选择 / 奖励三选一 / 开局祝福挑选等。

## 1. 默认:选择 → 推进,不检测选中态

点选项 → 点推进按钮往前走即可(推进按钮未必叫「确认」)。选中态往往没明显标记、不好认,硬验反而容易判错添乱。

**要校准的是"点哪儿能选中"** —— 选项上可能挂着图标、按钮、预览图等子区域,点选项主体 = 选中,但点到子区域可能开详情 / 触发刷新而跑偏。实测定准选中位置的坐标,存进 screen_info area(交互类 area 必须 click 实锤,方法见 `od-dev-screen-onboarding`)。

## 2. 多选 + 点击没落地 → 重试时才识别选中态

多选时 click 没落地 → 选不够 / 没法推进 → 流程重试。这时大概率要**先取消原选择再重选**(避免叠加 / 错位),取消前得**识别当前哪些已选中**——选中态呈现多样(边框 / 勾选 / 高亮),别预设形态,方法见 `od-dev-screen-onboarding`。

## 3. 判据一句话

默认「选择 → 推进」,别过度检测;只有**多选 + 重试要"取消重选"**时,才需识别选中态。写节点卡时按此归位:识别选中态是重试分支内的事,不是主干分支。
