# 0011. 依赖顺序(§1.4)≠ 召回(§1.6):决策点前置归正文结构,召回原则保持窄

- **Status**: accepted
- **Date**: 2026-08-11

## Context

skill 反馈(writing-craft §1.4 / §1.6):多形态 skill(`fairy-data-report-builder` 三形态:动态应用 / 静态快照 / 报告文件)把形态选择放第 6 步交付 → agent 已按错形态走了 3-5 步才发现该选什么(前几步白走 / under-trigger 别的形态 / 形态分支打断主线)。

最初拟改:§1.6「头尾放不变量」扩展,把「决策点(形态选择)前置」塞进 §1.6(冠召回原则之名)。review 子 agent 挑出**原则套错**:

- **§1.6 lost-in-the-middle** 讲**召回**:长上下文中段回忆弱 → 关键信息放头尾(primacy / recency)。解决「记住」问题。
- **形态选择前置**是**依赖顺序**:决策必须先于依赖它的步骤(形态选择先于形态流程)。解决「顺序」问题 —— 即使文档只有 6 步(不算长上下文),形态选择放依赖步骤后也是错的。

两者不同原则,处方不同:
- primacy 处方 = 形态选择永远放开头(第 1 步)。
- 依赖顺序处方 = 形态选择放分支前(第 5 步即可,只要分支是第 6 步)。

塞 §1.6 = 把 just-in-time(依赖顺序)当 primacy(召回)讲 → 读的人拿到互相打架的指导。

## Decision Drivers

- **原则不混**:召回(§1.6)和依赖顺序(§1.4 正文结构)是不同原则,各管各的。
- **形态选择 bug 根治**:归 §1.4(正文结构,决策放依赖步骤前),通用(不只多形态 skill,任何「决策先于依赖内容」都守)。
- **§1.6 保持窄**:召回原则单一职责,不掺依赖顺序。

## Considered Options

1. **§1.6 扩展(塞决策点 + 执行顺序)**:原则套错(召回 ≠ 依赖顺序),产出互相打架指导;「流程前的门」违反 §1.9 造词;「执行顺序概要」重复规范 2(否)。
2. **§1.4 加决策点前置 + §1.6 保持窄 + 划界限(选中)**:各原则归位,形态选择 bug 根治,§1.6 单一职责。
3. **§1.4 或 §3 新立小节专讲两原则对比**:最干净但工作量较大(本 ADR 选 2 够,必要时再升 3)。

## Decision

选 2。

- **§1.4(正文结构)加段**:决策点(何时用 / 不用、多形态形态选择、前置条件)放依赖它的步骤之前(依赖顺序),别埋子流程末尾;+ 自检问句(多形态 skill:形态选择放依赖步骤前了没)。点明和 §1.6 召回不同原则。
- **§1.6 保持原样 + 加界限行**:讲召回(长上下文放头尾能记住);依赖顺序见 §1.4,别混。
- 不塞形态选择进 §1.6(那是召回节,形态选择是依赖顺序,留着只会让下一个人也混)。

## Consequences

- **正向**:两原则各归位(召回 §1.6 / 依赖顺序 §1.4),不混;形态选择 bug 在 §1.4 根治(通用);§1.6 单一职责。
- **负向**:写多形态 skill 的人要读 §1.4(不进 4 硬规范 checklist —— 多形态才遇,不是每个 skill)。
- **边界**:依赖顺序(决策先于依赖步骤,§1.4)vs 召回(关键放头尾,§1.6)vs 规范 2(流程类 must-do checklist,执行顺序概要)—— 三者不同,§1.4 / §1.6 / 规范 2 各管一段。
