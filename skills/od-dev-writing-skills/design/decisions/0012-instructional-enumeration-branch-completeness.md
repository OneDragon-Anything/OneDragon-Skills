# 0012. 指令性枚举分支完备(规范 2 新增条)

- **Status**: accepted
- **Date**: 2026-08-27

## Context

用户与迭代方共创会话中发现实例:`od-dev-agent-autonomous-mode` 开启 checklist 第 2 步「对齐三源」消费外部状态「进度树」,但只写了进度树**存在**时的处理;**不存在**时该干什么没写——严格照文义执行的智能体在分支点只能自由发挥(推断弱会卡住或乱建)。单点已当场修(SKILL.md 第 2 步 + §1 补「进度树不存在 = 新迭代冷启动,直接走第 3 步建」)。

归纳出三种病型:①步骤消费的外部状态有 N 种合法取值只写 N−1;②路由/分诊表缺「未命中」去向(另一实例:`sr-od-currency-war-dev` 入口分诊表);③检查项缺「不过」出口。

理论根基已有:writing-craft §1.5 form-to-failure 表「行为该随条件变 → 条件式(挂可观测谓词)」,错误形态 =「无条件规则」。但 ADR-0010 定的 checklist 形态规范没接上这一行,且存在表面张力:「主流程只放可勾动作 + 一行判据」可能被读成「分支处理 = 细节,该留后文」——以该理由删分支即病型①。

## Decision Drivers

- **失败真实且会复发**:凡步骤读外部状态(读文件/查状态/查窗口)的 checklist 都可能犯,这类步骤在流程 skill 里常见。
- **可机械自检**:「这步消费的状态有几种合法取值,文本覆盖了几种」——能变成固定自检问句的才配进硬规范,靠「写全面点」的软建议防不住。
- **防膨胀**:只管合法取值枚举,不穷举一切意外(意外归异常处理条款)。

## Considered Options

1. **只放 writing-craft guidance**(否):guidance 自声明非硬性,自检门不强制,防漏力度不足——与 ADR-0010 选项 2 同判。
2. **进规范 2 作指令式子条**(选):与 checklist 条、列表排版条同位,逻辑归属正确(指令形态的结构化要求);条件性清楚标注(只指令性枚举强制,参考性列表豁免)。
3. **扩 ADR-0010 原文**(否):ADR immutable 只 supersede;且本条适用面超出 checklist(路由表/检查清单),是并列新条不是对 checklist 条的修订。

## Decision

选 2。规范 2 新增 bullet:指令性枚举(流程步骤/路由分诊表/检查清单)分支完备——状态取值写全 / 未命中去向 / 不过出口;参考性列表(知识查阅,不匹配无害)豁免。细则(三病型 + 机械自检问句 + 「合法取值 vs 意外」边界 + 豁免判据 + 与「主流程只放可勾动作」的边界澄清:分支路由是动作的一部分)进 writing-craft §1.11。

## Consequences

- **正向**:指令性列表的未枚举分支从「靠智能体推断」变成「自检可抓」;澄清与 ADR-0010 的边界,防止以「主流程只放可勾动作」为由删分支。
- **负向**:写指令性列表多一道自检;「合法取值 vs 意外」的界需要判断(细则给了判据:枚举合法取值,意外归异常处理条款)。
- **后续**:存量 skill 的同类 gap 由各消费方自查;本条落地时顺手修了已知实例(sr-od-currency-war-dev 分诊表补「未命中」行)。
