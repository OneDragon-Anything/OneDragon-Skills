## 实测 1(2026-11-13,单轮子 agent 定性 · utility test)

- **任务**:干净子 agent,只给 skill 文件路径 + 用户需求原话「做一个委托派遣的 app:每周自动把四个委托位重新派满,领取已完成的委托奖励」。约束:只做到编排设计过目为止,不写代码不连实机;实机走查用纸面推演替代(逐条标注虚构);开放点列清单交用户裁定,不自行拍板。
- **考察点**:§1/§2 是否产出三份记录;轻重判据是否选对;四段式是否套用;失败处理是否显式;读数类需求是否走识别器通道(不造读数 op);开放点是否交用户。
- **结果**:主线全通——三份记录齐、轻重判据命中重档、四段式套用(自行裁定领奖与玩法交织归属)、失败语义显式成表、读数正确走 ScreenRecognizer extras、开放点清单交用户未自裁。
- **gap 回灌(已修复)**:①领奖与玩法同屏交织无归属规则 → §3.2 补处理规则;②失败处理无最小参考分类、且「失败 × 周期完成标记」联动易漏 → §3.3 表下补参考档位与联动提醒;③读数通道缺落地指针 → §3.1 补样板与建档分工;④设计过目触发条件未覆盖「失败处理非一律中止」→ §3.4 补;⑤§1 开放点裁定与 §3.4 设计过目两次交互重叠 → §3.4 允许合并一轮;⑥无实机无降级路径 → §2 补纸面推演标注约定。
- **测试期版本注记**:本轮实测跑在重构中间版上(§1 尚未拆两步);gap 修复落在最终版,复验见实测 2。

## 实测 2(2026-11-13,最终版复验 · utility test)

> 版本注记:本轮实测跑在当日中间版上(§3.2 编排设计章时代);下列回灌位置按当时节号记录,现行结构里对应——交织规则 → §2 四段式骨架下方 / 失败参考与联动 → §4.1/§4.2 / 读数指针 → §3.1 / 过目触发 → 已并入 §4.3 / 无实机指引 → §2。回查时以内容语义定位,勿按旧节号找。

- **任务**:同实测 1 场景(委托派遣 app),干净子 agent,约束改为「只到设计过目为止、无实机、一次性输出」。专验实测 1 回灌的三处修复:交织归属规则 / 失败处理参考分类 / 无实机指引。
- **结果**:三处修复全部验证有效——
  - 交织规则被评为「命中率最高的一条」,agent 照规则把领奖并入玩法段并标注归属裁定;
  - 失败参考分类三档直接套用,周期标记联动条款逼出关键裁定(「无可做 ≠ 失败」:预期内无事可做标完成、该做没做成不标);
  - 无实机条款三件套(推演 / 标注 / 并入验证)可执行,且 agent 按 §1 玩法调研查官方更新说明,**发现游戏 4.0 改版推翻了需求措辞的旧机制假设**(按周派遣 vs 按小时积累 30h 封顶)——需求理解拦截了一次真实跑偏。
- **gap 回灌(已修复)**:①交织例子隐含旧机制形态 → §3.2 补「归属随玩法机制形态走,改版后重新裁定」;②失败跳过与正常无活的 is_done 判例缺失 → §3.3 联动段补判例(标记相反);③§2 待实机核对清单在 §5 无核销条款 → §5 补第 5 条核销义务;④§2 无实机条款未回指 §1 调研义务 → 补回指;⑤app 级查重未明说 → §3.1 补「动手新建前先查重」。
- **结论**:§1-§3 两轮实测通过(需求理解 / 流程探索 / 编排设计段);后续段待首个真实 app 实装时走通后补验。

## 实测 3(2026-11-13,合并 gameplay-automation 后的最终结构 · utility test)

> 版本注记:本轮跑在合并后的结构上;下列回灌位置为现行节号(实测 3 修复落盘时的结构,后续如有再重编号,同实测 2 注记口径回查)。

- **任务**:干净子 agent,长流程场景「深渊爬塔 app(肉鸽爬塔,打不过就停,领沿途奖励)」,只读调研可用,产出止于 §4.3,§5/§6 给执行计划;开放点列清单不拍板。
- **结果**:主线全通——长短流程判断(命中长流程)、四段式套用、无实机推演逐条标注、四档复用判定 + 读数走识别器、失败语义成表、周期标记判例套用(逼出「战斗失败停是正常终态还是失败」的关键决策)、迭代轮次按推进单元划分、策略按「初版不做」占位;裁定点 Q1-Q11 全部列清单未自裁。
- **gap 回灌(已修复)**:①玩法调研无完成标准 + 歧义无去向 → §1 补「能回答类型/流转/决策点/奖励即够;仍有歧义列开放点问用户」;②无实机推演退出链无最小清单 → §2 补四项框架;③复用判据缺「同型样板」档 → §3.1 补;④周期标记缺终止型目标判例 → §4.2 补第三态;⑤§4.3 无最小骨架 → 内联迭代目录骨架;⑥「最接近起点」构造无指引 → §5.2 第 6 步补;⑦探索目录与迭代文档双写漂移 → §4.3 补「沉淀后单一源」;⑧测试触线「复杂」无判据 → §7 改「有条件分支或循环即补」;⑨§1「不分档」与 §2 分档措辞打架 → 改「需求理解对所有 app 是同样的完整步骤」;⑩导航精细档三处重复 → §5.3 改引用。
- **结论**:合并后主线(§1-§6)经三个场景(委托派遣×2 + 深渊爬塔)实测通过;§7-§9(端到端/GUI/MCP 配置工具)待首个真实 app 实装时补验。
