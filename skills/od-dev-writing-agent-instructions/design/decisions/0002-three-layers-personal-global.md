# 0002 · 分层从两层扩为三层:补「个人全局层」(用户主目录工具入口)

- **Status**: accepted
- **Date**: 2026-08-16

## Context
初版 §3 只有两层(项目共享 / 项目个人本地)。实际使用复盘(用户以其 harness 主目录全局 AGENTS.md 为例)暴露:存在第三层 —— 用户主目录下的**工具级全局入口**,跨项目、本机、不入库,注入所有 session。初版把它的典型内容(工具操作知识)误判为「操作手册塞错 always-on」,建议迁 skill/doc —— 该建议不成立。

## Decision Drivers
1. **可达性轴**:skill / 项目层内容依赖挂载,别的 workspace 不加载;工具操作知识(工具怎么配 / 凭据怎么解析)在**任何** workspace 都可能要用 —— 「防止每个项目都要找」是真实需求。
2. 判「该不该存在」不能拿 skill 当对照物 —— skill 的可达性是有条件的(挂载),其他 workspace 可能没有这些 skill。

## Considered Options

| 方案 | 结论 | 理由 |
|---|---|---|
| 维持两层,把工具知识归 .local | 否决 | .local 是项目作用域;工具知识跟着工具走不跟着项目走,放项目层 = 每项目重复一份 + 版本漂移 |
| 工具知识做成 skill | 否决(作为**归属**方案) | skill 靠挂载可达,未挂载的 workspace 找不到 —— 断了「处处都在」的分发渠道。(作为**任务型**流程知识仍是 skill 的正当形态,两者不冲突:判据看「换项目还需要吗」) |
| 三层模型(采纳) | 采纳 | 共享 / 项目个人 / 个人全局,判据 = 谁需要它 × 可达性依赖什么;第三层独特价值 = 无挂载依赖的可达性 |

## Decision
§3 表扩为三列 + 新增「无挂载依赖的可达性」判据段 + 误放症状(1↔2 互错 / 该升 3 / 该降 2)+ 单源纪律判据链(跟着工具走→全局;团队人人见→共享;否则→.local)。checklist 第 2 步同步为三层判。

## Consequences
- 主目录工具入口(各 harness/编辑器形态)有了明确建模与该放/不该放判据。
- 全局层写一条 = 所有 session 付 token 税,判据段显式提醒。
