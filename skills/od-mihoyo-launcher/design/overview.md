# od-mihoyo-launcher 设计

## 定位

米哈游启动器（HoYoPlay）的使用 skill：怎么把本机米哈游游戏客户端更新到最新、以及 agent 无人值守时的自动化操作链路（CDP 驱动页面 + Win32 驱动原生对话框）。与具体游戏解耦：游戏身份用 biz（业务标识）+ 主程序 exe + 安装目录描述，逐游戏参数见 references/games.md。

**边界**：不管 OneDragon 各项目的代码更新（git 层面）；不管游戏内玩法、画面建档（归各项目自己的建档流程）；不管游戏内容数据查询（归各项目自己的数据 skill）。更新中撞到陌生游戏画面不归本 skill 处理——先完成更新，画面问题转项目建档流程。

## 背景（为什么会有这个 skill）

2026-10 崩坏：星穹铁道 4.5 → 4.6 更新实机排障发现，「打开启动器点更新」的天真路径在本机会卡死，且第一层原因之下还埋着更深的根因（见踩坑记录）：

1. **界面显示「获取游戏」≠ 真未关联**：提权上下文启动会让启动器读不出已保存的游戏关联——这是本次排障的最大发现（此前误判为「未关联」并走了定位关联流程）。
2. **自动化基础设施缺失**：UIA 在部分环境被过滤（顶层枚举只剩个位数元素，启动器对话框完全不可见）；截图+坐标点击对网页式界面脆弱。可行链路是 CDP（启动器为 Qt+CEF 架构，接受 `--remote-debugging-port`）+ Win32 消息驱动原生对话框。

## 关键决策与动机

- **更新必须经启动器**：增量包 + 完整性校验 + 旧冗余清理都是启动器内建能力（4.5→4.6 实测更新中自动清理约 45GB 冗余）。手动下整包覆盖或改版本文件会破坏校验链，禁。
- **CDP 而非截图点击**：HoYoPlay 页面是 DOM，按文本点按钮精确且抗分辨率/窗口位置变化；CDP 口用 Chromium 标准参数 `--remote-debugging-port` 即开，无需改启动器。负面代价：启动器要以非默认参数重启，且任务后要重启恢复普通模式——换取的是可无人值守。
- **Win32 消息而非 UIA 驱动对话框**：UIA 不可用（见背景）；Win32 `EnumWindows + SendMessage` 链路完整可验。核心坑沉淀在 references/automation.md §5。
- **脚本随 skill 提交（scripts/）**：验证过的实现收进 skill 才能跨项目/跨会话复用；机器特异值（游戏目录）参数化为必填参数，仓库保持机器无关。
- **按钮状态机驱动流程**：启动器页面主按钮三态（获取游戏/更新游戏/开始游戏）精确对应「未关联/待更新/已最新」，SKILL.md 的路由以它为准，不依赖界面布局猜测。
- **与具体游戏解耦**：biz/主程序 exe/版本文件位置全部参数化并汇总在 references/games.md（标注实测状态），skill 本体只写通用流程。游戏身份的权威发现方法走注册表 UninstallString，不依赖背表。

## 实测参考数据（星铁 4.5 → 4.6，2026-10）

- 下载约 6 分钟（千兆带宽）；「校验并修复」约 12 分钟，慢于下载属正常。
- 全程磁盘峰值：剩余空间最低降到 4.9GB，更新结束回升到 47GB（启动器自动清理旧冗余约 45GB）。
- 更新完成后 `config.ini` 的 `game_version` 立即变为新版本，可作为完成标志。

## 踩坑记录（2026-10-10 实机事件）

- 现象：agent 从提权 shell 启动的启动器实例里，游戏列表缺绝区零（显示「获取游戏」）；星铁/原神也在 agent 实例里显示过「获取游戏」。用户自己从桌面启动的实例三个游戏全部正常。
- 根因（对照实验 + 存储取证确认）：**提权上下文启动会让启动器界面读不出已保存的游戏关联**——与调试口无关（无调试口的提权启动同样缺游戏），与 `--game` 无关（对照均复现/均正常），与数据无关（后端 `gamedata.dat` + 注册表 `GameInstallPath` 三游戏路径全程完好；绝区零未做任何操作，用户上下文启动即恢复「开始游戏」）。当天 18:32 前端 Local Storage 还发生过一次整体重建（SafeMode 链 + 强杀进程树诱发），其独立影响无法与提权效应区分，但用户上下文启动可完整恢复，说明持久层从未损坏。
- 附带发现：星铁/原神的旧版启动器 `config.ini` 记录的安装路径指向已不存在的旧盘（游戏迁移过盘），这类陈旧记录会让文件选择框反复弹「位置不可用」——属启动器记住历史路径的行为，清掉弹窗即可，不影响关联。
- 沉淀规则：automation.md §1 —— 必须用户桌面上下文启动（explorer 委托 + .lnk 内嵌参数），强杀禁用、优雅退出方法（设置关闭行为→退出启动器 + WM_CLOSE）；§4 —— 「获取游戏」先切用户上下文重启排除假缺失。

## 已知局限

- `--game` / `--remote-debugging-port` 参数与按钮文案来自当前版本（启动器 1.18.0.380）实测，米哈游改版可能失效——失效时优先回退人工操作路径，再更新本 skill。
- 未实测游戏：崩坏3 / 星布谷地 / 崩坏：因缘精灵（本机未装，参数表已标待核对）。
- 未覆盖：启动器自身大版本更新的迁移流程、跨大版本（>1 个版本差）的更新差异、国际服（biz 后缀不同，方法同构）。
- 「提权上下文读不出关联」的启动器内部机制是黑盒（安全组件限制或自身逻辑均有可能），本 skill 只依赖可实测的行为边界。
