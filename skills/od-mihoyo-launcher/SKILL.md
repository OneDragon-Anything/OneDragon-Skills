# 用米哈游启动器操作米哈游游戏客户端

> 原则：客户端更新必须经米哈游启动器完成（增量下载 + 完整性校验 + 旧冗余清理），禁手动下整包覆盖、禁手改版本文件。先读启动器页面主按钮状态再动手，按钮状态决定走哪条路。
> 本 skill 与具体游戏解耦：游戏身份 = `biz`（业务标识）+ 游戏主程序 exe 名 + 安装目录，逐游戏取值见 references/games.md。

没做完这 7 步不算完成：

1. ☐ 摸清环境：定位启动器 `launcher.exe` 与游戏安装目录，读出当前版本。判据：三个值都拿到（启动器路径 / 游戏目录路径 / 版本文件里的 `game_version`）。
2. ☐ 确认目标版本：联网查该游戏最新版本号。判据：明确本地落后几个版本；对账前把版本号归一为三段式（新闻口径「4.7」= 配置里的「4.7.0」），避免字面比对误判不一致。
3. ☐ 检查磁盘空间：游戏所在盘剩余 ≥10GB 才继续；不足 → 停下向用户要空间决策，禁自行删文件腾地方（启动器更新途中会自己清理旧版本冗余，缺口通常比整包小，但下载+校验仍需余量）。余量刚过门槛时照常继续，但每轮轮询盯空间，并在报告显式声明余量偏紧。
4. ☐ 检查运行中的游戏：确认没有游戏客户端进程在跑；有 → 先问用户能否关，禁不问就杀启动器进程树——从启动器拉起的游戏是它的子进程，按树杀会连带关掉游戏。
5. ☐ 以目标游戏的 biz 打开启动器对应页面，按主按钮状态路由（自动化读法见 references/automation.md）：
   - 「更新游戏」→ 有待更版本，直接进第 6 步；
   - 「开始游戏」→ 已是最新：与第 2 步版本对账，一致则收尾，不一致（启动器数据滞后）→ 重启启动器再读一次，仍不一致停下报异常；
   - 「获取游戏」→ 先排除启动上下文假缺失（见下方「启动上下文」节，实测零操作可恢复），确认真未关联才走关联流程（references/automation.md「关联本地安装」节），关联成功后按钮变「更新游戏」。
6. ☐ 点更新并监控到结束。判据：进度经历「下载中」→「校验并修复」→ 进度消失，页面按钮回到「开始游戏」；期间每几分钟看一眼游戏所在盘剩余空间。
7. ☐ 验证并报告。判据：游戏目录版本文件里的版本等于目标版本；报告写明更新前后版本、磁盘空间变化、过程中出现的异常。

## 环境发现（第 1 步的做法）

- **找启动器与 biz**：搜 Windows「已安装程序」注册表项，`DisplayName` 含「米哈游」或游戏名；游戏条目的 `UninstallString` 形如 `<启动器目录>\launcher.exe --uninstall_game=<biz>`，同时得到启动器目录与该游戏的 biz。
- **找游戏目录**：已关联游戏的权威来源是注册表 `HKCU\Software\miHoYo\HYP\1_1\<biz>` 的 `GameInstallPath` 值（后端真源）；无记录则找旧版启动器遗留的 `config.ini`（`[launcher] game_install_path`，注意可能指向已不存在的旧盘）或全盘搜游戏主程序 exe（exe 名见 references/games.md）。
- **读当前版本**：`<游戏目录>\config.ini` 的 `[General] game_version`（米哈游 Unity 系通例，新游戏首次操作先实机核对）。注意：游戏 exe 的文件版本信息是引擎版本号，不是游戏版本，别用它判断。

## 启动上下文（最容易踩的坑）

**必须以用户桌面上下文启动启动器，严禁从提权 shell 直接启动。** 提权上下文下启动器界面读不出已保存的游戏关联——**所有**游戏显示「获取游戏」，正常重启也不恢复，看似"配置丢失"，实际后端记录（`gamedata.dat` + 注册表 `GameInstallPath`）完好，换用户桌面上下文启动零操作即恢复。正确方式（explorer 委托）、需要调试口时的参数内嵌方案、强杀禁令、优雅退出方法——全套见 references/automation.md §1，执行前先读它。

## 操作方式

- **人在场**：按界面文字操作即可；「获取游戏」旁小字「已安装？定位游戏」是关联入口。
- **无人值守（agent 默认）**：用 CDP（Chrome DevTools 协议）驱动启动器界面——启动器是 Chromium 内核，经 explorer 委托以用户桌面上下文带 `--remote-debugging-port` 启动后可脚本读写页面、点按钮（**严禁提权 shell 直接启动**，会让界面丢游戏列表）；原生「文件夹选择」对话框用 Win32 消息驱动。工具已随 skill 自带（`scripts/`），启动方法、工具用法、关联流程、踩坑全集见 **references/automation.md**，执行前先读它。

## 收尾

- 「关闭窗口」设置改回用户原值；带调试口的实例经 explorer 委托正常重启一次即回普通模式。
- 大版本更新后，该项目自己的画面识别资产可能与新画面有偏差：跑自动化前先抽验，异常按项目自己的建档流程处理。
