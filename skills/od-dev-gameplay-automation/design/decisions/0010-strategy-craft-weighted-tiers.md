# 0010 · 策略深度细则按「策略重量」分层,而非平铺或按玩法类型分文件

- **Status**: accepted
- **Date**: 2026-08-16

## Context

CW(最复杂玩法试点)复盘暴露:阶段 7 是唯一没有 reference 的实质阶段(SKILL.md 策略节约 5 行,阶段 7 深度细则列 = 「见上」)。而 CW 实际策略期工作量与画面+实现同量级,四项方法论(遥测设计 / A/B 实验协议 / 人类玩法校准 / 策略代码 review 轮)全部在项目侧临时发明,换玩法即丢。

但「照 CW 的样子平铺一个全量 reference」被否决:CW 是策略重量的**最右尾样本**(自走棋×肉鸽混合,回合经济滚存),主流玩法(日常/领取、静态配队刷本、周期挑战)策略分量极轻,平铺会让 90% 的玩法读到用不上的重装备。skill 已有门控先例(策略需求清单:「简单玩法三条够,不强制;复杂才出」),策略深度细则应长成同构。

## Decision Drivers

1. 多数玩法策略轻,细则必须便宜可跳过(渐进披露,别让轻玩法负重)。
2. 方法论要能覆盖**未来的新玩法类型**(fail-open,别靠穷举既有类型)。
3. 避免与 build-craft「找兄弟」的类型映射、runtime-iteration 的验证协议双源。

## Considered Options

| 方案 | 结论 | 理由 |
|---|---|---|
| **平铺全量 strategy reference**(把 CW 四项全部平铺) | 否决 | 对主流玩法 over-fit;CW 是最右尾样本,套在轻玩法上全是死重 |
| **按玩法类型分文件**(肉鸽一个文件 / 自走棋一个 / 周期挑战一个…) | 否决 | ① 方法论与玩法类型**正交**(A/B 纪律对肉鸽/自走棋/周期挑战同样成立,分文件必然复制或交叉引用);② 类型名单对**新玩法** fail-closed —— CW 本身就不在旧名单任何桶里(自走棋×肉鸽混合),先例证明穷举必漏;③ 与 build-craft「找兄弟」类型映射双源 |
| **单文件 + 三轴门控分层(采纳)** | 采纳 | 门 = 局内决策密度 / 单局方差 / 局内资源管理 三轴问答,任何新玩法都能落位(fail-open);内容按 T1(全员)/ T2(局内决策)/ T3(局内经济)递进,轻玩法只付 T1 成本;跨游戏玩法原型表只作速查锚点(类型学词汇,非项目例子,规范4 安全) |

## Decision

新增 `references/strategy-craft.md`:顶部「三轴判型」门 + 主流玩法锚点表(锚点非穷举);T1 调优纪律(完整新局对照/别用恢复局/重启只在局间/单变量/样本量/最小可归因信号——最后者引用 runtime-iteration 不复制);T2 局内决策型(遥测记动作 / 人类玩法校准 / 日志分档);T3 局内经济型(逐回合快照 / 策略 review 轮 / session 生命周期);定位节「观测回路闭合后策略迭代与流程补全并行」。

SKILL.md 联动:T1 纪律 2-3 句上提进策略节(普适且便宜);阶段 7 行补 reference 指针;「调优在收尾」定位修正为「闭合即开始、与流程补全并行、收尾做最终定型」(CW 实证:流程层达标后即进策略期且正确,事件长尾与策略迭代互不阻塞)。

## Consequences

- 轻玩法(日常/刷本)读到策略节 2-3 句 T1 纪律即够,不需打开 reference。
- 肉鸽选择类(T2)获得遥测+人类校准;自走棋类(T3)获得全套,CW 经验完成泛化沉淀。
- 锚点表是词汇不是规则:新玩法类型答三轴即可落层,表不用维护穷举。
- 「最小可归因信号」单一源在 runtime-iteration(本 ADR 不搬),依赖后续反馈条目落地该节。
