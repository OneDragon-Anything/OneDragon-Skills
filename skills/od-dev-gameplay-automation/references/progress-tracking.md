# §1 开局:种子任务模板与生长

## §1.1 种子(开工即建,四件)

| 种子任务 | module | deps | 出口判据 |
|---|---|---|---|
| 玩法调研:确认能玩(常驻/限时/能实机/反作弊)+ 机制/一局流程/决策点/数据 | 支撑 | 无 | 玩法建档 doc(机制+流程+决策点;见 gameplay-recording.md) |
| 找兄弟+读代码:复用/丢弃清单 | 支撑 | 无 | 复用清单(build-craft.md §找兄弟) |
| 流程摸索:自行按玩法调研结论实机操作游戏,从入口走到底 | 支撑 | 玩法调研 + **动态**(每个画面建档任务,见 §1.2) | 全流程走通一遍 + 全部 deps done |
| 画面建档·\<画面名\>(**探索期动态生成**,见 §1.2) | 流程 | (不预设) | screen-onboarding 完整标准,产物标「待实现期验证」 |

- id 由 dag.py 自动分配,使用者不传。
- 玩法调研与找兄弟无依赖,开局即 ready 可并行;流程摸索被玩法调研挡住,自动等解锁。
- 简单玩法(策略轻)种子就这四件;复杂/策略重玩法,策略需求清单任务在玩法调研 done 后再建(能写 criteria 才建)。

## §1.2 流程摸索 × 画面建档:动态生成 + 动态加边

- 流程摸索**不是记录玩家操作**——没有真人可看,是 agent **自己按玩法调研的结论操作游戏**(入口/规则从调研 doc 来),实机从入口走到底。
- **每进入一个新画面**:当场 `add 画面建档·<画面名>`(按 od-dev-screen-onboarding **完整标准**,不分初档/全档,探索期产物标进行中)+ `dep <流程摸索id> --add <建档id>`——**每个画面的建档完成都是流程摸索任务的前置**(没搞清画面进出就继续走=凭猜)。
- 探索期执行节奏:摸索(doing)→ 进画面 → 建档任务建出并完成 → 摸索继续前进;交替由执行者驱动,图上只表达「摸索 deps=全部建档任务」这组边(建档任务不反指摸索,抵达画面是摸索的 doing 过程,不是任务——反指会成环)。
- 流程摸索的 done 判据 = 全流程走通一遍 + 其 deps(画面建档)全部 done;`who <摸索id>` 随时看还缺哪几档。
- 探索期建档**不是粗版**:标准一套,差别只在认知完整度(产物标注「待实现期验证」),实现期补全。

## §1.3 生长触发(done 的双动作,gameplay 实例化)

1. 玩法调研 done → 可定义:策略需求任务(复杂玩法:客观指标+策略需求清单,deps=玩法调研);
2. 流程摸索 done(全部画面建档齐)→ 可定义:流程设计任务(op 链+配置口,deps=流程摸索);
3. 流程设计 done → 按画面清单建**实现期画面闭环任务**:**1 画面 = 1 任务**(criteria=〔建档补全→写op→实测→代码测试→分支覆盖〕全过;环内进度用 note 记),deps 引用探索期对应建档任务(复用不重建),按游戏流程顺序排;
4. 全画面闭环 → app 编排任务(deps=全部画面闭环,判据 od-dev-write-application)→ 端到端验证;
5. 涌现(实现循环撞到新画面/子态/分支、实机复盘出病灶)→ 当场 add,deps 挂所属位置;
6. **别预画全图**:远期(编排/端到端/收尾)留到能写 criteria 再建。

## §1.4 分池判据(module 归属)

- **支撑**:玩法调研/技术调研/流程摸索/找兄弟/观测工程/测试基建/数据语料;
- **流程**:画面建档/画面闭环/op 编写实测/app 编排/端到端(按游戏流程结构,新分支归属自明);
- **决策**:策略需求/一个病灶或一条改进=一个任务(诊断→设计→实现→sim 验证→实机验证,环节按复杂度裁剪、**验证不可省**;轻调参直接一行:改了什么+sim 数字+commit);
- 三池互相触发:某任务 done 时检查别的池该不该长新任务(调研结论常在决策池生成工作项;实机/sim 发现的东西判性质入池:不懂→调研、画面/op→流程、行为数值→决策)。

# §2 防偏离门(gameplay 特化,loop 每轮必过)

- **定位五元组(硬门,必填)**:焦点必填 `做法X / 节点Y(工件) / 子项Z / 判据N / 本轮动作W`。
  - **判据 N**:画面节点填子态子判据 ①-⑤;**非画面节点填 §3 对应 skill 模版的完成判据**。
  - 假绿焦点豁免(画面级):`做法X / 画面Y / 对象类 / 动作W`。缺一 = 不合法。
- **产物落点校验(硬门,git diff 机械校验;只防最高危的「策略前置」漂移)**:画面任务的改动**不得触碰策略行为模块**(评分/权重/搜索/选择);该任务产出 = op 节点,读字段→存局内状态。策略行为代码算,**局内状态对象字段定义不算**(**实例须在根索引/决策日志列出本项目具体算/不算的策略行为模块路径**)。触碰 → 属策略行为(收尾策略节点),不是画面 op,得过下面策略锁。
- **策略行为锁**(改策略行为模块先过三解锁):
  - (解锁一·半硬)**改动策略读取的每个「从画面读取的字段」,其权威源画面的对应子态子任务①-⑤ 全已过(子态级)**。**非画面读取字段(代码内部派生值)豁免,不追溯**。**策略不得依赖罕见态子态才能读到的字段**(罕见态走中性 fallback;需真值等晋升后解锁)。字段→权威源画面→子态的映射**必须记入决策日志(D-NN)供复核**。
  - (解锁二·硬)做法二端到端跑通有观测回路;(解锁三·硬)客观指标已定义。
  - **权威源画面**:该信息最完整/最准的画面(完整形态),登记在**根索引的跨画面权威源映射表**(每画面要读信息清单在 screen doc)。
