# 策略深度细则(阶段 7,按策略重量分层取用)

> 本文件是 SKILL.md 阶段 7 的按需读深度细则。**策略调优方法论按「策略重量」分三层(T1/T2/T3),先判型再取用** —— 多数玩法只需 T1,别把重装备套在轻玩法上;判型拿不准时从低层开始,撞到该层解决不了的证据(如归因不了、数据被污染)再升层。

## 先判型:三轴定策略重量(门)

**门 = 回答三个轴的问题**(新玩法 / 不在下面锚点表里也能落位):

| 轴 | 问题 | 答案影响 |
|---|---|---|
| **局内决策密度** | 一局之中 bot 要做选择吗?多少?(无 / 节点级 / 回合经济级) | 决定要不要 T2/T3 |
| **单局方差** | 同样打法两局,结局差异大吗?(肉鸽随机性 / 商店 / 词缀) | 大 → fresh 局对照 + 样本纪律必须 |
| **局内资源管理** | 有跨回合经济(钱 / 资源滚存)吗? | 有 → 逐回合遥测 + session 生命周期(T3) |

**主流玩法锚点(速查用,非穷举;类型词汇不绑项目)**:

| 玩法原型 | 三轴落点 | 取用层 |
|---|---|---|
| 日常 / 领取 / 导航类 | 无局内决策 | T1 |
| 静态配队刷本(体力本 / 周本) | 局前配置一次 | T1 |
| 周期挑战(每期敌人变的配队挑战) | 局前决策、方差中 | T1-T2 |
| 肉鸽选择型(每节点选祝福 / 卡 / 奇物) | 节点级决策、方差高 | T2 |
| 自走棋 / 局内经济型(买 / 卖 / 升滚存) | 回合经济、方差高 | T3 |
| 放置 / 挂机阈值调参 | 无局内决策、需调阈值 | T1-T2 |

## T1 · 调优纪律(所有玩法都用,含无局内决策的)

- **基线先行**:改动前先用未改动的策略连跑多局完整新局,采出趋势级基线分布 —— 没有基线的"改了感觉好点"不是证据。
- **对照实验用完整新局,别用恢复局(进行中被中断后续跑的局)**:局内状态(session / 目标 / 历史)在中断与重启中可能已被污染或重置,恢复局的后续行为不代表任何一种策略的干净样本。恢复局只可用于**机制级验证**(某个动作执行没执行、日志对不对),**不可用于效果对比**。
- **重启 / 换代码只发生在局间**:上一局自然结束、下一局开始之前。绝不在对局中途重启(进行中局重载新代码 = 该局作废,还可能让流程迷航)。
- **单变量**:一次只改一个策略改动,别多改混跑 —— 两个改动同时上,赢了不知道归谁。
- **样本量直觉判据**:高方差玩法(方差轴答"大")单局结局无意义,至少几局看趋势;别拿一局胜负归因策略好坏。
- **最小可归因信号优先**:验证一个改动,取**能归因到该改动的最小信号**(一次动作的客观差异 / 一轮日志),别干等整局结局 —— 整局结局是多因素噪声。判据与长跑并行协议见 `runtime-iteration.md`「验证信号分层」(single source,本节不重复)。

## T2 · 局内决策型(节点级选择:肉鸽选祝福 / 卡 / 奇物类)

- **遥测记「做了什么」,不只「看到什么」**:每个决策点落一行 action 记录(在哪个节点、候选是什么、选了哪个、凭什么);只记状态快照不记动作 = 事后无法归因"为什么这么走"。
- **人类玩法校准(策略 ground truth)**:让会玩的人口述玩法节奏 / 选择倾向 / 数值经验,当**权威 ground truth**;与 bot 遥测**逐条对拍**找结构性差异(人做的事 bot 不做 / 人给的数值模型里没有)—— 每条差异即一个候选改动。数值门槛类(等级 / 费用表)优先向人要权威表,别自己估(估错会像观测错误一样污染决策模型)。
- **候选改动两个来源,别只靠人**:① 人类玩法校准(上条);② 遥测自主诊断 —— grep「需关注」前缀与失败局记录,漏检 / 异常聚集处 / 失败局的过程数据就是假设生成器。只有 ① 会漏 bot 特有问题(人不会犯的错人指不出来)。
- **日志前缀分档**:普通流程日志与「需关注」(漏检 / 未知画面 / 异常状态)分两个前缀,后者可 grep 直查 —— 调优期的主要排查入口。

## T3 · 局内经济型(回合经济滚存:自走棋类)

T2 全部内容 + 以下:

- **逐回合状态快照**:每回合落一行结构化快照(回合数 / 资源 / 血量 / 阵容构成 / 关键状态),格式可 grep 可聚合(如 jsonl);跨回合经济玩法不落快照 = 调优时只有结局没有过程,任何中期问题(第几回合开始崩)都定位不了。
- **策略代码 review 轮**:策略实现量大后,用**独立视角**(新会话 / 子 agent)质疑式审查:代码 vs 设计文档逐条对拍(实现和设计脱节是常态;对拍只对**设计内容** what/why,实现状态以任务树为准 —— 设计文档里的状态副本可能过期,别当证据)、评分权重 / 阈值硬编码与配置口覆盖度、数据依赖真实性(读的字段是真读还是兜底)。发现项分**阻塞**(错误行为 / 死逻辑)与**次优**(可辩护但待验证)两级,阻塞先修;每修一条独立 commit + 决策记录。
- **资源耦合闭环审查(review 固定检查面)**:系统里存在**多类决策共享有限资源**(金 / 槽位 / 人口 / 装备位 / 材料等)时,逐对检查「决策 A 的资源不足分支」有没有回连到「能补该资源的决策 B」——**断链形态**:不足分支直接拒绝 / 放弃 / 静默跳过,而系统里明明存在变现 / 腾位 / 合成腾槽等补资源路径。审查法:列决策种类×资源种类矩阵,每格问「这个不足分支回连了吗」;设计文档只写各决策点、不写轮内闭环时,断链几乎必然存在(设计按决策点分节,闭环是跨节的)。判例:买卡金不足直接拒绝,而备战席的压库件(设计上双重身份:占池+可变现)本可卖掉凑金——"存款"没有取款通道。
- **「门槛 vs 身份」判据(防特权逻辑)**:玩法指导 / 玩家口述里的「X 优先 / 默认 / 必选」措辞进入实现时,先问这是**门槛差异**还是**身份差异**——门槛差异(某物更容易达成 / 成本更低 / 更早可用)应实现成**统一评分维度或数据字段,对所有候选生效**;身份差异(功能链不可拆 / 机制专属)才允许专属处理,且判定依据读注册表数据而非名字 if。判法:把那个性质抽象成维度后,其他候选也能有值吗?能 → 门槛差异;只有它有 → 再核是不是真身份。**代码味道**:具名 if / 专属常量 / 手抄名单,而该知识已在数据注册表里;**扩展性自检**:新候选加入时要改分支代码而非只加一条数据 = 同味(未来加羁绊 / 加卡 / 加阵容时零改动的才是统一实现)。判例:「X 默认首站」(某体系激活只要 2 件,门槛最低——被实现成专属 +1.0 加成与例外条款;正解是 readiness=已有件数/激活所需件数的统一维度,低门槛自然胜出,新体系加入零改动)。
- **session 生命周期要显式设计**:局内累积状态(目标 / 历史 / 追踪)放哪、局间怎么重置、进程重启丢什么要想清楚并写下来;「重启后 resume 的局不算连续样本」(T1 的 fresh 局纪律由此而来)。

## 定位:观测回路闭合后,策略迭代与流程补全并行

「策略调优」不是等全部流程收尾才开始的独立阶段:**观测回路一闭合**(能采到每回合关键指标 / 胜负),策略迭代就可以开始,与流程补全(事件长尾 / 罕见态)**并行推进** —— 两者互不阻塞。收尾阶段做的是最终 A/B 定型与文档,不是从零开始调优。
