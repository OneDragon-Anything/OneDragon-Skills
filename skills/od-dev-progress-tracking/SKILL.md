# 进度记录与防偏离(任务树状态机)

**全局方法**(不绑具体项目/玩法/框架)。适用于任何复杂多步骤开发。各工件 skill 在各自 SKILL.md 末尾有「进度模板」小节提供叶子完成判据;本 skill 只组织成树(状态机 + 聚合 + 防偏离),不发明判据。具体应用的阶段骨架(如 gameplay-automation 的 5 阶段)在对应流程 skill 的 reference 里。

# 进度文件改动 checklist(使用入口)

写 / 改 / 加状态时过一遍。**指针式** —— 每项指向 §,机制详述在各节(本 checklist 不复述,避免双源);拿不准的项跳对应 § 看。

**结构 → §2**
- [ ] 节点形态对:非叶子(≥2 子步骤 / 进行中 / 多判据)= 目录 + 进度.md;叶子(单一判据已验 / 未做占位)= 父表一行;⚠️ 半完成的别当叶子行
- [ ] 编号反映深度、接续(中途插用尾缀 a);依赖 DAG 无环
- [ ] 新节点记「为何加」(实机撞到 / 版本 / 拆分)

**状态 + 聚合 → §3 / §4 / §6**
- [ ] 用规范状态词,不自造
- [ ] 父状态按聚合规则派生,不自由填
- [ ] 改了叶子 → 沿依赖链重算各层聚合
- [ ] 回退标对:误判回退 vs 代码退步(两种记法不同)

**归属不双源 → §10 边界**
- [ ] 判据存指针非复制;why → 决策日志;产物成熟度(草案 / `# 未验证`)→ 产物标注,不进状态机

**可观测性(可重载 + 可重验)→ §9**
- [ ] 仅凭文件能重载:干净上下文读核心段,答得出「在哪 / 卡哪 / 下一步」
- [ ] 硬门三问填得出:验什么 / 怎么算过 / 凭什么
- [ ] 无含糊编号代指:①-⑤ / a-b-c 必枚举 + 每项验证法,否则补 or 废弃(已有的回溯)
- [ ] AI 推断当硬门时标源:⚠️ AI 推断 + 来源 + 可质疑,固化时找读者认同;普通中间推断不标
- [ ] 「待确认」给可答形式:选项 or 具体问题,非让读者替你定义概念
- [ ] 概念可查:新黑话 / 缩写首现处定义 or 进概念表

**续任务 → §7**
- [ ] 恢复用 grep 未完成集(不信聚合层),根索引只作上下文
- [ ] 根索引 + 每层索引有焦点;焦点 = 进行中且未阻塞的最早任务(被卡住标锁定不当焦点)

**防偏离门 → §8(仅 loop / 自主推进时)**
- [ ] 定位五元组填得出(阶段 / 节点 / 子项 / 判据 / 本轮动作)
- [ ] 产物落点没碰核心模块(碰了 → 核心锁过三解锁)
- [ ] 进行中工件节点 ≤ 1

# 总纲(通用机制,递归不变量)

> 适用于树的**每一层**:根/阶段/工件/子项/叶子都是任务节点,有状态、可聚合、可加子任务、可改状态。

## 1. 原则

- **状态机,不是叙事**:节点状态可更新,不 append 过程。过程时序/决策 why/历史各有归属。
- **扎根 skill,不双源**:节点只存「状态 + 判据指针」,判据原文在对应 skill 模版(§11),不复制。
- **每层有索引**:每目录 `进度.md` = 该层目标 + 子任务表(编号/状态/依赖/卡点)+ 当前焦点。
- **自主推进模式的编排接口保护**(与 od-dev-agent-autonomous-mode 的边界):若该进度文件同时被自主推进模式使用,其关注面节的工作状态三小节(主线任务/周期改进/持续运行)+「下一个待派」是**编排接口**——按本 skill 规范重排结构/治理流水账时**保留这些节**;它们的消费协议(触发器/补位/盘点)归 autonomous-mode skill,本 skill 不管。防偏离分工:本 skill 管**文件层面**(记成叙事/状态失真/树腐化),autonomous-mode 管**行为层面**(干等/窄化/陪跑)。
- **三类工作是普适关注框架**(任何推进模式——指导/自主——都该关注,自主模式只是把它机械化):**主线任务**=关键路径上的交付件(有终点有依赖,依赖驱动);**周期改进**=降低未来风险的洞察件(单个一次性,类是周期性——review/对抗/模拟找问题/反馈审,定期扫描供给);**持续运行**=无终点只有健康态的运转(测试基线/语料积累/常跑任务,健康监控)。进度文件的关注面节按此三小节记。**为什么所有模式都该关注**:周期改进永远「重要不紧急」,不显式关注就永远排在主线后面;持续运行不监控就静默死。指导模式下靠人自觉维持,自主模式下由提醒网机械化(触发机制归 od-dev-agent-autonomous-mode)。

## 2. 任务树(递归)+ 文件组织

**树形**:`app(根) → 阶段 → 工件 → 子项 → … → 叶子`,**任意深度**递归。
- **递归终止判据**:节点能**独立完成 + 独立验证**(单画面单子态建档过 / 单 op `run_operation` 过 / 一段流程端到端过 / 一类数据采集完)。能 → 叶子;含多个工件或多判据 → 继续拆子节点。
- **编号**(层级,反映深度):`4.2.1.3` = 阶段.工件.子项.更细。中途插入用尾缀(`4.2.1a`)。
- **聚合**:父节点状态 = 子节点按 §4 派生(无自由度)。

**文件/目录组织**(任务树落盘,示例):
```
<app>_dev/
  进度.md                          # 根索引:app目标 + 阶段状态(聚合) + 当前焦点 + 防偏离门 + 权威源映射表 + 阈值实例
  1_<阶段>/进度.md                  # 阶段索引(子任务表 + 焦点)
  ...
  N_<阶段>/
     进度.md                       # 阶段索引
     <工件>/进度.md                 # 工件节点:子任务表 + 判据指针
     <工件>/<子项>/进度.md          # 更深层(如需要)
  events.md                        # 分支长尾收件箱(§12)
```

- **目录 vs 行(建文件时的硬判据)**:**非叶子节点 = 独立目录 + `进度.md`**(有 ≥2 子步骤 / 进行中未闭环 / 多判据 → 继续拆,每层一目录);**终端叶子 = 父 `进度.md` 子任务表一行**(单一判据、已验证完成,或未开始的占位)。⚠️ **半完成任务(部分步骤过、有未做子项)算非叶子 → 建目录**,别当行塞进父表(常见错:把「方法验证了但集成没做」当叶子行)。规模门槛(>~20 / 非平凡图)触发**再深拆一层**(§5),非唯一建目录条件。
- **工件 skill 的多步流程任务 = 非叶子(目录),别当叶子行**(常见矛盾:各工件 skill 的「进度模板」表用「叶子」列,但其任务是多步流程 → 跑的时候照叶子行做,漏子步骤、早标已过)。判据:**任务有 ≥2 个独立子步骤要逐个跟踪(画面建档 9 步必做流程 / app 编排步1-5 / 一个画面的多 op)→ 非叶子 → 目录 + 进度.md**,子步骤作子任务逐个推进、全过才算该节点过。各工件 skill「进度模板」表给的是**单步叶子的完成判据**,不是「整个多步任务是叶子」—— 多步任务用目录组织,目录下每个子步骤引用对应判据。⚠️ **别早标已过**:多步流程节点在没走完全部子步骤(尤其交互验证 / 实测类)前标已过 = 假绿,是常见跑偏。
- **`进度.md` 顶部标注关联 skill**(若有,写 `参考 <skill-name> skill` —— 让继续者一眼知道该看哪个 skill 的方法论;有些任务无关联 skill 可不标)。
- `events.md` / 决策日志 / 过程时序记录 / doc 各归各处(§10 边界)。

### 2.5 多迭代三层结构(跨迭代并存;2026-08-25 新增)

> 术语约定(本节):**三池**=迭代目录下的三类任务池(调研/流程/策略——每类工作性质不同,任务进各自的池);**工作状态的三小节**=主线任务/周期改进/持续运行(定义见 §1 普适框架);**停用条件**=新进度结构取代旧进度文件的切换条件。

单 app 长期开发会有**多个迭代/分支并行或相继**(新功能/大重构/策略冲刺),单根索引装不下——升级为三层(与单 app 结构并存,小项目用单 app 结构即可):

```
.debug/progress/                    # 进度追踪根(一个仓库一个;**无入口文件**——每个迭代目录自含)
└── <开工日期-内容>/                 # 一个分支/一次完整功能迭代 = 一个目录(自含入口)
    ├── 进度.md                     # ★ 迭代入口(三件套,见下)
    └── <app>/                      # 涉及哪些 app 建哪些子目录(影响面盘点产物;多 app 平级)
        ├── 调研/玩法/进度.md        # 调研池(疑问单步任务平铺)
        ├── 调研/技术/进度.md
        ├── 流程/进度.md(+<画面>/)  # 流程池(按游戏流程结构;画面=目录)
        └── 策略/进度.md(+<病灶>/)   # 策略池(按策略分层;病灶=目录)
```

**迭代入口三件套**(迭代目录的进度.md 放什么;任务细节不进入口——那是 app 三池的事,入口只留指针):
1. **工作状态**(三小节:主线任务/周期改进/持续运行,定义见 §1 普适框架)——主线小节第一行=**当期目标行**:「追什么+达成判据进行到哪」(如「判据起数 1/3」);判据**定义不复制**,锚定权威文档(玩法判据锚口述节奏/形态白名单等,禁自创验收数字——孤立/自创指标是误判之源,判例:拿 HP 当位面验收而权威文档明写验收是经济线);判据状态由判读评估,**不随任务完成自动翻转**(任务全做完≠目标达成);达成即换下一目标行并归档旧行;
2. **涉及 app 表**(每 app 一行:目录+状态;多 app 迭代在此总览);
3. **并行协议脚注**(与旧进度文件的分工/停用条件,若有)。

> 长视程目标(跨迭代的最终目标)不进入口——家在项目策略文档;入口的当期目标从它派生。任务节点行内标注「→判据N」关联(收账时看推进了哪条判据);策略类任务的效果记录规范见 od-dev-gameplay-automation 策略节。

**迭代启动 checklist(开始新 app/新迭代的第一件进度动作)**:
1. ☐ 影响面盘点:这个迭代波及哪些 app(玩法级=1 个 app 子目录;底层修复多 app=多个平级 app 子目录)
2. ☐ 建迭代目录(`<开工日期-内容>`;追溯历史时用首提交日,不伪饰)+迭代入口进度.md(三件套)+app 子目录(按需建三池)
3. ☐ 判停用:若与旧进度文件并行,写明并行分工与停用条件(新制能独立回答「下一步派什么」→ 旧制降级为运行日志)

**三池任务模板**(判据 defer 到工件 skill,见 §11 通用叶子表;**玩法侧的具体语义=gameplay-automation 的事,此处只写通用形态**——本节细则全文的 gameplay 实例化见 od-dev-gameplay-automation references/progress-tracking.md §1,别在两处重复):
- **调研池**:疑问单步任务(搞懂一个疑问即完成;状态+结论指针+来源标注);产物归领域知识文档(不进进度目录)
- **流程池**:按目标系统的流程结构组织(如游戏的流程阶段→操作单元→变体);**多步骤工作单元 = 独立子目录**(§2 硬判据);小修不建目录但**验证锚点必挂**(改了什么+拿什么验证)
- **策略池**:按策略的分层结构组织;**一个改进主题=一个目录**(诊断→设计→实现→离线验证→实测,环节可裁剪**验证环节不可省**;含效果结论位,规范见对应领域 skill);微调不建目录
- **gameplay 实例化细则**(池的玩法侧组织)→ od-dev-gameplay-automation references/progress-tracking.md §1

**涌现登记规则**(一池的发现可在别的池生成任务):实机/sim/口述发现新东西→判性质(不懂的→调研/画面或 op→流程/行为数值→策略)→对应池生成节点(行内注释来源);**某池完成时检查是否应在别的池生成节点**(跨池触发)。

**工件 skill 进度模板链**(流程池内的嵌套组织,各环节自己的组织细则归各 skill——本节只画链):
`write-application`(app 编排=目录,五步判据;前置=各画面闭环) → 前级的画面组织 → `od-dev-screen-onboarding`(画面=目录,建档 9 步;画面目录挂流程池下,建档完继续收 op 任务) → `od-dev-write-operation`(画面目录内每 op=子节点,op 三步判据)。新工件类型进链时:在对应 skill 的进度模板节写自己的组织规则+互引,本链只加一行指针。

**聚合/检索/焦点三机制**:
- **状态向上同步**('冒泡'):改叶子状态时顺手改两级父(每次 5 秒,别攒批对账;进度对表类提醒只抽查纠偏);
- **检索待办**:单条 grep 全树活任务(`未做|进行中|锁定` + `--include=进度.md`);「下一个待派」全树只在迭代根标一处(活动指针,派完即更);
- **焦点向上同步**:三层焦点(根入口/迭代根/段进度),改状态时问一句「这改变当前焦点吗」。


## 3. 状态机(文本可 grep)

| 状态词 | 语义 | 适用层级 | 格内容 |
|---|---|---|---|
| 已过 | 过(满足判据) | 节点级 | `已过 D-NN` |
| 未做 | 未做 | 节点级 | `未做`(回退见下) |
| 进行中 | 已动手未闭环 | 节点级 | `进行中`(可选注在做啥) |
| 锁定 | 前置节点未过,禁止推进 | 节点级 | `锁定 前置=<节点号>` |
| 不适用 | 不适用 | 节点级 | `不适用 <为何>` |
| 部分过 | 子节点部分过(聚合态) | 父节点级 | `部分过 <缺什么>` |
| 罕见态 | 罕见子态特例(走不完验证) | 子态节点特例 | `罕见态`(见 §12) |

> 决策日志用项目自选编号(示例 `D-NN`)。

**聚合用二分**(§4):「满足」= 已过 / 不适用 / 罕见态(声明 fallback);「未满足」= 未做 / 进行中 / 锁定。

**回退标记**(非独立状态,跟「未做」后):`未做 曾过D-XX 回退D-YY`。仅用于「误判回退」(原判断错);「代码退步」(改坏致退步,原判断当时对)记新 `未做` + 新决策,不用回退。

## 4. 聚合规则(父 = 子派生,按序匹配,无自由度)

| 序 | 子节点情况 | 父节点状态 |
|---|---|---|
| 1 | 全部满足(已过/不适用/罕见态) | 已过 |
| 2 | 全未满足,且全锁定 | 锁定 |
| 3 | 全未满足,有未做(无进行中) | 未做 |
| 4 | 有满足 + 有未满足,满足数 **>** 未满足数 | 部分过 |
| 5 | 其余(有进行中,或 满足数 **≤** 未满足数) | 进行中 |

- 按序匹配,先命中先生效(序 2/3 在序 4/5 前,消除"全未做"歧义)。
- 计数:满足数 vs 未满足数直接比较(**不适用计入满足数**)。边界:满足数 = 未满足数 → 序 5(进行中,未过半)。
- 罕见态子节点 = 满足侧(不阻塞父聚合);其自身晋升见 §12。
- **锁定传播**:前置未过 → 依赖节点标「锁定」。依赖须 DAG(有向无环);出现环 = 建依赖时出错,拆环。改一处叶子 → 沿依赖链向上重算各层聚合。

## 5. 中途加任务(树操作)

- 发现新工件/新子项/新事件/新数据类 → **按对应 skill 规范建新节点**,挂进对应阶段。
- 编号接续(§2);依赖连相关节点;状态=`未做`;判据指针指向 §11 skill 模版;记「为何加」(来源:实机撞到/版本更新/拆分)。
- **规模门槛(再深拆一层)**:单节点子项 > ~20 或流转成非平凡图(循环/多对多)→ 再深拆一层子目录。⚠️ 这是**规模触发的更深拆分,非唯一建目录条件** —— 建目录主判据是「非叶子」(§2:有子步骤/进行中/多判据 = 目录,终端叶子 = 行)。别把本条读成「小节点都该是行」。

## 6. 改状态(树操作)

- **推进**:未做 → 进行中 → 已过(格内容记 `已过 D-NN`,why 留决策日志)。
- **回退**:已过 → 未做(标 `回退 D-YY` 误判 / 新决策 代码退步)。假绿复核反转(原判不适用实际要认全)→ 闭环回退为未闭环 + 补建全集,记决策。
- **唯一真相 + 路径回算(改状态 ≠ 只改一行)**:状态改在节点;改完叶子后**沿其文件路径逐层向上回算**(所在子目录 `进度.md` → 父目录 `进度.md` → … → 根索引),每层用 §4 规则重算**该节点在父表中的那一行**并更新,直到根。⚠️ 常漏点:只改了子任务表行,忘了该节点在父表也占一行 —— 漏任何一层 = 聚合层随即过期,这次状态更新没完成。
- **每层重算(机械)**:数该节点子任务表「满足」(已过/不适用/罕见态)与「未满足」(未做/进行中/锁定)行数 → 按 §4 序 1-5 匹配 → 得父新状态;**决策号只记叶子**(聚合行不带 D-NN,「凭什么过」在叶子的决策日志)。
- **写完自查(一条 grep)**:状态更新后对整棵树 grep 未完成状态词(`未做|进行中|锁定|部分过`),两个异常模式 = 回算漏了,当场补:**父=「已过」但子表仍有 未做/进行中/锁定**;**父=「未做/锁定」但子表已有 已过/进行中**(反向漏:做了没记)。

## 7. 继续之前任务(跨会话/loop 续)

- **根索引顶部**永远有「当前焦点」(哪个阶段/哪个节点/卡什么)+ 「下一步」。每层索引有「该层焦点」,层层下钻到正在做的叶子。
- **恢复流程 = grep 优先,不信聚合层**:① 先 `grep -rnE '未做|进行中|锁定|部分过' --include=进度.md <任务树根>/` 拿**未完成全集**(规范状态词 grep 得候选;「已过/不适用/罕见态」不算);② 根索引只作**上下文核实**(当前焦点/防偏离门/权威源),**未完成项以 grep 结果为准**;③ 按焦点下钻对应子目录,看卡点+依赖 → 继续。**为什么不信聚合**:聚合状态由叶子手动回算(§6)而来,回算前它就是过期的 —— 根索引「已过」可能是重算遗漏,「未做」可能已做完没回填,两个方向都误导;树越大(跨月/多子目录)越严重。焦点定位不上 → 偏离信号,回最近未闭环叶子。

## 8. 防偏离门(loop 每轮必过)

> 本方法补充,非 playbook 原文。防止自主 loop/agent 漂离主线。

- **定位五元组(硬门,必填)**:焦点必填 `阶段X / 节点Y(工件) / 子项Z / 判据N / 本轮动作W`。
  - **判据 N**:填 §11 对应 skill 模版的完成判据(或项目自定义判据)。
  - 填不出 = 偏离信号,回最近未闭环叶子。
- **产物落点校验(硬门,git diff 机械校验)**:工件节点的子任务改动**不得触碰项目定义的核心模块**(如策略行为模块:评分/权重/搜索/选择;具体路径由项目在根索引/CLAU.md 列出)。触碰 → 属核心模块改动,得过下面核心锁。**局内状态对象字段定义不算**(实例须在根索引列出本项目具体算/不算的核心模块路径)。
- **核心模块锁**(改核心模块先过三解锁):
  - (解锁一·半硬)**改动读取的每个「从权威源读取的字段」,其权威源的对应子任务全已过**。**非权威源读取字段(代码内部派生值)豁免**。字段→权威源映射**必须记入决策日志(D-NN)供复核**。
  - (解锁二·硬)端到端跑通有观测回路;(解锁三·硬)客观指标已定义。
  - **权威源**:该信息最完整/最准的来源,登记在**根索引的映射表**。
- **跨阶段不变量自检(软门)**:①结论跨多样本?②动手前查文档非凭猜?③先读日志?④卡住时分清技术故障 vs 认知缺口?任一不过=偏离。致判据变化→决策日志;未致→过程时序记录。
- **进行中工件节点≤1(软门)**:同时「进行中」的**工件级**节点 ≤ 1。开新工件先闭环当前或显式暂停记决策。

## 9. 进度文件可观测性(可重新加载 + 可重新验证)

> 进度文件是任务状态的**外部持久化产物** —— 把易失的上下文 / 会话记忆卸载到文件。它要满足**可观测性 + 可复现性**:任意读者(未来的 session / 人 / 任何观察者)都能**仅凭文件本身**自洽地重新加载状态 + 重新验证每个结论,**不依赖写文件时的原上下文**。含糊 / 悬空 / 不可验 = 重新加载失败 = 任意读者卡死(含写它的 AI 自己换 session)。读者是人还是 AI 不重要 —— 重要的是文件**自带足重建 + 验证所需的一切**。

进度文件不只给「写它的那个 session」续任务用,而是给**任意未来读者**(换 session 的 AI、项目负责人、任何观察者)。判据见开头「进度文件改动 checklist · 可观测性组」。核心四点:

- **可观测(可重新加载)**:状态持久化到文件,任意时刻 / 任意读者能仅凭文件重建「在哪 / 卡哪 / 下一步」—— 对应软件可观测性(把易失的进程内存 / LLM 上下文,持久化成可被重新观测的外部表征)。
- **可复现(可重新验证)**:每个状态标记带「凭什么」(判据 / 证据 / 来源),任意读者照着能重新跑一遍验证,而非盲信原标记 —— 对应可复现研究 / event sourcing(状态可重放推导,不是一次性黑盒)。
- **读者无关**:不区分人 / AI,都是读者;文件自带重建 + 验证所需的一切。失了这条 = 进度文件退化为「只有原写者能懂的自循环笔记」,换 session 即失效。
- **AI 推断标源**:被当作阻塞推进的硬门 / 锁 / 前置的 AI 推断(非用户指令 / 代码事实 / 客观证据派生),必须标来源 + 可质疑 —— 否则未来读者无法重验,等同含糊门。普通中间推断不必标(避噪音)。

典型病灶(反例):进度文件写「硬门:某条件①-⑤ 全过」当阻塞门,但①-⑤ 从未枚举、无每项验证法 —— 这条只活在写它的 session 上下文里,文件无法重载 / 重验,任意读者(含换 session 的 AI)卡死,或漂移去做无关工作填时间。解法:硬门三问(验什么 / 怎么算过 / 凭什么)+ 含糊编号当场枚举 or 废弃。

# 12. 事件长尾(events.md)

运行中持续冒出的新分支/新画面/新事件收件箱。分节:主收件箱 / 广义降级区(可复现待排期)/ 已知局限暂搁。
- 条目:`类型/归属工件/fixture/代码测试/来源(建档已知/运行时新发现)/状态`。
- **降级流转**:条目停留超**降级阈值**未三过 → 按可否复现移入广义降级区。暂搁条目停留超**最终阈值**仍未复现 → 决策日志记「已知局限」+ events 标最终态。
- **清理(正常分支)**:handler+fixture+测试**三过** → 补齐子任务迁入工件子节点 → events 删条目。
- **清理(罕见态特殊路径)**:判据表罕见子态行保持 `罕见态`(**不晋升**);events 留广义降级区靠运行时撞;撞到且能完整验证 → 该子态从 `罕见态` 变全已过(晋升)+ events 删。
- **全新独立工件晋升**:先建工件节点(子任务骨架)→ 走子任务 → events 删条目。
- **退出判据**:连续 N 次运行无新 event 涌入。阈值(M/N/降级/最终)按项目单局规模定,实例在根索引给出。
