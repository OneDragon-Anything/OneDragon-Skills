# 进度记录与防偏离(任务账本 + 流水 + 脚本校验)

# 进度文件改动 checklist(使用入口)

写 / 改 / 加状态时过一遍。**指针式**——每项指向 §,机制详述在各节;拿不准的项跳对应 § 看。

**写入 → §3/§4/§7**

**结构 → §2**
- [ ] 文件类型正确:账本(模块 进度.md)=纯任务行;流水=jsonl append;归档=只进不入检索

**依赖 → §5**

- [ ] 定位五元组、产物落点、核心锁三解锁、进行中工件 ≤1

## 1. 原则

- **状态机,不是叙事**:任务行状态可更新;过程时序(局判读/收账叙事/事故/裁决记录)归流水文件,不在账本。
- **账本与明细分离**:任务行(账本,永久)=每任务一行;多步任务的子任务行(明细,临时)=闭账塌缩成父行一行。
- **机器算的聚合才可信**:汇总由 `progress.py summary` 现算现输出,不落盘、不人工回算——人工派生层必然腐烂(实证与出处见 ADR-0002)。
- **扎根 skill,不双源**:任务行只存「状态+判据指针」;完成判据原文在各工件 skill 模版(§12),不复制。
- **写入过门**:任务行由 `progress.py write` 生成或校验;格式是校验规则不是建议(先例=tool-ralph 的有界结构化交接:状态与必填字段一致性由机制拒绝,不靠自觉)。

## 2. 结构(两级目录,固定)

```
.debug/progress/<开工日期-内容>/        ← 迭代目录
├── 进度.md                            ← 入口:init 生成三行(目标+判据指针),此后不维护
├── 流水-<YYYYMMDD>.jsonl              ← 过程时序,append-only,一天一文件
└── <app>/                             ← 第 1 级:app(跨 app 共用件用「公共」伪 app)
    ├── 流程/进度.md                    ← 第 2 级:模块 = 账本(任务清单)
    ├── 决策/进度.md
    └── 支撑/进度.md                    ← 内部自由标签分节(tag 非枚举)
```

- **入口**:`progress.py init` 生成(迭代名/目标/判据各一行+治理说明),此后只在目标措辞变化时改。不记 app 表(目录存在=app 存在,脚本自动发现)、不记状态(归账本)。
- **流程 vs 决策** 分判:改「bot 走到哪」(画面/op/流转) → 流程;改「每步怎么选」(判据/权重/采购规则) → 决策。
- **支撑**:非产品行为的全部任务(遥测/sim/数据语料/工程/调研/识别体系/实机队列…),内部自由标签分节。标签是 tag 非封闭枚举;某标签 ≥15 行且高频被派单引用 → 升格独立模块。归属判据一句话:**类是持久交付物的容器,不是工作的某个时刻或做法**(验证/评审是任务收尾环节,运维归值守体系,都不是类)。
- **多步任务**:缩进子任务行(两空格)装在模块文件里,**不开子目录**。出生条件=≥2 个需独立验证的子步;死亡形态=闭账删明细行,父任务一行收口。
- **跨模块任务**归其代码/知识所属模块;跨两侧消费的(如遥测)进支撑,不在两侧各记一份(防双源)。

## 3. 行文法(任务行,唯一格式)

```
[编号 ]<主题>——<状态词>(<指针或验证锚点>;<一行补充≤80字>)
  <缩进子任务行,同文法>
```

- 括号内白名单:**指针(文件/ADR/符号)/ 验证数字 / 一行结论**。禁过程叙事。
- 编号只要求同文件内一致,跨文件不比大小(不同文件的编号是不同坐标系)。
- **合法聚合行**:单任务的多步(如 op 的编写/实测/测试三步全过)可聚合为一行,括号内带判据指针,不展开子行。
- 模块文件内 `## 标签` 分节仅支撑文件必用;流程/决策文件按需分节(如按画面域),节是导航标签非任务节点。
- 文件尾部保留一行治理指针(归档去向/流水位置),由 init 生成。

## 4. 状态机(七词封闭 + 一致性强制)

| 状态词 | 语义 | 必带字段(write 校验,缺失=打回) |
|---|---|---|
| 已过 | 满足判据 | 指针(产物/ADR/commit);不带下一步 |
| 未做 | 未做(含回退标注:`未做 曾过D-XX 回退D-YY` 仅误判回退;代码退步记新未做+新决策) | —— |
| 进行中 | 已动手未闭环 | 下一步动作 |
| 锁定 | 树内前置未过 | `前置=<任务标识>` |
| 待激活 | 等外部条件(非树内前置) | `条件=<条件+复查时机>` |
| 不适用 | — | `<为何>` |
| 部分过 | 子行部分过(聚合态) | `缺=<什么>` |

**自造词别名映射**(直改文件时先归一,write 拒绝未映射词):
已修→已过 / 已挂→待激活 / 在飞→进行中 / 候用户→锁定(前置=用户裁决) / 条件已解除→未做(注:条件已解除) / 收编→已过(注:并入件号) / 已落地→已过 / 已闭环→已过。

> 锁定 vs 待激活:锁定=等树内前置(看前置过没);待激活=等外部条件(看条件到没)。待激活登记自问「没有它这个批真的跑不了吗?」答不出=只是偏好时序,记未做并注明想等什么(不强制)。

## 5. 依赖与检索

- 依赖用两个字段表达,不靠嵌套:`前置=<任务标识>`(树内,看前置过没)/ `条件=<外部条件+复查时机>`(外部,看条件到没)。
- **未完成集检索**(恢复/派单的唯一依据):
  `grep -rnE '未做|进行中|锁定 |部分过|待激活' --include=进度.md <迭代目录>/`
  ——只扫账本;归档与流水文件永不参与(归档里的历史状态词是快照,计入=误报)。
- 派单=盘点轮每轮重扫账本综合判断,不设「下一个待派」指针(ADR-0001)。

## 6. 聚合(机械生成,不人工回算)

- 带缩进子行的任务/模块/app 的汇总状态由 `progress.py summary` 现算现输出,规则:满足(已过/不适用)数 vs 未满足(其余)数——全满足=过;满足数>未满足数=部分过;其余=进行中;全锁定/待激活=锁定。
- **不落盘、不人工维护**。账本里手写无子行依据的聚合态=违规(check 拒绝)。

## 7. 脚本(写入与体检的门)

```
progress.py init    <迭代目录> --goal "..."              # 生成入口+默认模块(流程/决策/支撑)
progress.py write   --file <模块进度.md> --topic ... --status ... [--ref|--next|--pre|--condition] [--parent ...]
progress.py check   <迭代目录>                           # 结构体检:行文法/状态-字段一致性/叙事特征词计数
                                                         # (已派|验收(|板面[:：]|判读()/行数阈值(~300行)切档提醒/
                                                         # 流水藏活任务检测/聚合态无子行依据
progress.py summary <迭代目录> [--app ...]                # 机械聚合,现算现输出
progress.py journal <迭代目录> --kind ... --text ...      # 流水 append(当日 jsonl,text ≤2K)
progress.py journal --view <日期> [--kind ...]            # 流水渲染 markdown 供人读
```

- 脚本是**纪律工具非硬门**(agent 仍可直 edit),但直改后必须跑 check;配套 check 进回顾轮/盘点提醒当体检项。两个门合起来挡惯性流水(实证:退化源于惯性非蓄意)。
- **Markdown 维护实现要点**:解析=逐行正则(行文法是严格方言,不用 markdown 库);改行=读→改→**原子写**(临时文件+rename),杜绝半写残文件;**每次变异必 journal 一条**(哪行/从什么改成什么)——.debug 不入 git 无版本兜底,流水即账本变更史,账本损坏可从流水重建(审计链与兜底二合一)。
- 格式选型依据:任务清单=行状数据+行级 append 并发安全+直改容错 → Markdown;流水=结构杂+纯机器追加 → JSONL。**主消费者决定格式,不为统一而统一**。

## 8. 继续之前任务(跨会话/loop 续)

1. `progress.py check` 或 grep 拿**未完成全集**(规范状态词,只扫 `进度.md`;「已过/不适用」不算);
2. 入口只作**定位**(在追什么目标/判据去哪查),未完成项以检索结果为准;
3. 按依赖/条件字段下钻,对待激活行逐行做条件真实性核对——特别是 sim 内可完成的验证批,实机观测只是背景不得当前置;
4. 活任务多时标当前焦点(进行中且未阻塞的最早任务);被卡住标锁定不当焦点;
5. 检索定位不上当前工作 → 偏离信号,回最近未闭环任务行。

## 9. 防偏离门(loop 每轮必过)

- **定位五元组(硬门,必填)**:焦点必填 `阶段/模块(文件) / 任务行 / 判据N / 本轮动作W`。判据 N=§12 对应 skill 模版的完成判据;填不出=偏离信号,回最近未闭环叶子。
- **产物落点校验(硬门,git diff 机械校验)**:画面/流程任务的子任务改动**不得触碰策略行为模块**(评分/权重/搜索/选择;具体路径由项目在指令文件列出)。触碰 → 过核心锁。**局内状态对象字段定义不算**。
- **核心模块锁**(改核心模块先过三解锁):
  - (解锁一·半硬)改动读取的每个「从权威源读取的字段」,其权威源的对应子任务全已过。非权威源派生值豁免。字段→权威源映射**必须记入流水或决策日志供复核**。
  - (解锁二·硬)端到端跑通有观测回路;(解锁三·硬)客观指标已定义。
  - **权威源**:该信息最完整/最准的来源,登记在项目 doc/指令文件。
- **跨阶段不变量自检(软门)**:①结论跨多样本?②动手前查文档非凭猜?③先读日志?④卡住时分清技术故障 vs 认知缺口?任一不过=偏离。致判据变化→决策日志;未致→流水。
- **进行中工件任务 ≤1(软门)**:同时「进行中」的工件级任务 ≤1。开新工件先闭环当前或显式暂停记流水。

## 10. 可观测性(可重新加载 + 可重新验证)

进度文件是任务状态的**外部持久化产物**:任意读者(未来的 session/人/任何观察者)仅凭文件本身重建「在哪/卡哪/下一步」+ 重新验证每个结论,不依赖写文件时的原上下文。

- **可观测**:状态持久化,任意时刻重建「在哪/卡哪/下一步」。
- **可复现**:每个状态标记带「凭什么」(判据/证据/来源指针),照着能重验,非盲信标记。
- **读者无关**:不区分人/AI;失了这条=退化为只有原写者能懂的自循环笔记,换 session 即失效。
- **AI 推断标源**:被当作阻塞推进的硬门/锁/前置的 AI 推断(非用户指令/代码事实/客观证据派生),必须标来源+可质疑;普通中间推断不必标(避噪音)。
- **「待确认」给可答形式**:选项 or 具体问题,非让读者替你定义概念;新黑话/缩写首现处定义。

## 11. 边界(判据不双源)

| 信息 | 归属 | 进度节点 |
|---|---|---|
| 完成判据/模版原文 | 对应 skill 模版(§12) | 只存「判据指针」 |
| 画面/工件事实 | 项目 doc | 引用 |
| 权威源映射 | 项目 doc/指令文件 | 指针 |
| 代码行为/当前值 | 代码 | 不记 |
| **验收经过/板面快照/局判读/事故** | **流水文件(journal)** | **禁入** |
| **防跑偏教训/方法论缺口** | **skill 反馈队列** | **禁入** |
| 状态变化 why/偏离致判据变化 | 决策日志(D-NN)/流水 | 节点只标 `已过 D-NN` |
| 产物成熟度(草案/`# 未验证`) | 产物标注 | 不进状态机 |
| 任务完成状态+依赖+卡点 | **账本(本方法)** | **唯一归属** |

> 在飞板面(几个槽在跑什么)不落任何文件——以子 agent 系统实况为准;写进文件的板面=过期判断(ADR-0001 已废「下一个待派」指针,板面行同罪)。

## 12. 叶子任务类型 → skill 模版映射(落实 skill)

> 进度方法论**不发明判据,只组织各 skill 的模版成账本任务行**。

| 叶子任务类型 | skill 模版 | 该 skill 提供的完成判据 |
|---|---|---|
| 画面建档 | od-dev-screen-onboarding | analyze+视觉大模型+doc+核实area+归档fixture(建档9步=多步任务用缩进子行,别早标已过) |
| operation 编写/调试 | od-dev-write-operation | 节点图+round结果+探索式主线 |
| run_op 实测 | od-dev-write-operation(run_op 微循环) | 单 op `run_operation` 实测过 |
| 代码测试(fixture/unit) | od-dev-write-operation/references/testing | fixture+unit 测试过 |
| 分支覆盖 | 对应流程 skill + 罕见态机制 | 主分支覆盖+连续 M 次无新分支 |
| UI 区域坐标检测 | od-dev-ui-region-detect | 稀疏独特→VLM/密集网格→CV投影 |
| app 编排/factory/config/GUI | od-dev-write-application | Application=Operation+factory注册(五步=缩进子行,自底向上) |
| 端到端验证/测试/成文 | 对应流程 skill | run_standalone_app跑通+ruff+测试仓+docs |
| 罕见路径验证 | 本方法自身 | 无法主动验证的罕见路径 → `待激活(条件=实机再现该子态,复查=定期盘点)`;声明 fallback 行为 |

> 各项目/玩法可能有额外叶子类型(策略迭代、数据采集等)——在对应流程 skill 的 reference 里定义。
> ⚠️ **别早标已过**:多步流程节点没走完全部子步骤(尤其交互验证/实测类)前标已过=假绿。

## 13. 涌现任务与流水的关系

- 运行中冒出的新任务,**直接 `progress.py write` 写进所属模块账本(未做)**——写入零摩擦,不需要暂存区(旧「任务收件箱/events」机制废除:它存在的理由是旧树加任务太重,新模型已消灭)。
- 唯一保留的纪律:**流水(历史)里不允许藏活任务**——check 第⑤项检测:流水条目像待办而账本无对应行=报警。过程记录归流水,可执行的事归账本,两不相混。
