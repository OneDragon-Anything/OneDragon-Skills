# 进度记录与防偏离(DAG 任务账本 + 脚本校验)

**全局方法**(不绑具体项目/玩法/框架)。适用于任何复杂多步骤开发。各工件 skill 在各自 SKILL.md 末尾有「进度模板」小节提供叶子完成判据;本 skill 组织成**任务依赖图(DAG,有向无环图:任务间「先完成才解锁」的依赖网)+ 七态状态机(含 pending_review=已交付待验、rejected=打回待返工) + 防偏离**,不发明判据。结构决策 why 见 `design/decisions/`(0004 交付-验收记账协议(待验收态,更名史见 0005)+多方自记账+文件存在门;0003 DAG 事件流账本;0002 两级平铺账本——行文法部分已被 0003 取代,其分解/依赖分离原则延续;0001 入口定位层)。

# 使用入口

**机器管的,无需人记**:节点字段完整性/状态流转合法性/依赖边存在性/环——`dag.py add/status/dep` 写入时逐条校验,非法直接打回;直改了 `dag.jsonl` 必须补跑 `dag.py check`。本 checklist 只列**脚本管不了的判断项**:

- [ ] deps vs cond 分判:「它的完成能不能由本账本一条 done 满足?」能→deps;不能→cond(§5)
- [ ] 建任务门:能写出完成判据(criteria 凭据指针)才建;写不出=还不该建(§6)
- [ ] 幽灵前置禁令:要依赖的任务账本里不存在→立项它,或降级为 cond+note 标注「立项后改 deps」(§5)
- [ ] 里程碑显式化:deps 只认任务 done;要等某任务的中间状态→把该里程碑建成独立任务(§5)
- [ ] 涌现任务直接 `dag.py add` 进账本,账本外不许藏活任务(§13)
- [ ] 恢复=§8:`ready`+`list` 拿未完成全集;`doing` 行=恢复锚点
- [ ] loop/自主推进:每轮过 §9 防偏离门(定位五元组/产物落点/核心锁三解锁/进行中工件 ≤1)

## 1. 原则

- **状态机,不是叙事**:节点状态按流转矩阵变更(机器校验);账本不记叙事——判读/经过/事故等内容住产物文档(报告/复盘 doc),账本只经 criteria/note 存指针。
- **「能不能做」是算出来的,不是标的**:可派/被挡=图查询结果,不占状态词;前置终态后下游自动就绪——不存在「忘记解锁」。
- **正本=事件流,状态=折叠**:账本只追加事件(谁/何时/对哪个任务/做了什么);当前状态由脚本重放事件现算(=折叠)。变更史=正本本身,没有「账本+变更日志」双源,不存在「忘补流水」。
- **扎根 skill,不双源**:criteria 只存凭据指针;判据标准查 §12 模版,不复制进账本。
- **写入过门**:任务节点由 `dag.py` 生成并校验;格式是校验规则不是建议。

## 2. 结构(迭代目录)

```
.debug/progress/<开工日期-内容>/
├── dag.jsonl              ← 账本正本:事件流(append-only,全部任务)
├── reports/               ← worker 完成报告(T-<N>-r<K>.md,返工轮次递增不覆盖)
└── reviews/               ← 验收官结论(T-<N>-r<K>.md,与被验轮次对应)
```

- **分类靠字段不靠目录**:`module` 单值封闭枚举(`流程`=改「走到哪」/`决策`=改「每步怎么选」/`支撑`=其余工程活)承担旧目录分模块的职能。
- **新迭代冷启动 = 直接对 `<新目录>/dag.jsonl` 跑第一条 `add`(目录自动建)**。
- **旧格式目录只读封存**:历史迭代若为行文法 `进度.md` 格式,不再写入;查历史用 grep 状态词;新任务一律进当前迭代的 dag.jsonl。
- 迭代目标单一源 = 项目指令文件「目标」字段;判据单一源 = §12 模版与玩法文档——**目录里不放目标/判据抄本**(单一源原则,ADR-0003 修订)。

## 3. 节点模型(任务 = 图节点)

| 字段 | 语义 | 必带时机(脚本强制) |
|---|---|---|
| `id` | 全局唯一 `T-N`,写入自动分配 | 恒有 |
| `title` | 一句话主题(含功能词,供检索) | add |
| `module` | 流程/决策/支撑(封闭枚举) | add |
| `status` | 七态,见 §4 | 恒有 |
| `deps` | 依赖的前置任务 id 列表;**只存这一侧**,反向查询现算 | 依赖即列 |
| `cond` | 图外等待条件 + **复查时机** | wait |
| `criteria` | 完成凭据指针(路径/commit/测试名/关键数字);**追加式**(预注册+实证共存,不覆盖) | done(验收结论) / pending_review(交付报告) |
| `assignee` | 谁在做(编排者起的可读名;`self`=主会话亲做)——由编排者在 →doing 时填,子 agent 不填 | doing |
| `priority` | 派单优先级(0..10,大者先派;缺省 0=纯图序:关键链→挡下游→id;降权延后用 wait 态而非负值)。**建任务时定数据,派单时零判断** | add 可选;`prio` 命令改 |
| `since` | 进入 doing 的时刻(自动记) | doing |
| `dead_reason` | 终态原因 | dead |

禁填:`criteria` 禁叙事(「验收过了」无凭据=过期作废);`cond` 禁出现任务 id(该建 deps 边——check 告警);`note` ≤500 字且只放注记(挂账/新证据指针),不是叙事。

## 4. 状态机(七态 + 流转矩阵)

| 态 | 语义 | 进入必带 |
|---|---|---|
| `todo` | 未开始 | — |
| `doing` | 已动手在跑 | assignee |
| `wait` | 等图外条件(非任务依赖) | cond(含复查时机) |
| `pending_review` | 已交付待验收 | criteria(交付报告指针) |
| `rejected` | 打回已裁决,返工未启动(泊位,ADR-0006) | why(结论文件指针) |
| `done` | 判据过 | criteria |
| `dead` | 不做/被取代 | 原因 |

合法流转:add→todo|wait;todo→doing|done|dead;doing→done|wait|dead|pending_review;wait→todo|done|dead;pending_review→done|doing|rejected|dead;rejected→doing|dead;done→todo;**dead 无出边**。

> 旧账本事件流里的 `review` 即本态:dag.py 读侧自动归一,`status` 命令仍收旧名(按规范名落盘+更名提醒),历史账本零迁移(ADR-0005)。

五条裁决:

1. **「被前置挡住」不占状态**——deps 未满足的任务就是 todo,可派/被挡是图算出来的;wait 只留给「等外部世界」。
2. **`dead` 是终态不可出**——依赖满足判定把 dead 视为已满足,下游可能已开工,复活会炸图;要重做=新建任务+note 注明承接。
3. **`done→todo` 回退必带 why**——下游自动回到被挡(deps 不再满足),返工影响自动传播。
4. **允许跳步**(todo→done 补记)——doing 只是「已动手」标记;防假完成靠 criteria 必带,不靠禁跳步。
5. **pending_review 与 rejected 的必带项**——doing→pending_review 交付必带 criteria(报告指针,worker 登记);pending_review→done 必带新 criteria(验收结论指针,交付报告不算数,reviewer 登记);pending_review→rejected 打回登记必带 why(结论文件指针,编排者执行)——rejected 是**打回待返工泊位**(reject 之后未必立刻返工,ADR-0006),计入 ready 队列;rejected→doing 返工派工必带 assignee(路由决策归编排者)。以上指针均过**文件存在门**(须指向真实存在的文件,相对账本目录解析)——子 agent 自登记的机械担保,假登记在写入时即被打回。

## 5. 依赖与等待(deps / cond 分判)

| | `deps` | `cond` |
|---|---|---|
| 指向 | 本账本内的任务(id) | 外部世界(无 id,不是任务) |
| 满足判定 | 机器:前置 ∈ {done, dead} 即满足 | 人:按复查时机确认条件到没到 |
| 进图 | 是(拓扑/环检测/阻断分析) | 否 |
| 满足后 | 自动解锁,自动传播 | 人工 wait→todo |

- **分判一句话**:它的完成能不能由本账本一条 done 记录满足?能→deps;不能→cond。
- **排序偏好不是依赖**:登记边前自问「没有它的产物,这个任务真的做不了吗?」答不出=只是想先做,不建边。
- **幽灵前置禁令**(幽灵前置=被多个任务依赖、但账本中不存在的任务):deps 引用必须存在(写入打回)。发现多个任务等一个不存在的行→正式立项该任务(能写 criteria 时);暂不能立项→各依赖行挂 cond+note 标「立项后改 deps」。
- **里程碑显式化**:deps 只认任务 done;要等某任务的中间状态(如「某循环达成收敛门」)→ 把里程碑建成独立任务,原任务→里程碑→下游串成链。
- **环在写入时拒绝**(加边即检测,成环打回),不做事后体检。

## 6. 建任务时机与生长

- **能写 criteria 才建**;种子只建当下可验收的粗任务(如玩法开发开局:玩法调研/流程摸索/画面初档/找兄弟——前两个无依赖可并行,后两个 deps 前者)。
- **DAG 是长出来的**:前置 done 后才可能定义出原本写不出判据的细化任务;远处留粗,变近再细化。
- **done 的双动作**:①机器——依赖它的节点自动重算就绪;②人——生长检查:「这个产出让哪些原先定义不了的任务现在可定义了?」答得出就 add,答不出不硬造。
- **不建占位空壳**(「实现」「调优」这类写不出验收凭据的大词);**不预画全图**。

## 7. 脚本(dag.py,skill 自带 scripts/ 下)

```
dag.py [--file dag.jsonl] [--actor 标识]
  add <标题> --module 流程|决策|支撑 [--dep T-1,T-2] [--cond ...] [--criteria ...]
  status <id> <to> [--assignee ..] [--criteria ..] [--cond ..] [--why ..]
  note <id> <文本>            # 注记,不改状态
  dep <id> --add T-N | --del T-N
  ready                        # 可派(按 优先级→关键链→挡下游 排序,首行=下一个任务;rejected 打回待返工计入)+doing+pending_review+wait+被挡(派单入口)
  list [--all]                 # 活任务(终态隐藏)
  graph [--mermaid]            # 拓扑视图(现算,stdout,不落盘)
  card <id>                    # 任务卡:前置状态+凭据+被依赖(派单任务书直接引用)
  who <id>                     # 它在等谁 / 它挡着谁
  prio <id> <N>                # 设优先级(整数大者先派;缺省 0)
  log <id>                     # 事件时间线+交付/打回计数(历史查询;返工熔断口径)
  check                        # 体检:重放校验/悬空边/环/必带字段/cond 泄漏 id 告警
```

- 记账分工(dag.py 已带账本级写锁,多方并发写安全):谁把任务置成某状态,谁记那条账——→doing 编排者(填 assignee)/→pending_review worker/→rejected reviewer(打回登记=裁决记录)/→done reviewer;流转合法性与必带字段由脚本写入时校验,写错直接打回。
- 直改 dag.jsonl 后必须补跑 check;check 不过的任务不得当依据派单。
- note 是账本注记(≤500 字):挂账/新证据指针/一行补充;**长内容放产物文档,note 存指针——叙事不进账本**。

## 8. 继续之前任务(跨会话/loop 续)

1. `dag.py list` 拿未完成全集(todo/doing/wait/pending_review/rejected;done/dead 终态不入),`ready` 拿可派集;
2. `doing` 行=恢复锚点:看 assignee(谁在做)与 since(何时开始);跨会话后 assignee 失效的,人工确认后回 todo 或重派;`pending_review` 行=交付待验收:结论文件已在 reviews/ 的按其结论处置(reject→打回路由),没有的补派 reviewer;`rejected` 行=打回待返工:排到返工时 `doing --assignee` 派出;
3. `wait` 行逐行核对 cond 复查时机:条件真实吗?到期没?——「没有它这个批真的跑不了吗」答不出=偏好时序,回 todo;
4. 被挡任务用 `who` 看在等谁;活任务多时标当前焦点(最早 doing 且未阻塞);
5. 检索定位不上当前工作 → 偏离信号,回最近未闭环任务。

## 9. 防偏离门(loop 每轮必过)

- **定位五元组(硬门,必填)**:焦点必填 `阶段 / module+任务id / 判据N / 本轮动作W`。判据 N=§12 对应 skill 模版的完成判据;填不出=偏离信号,回最近未闭环任务。
- **产物落点校验(硬门,git diff 机械校验)**:画面/流程任务的改动**不得触碰策略行为模块**(评分/权重/搜索/选择;具体路径由项目在指令文件列出)。触碰 → 过核心锁。**局内状态对象字段定义不算**。
- **核心模块锁**(改核心模块先过三解锁):
  - (解锁一·半硬)改动读取的每个「从权威源读取的字段」,其权威源的对应子任务全已终态。非权威源派生值豁免。字段→权威源映射**必须记入决策日志(项目 ADR/doc)供复核**。
  - (解锁二·硬)端到端跑通有观测回路;(解锁三·硬)客观指标已定义。
  - **权威源**:该信息最完整/最准的来源,登记在项目 doc/指令文件。
- **跨阶段不变量自检(软门)**:①结论跨多样本?②动手前查文档非凭猜?③先读日志?④卡住时分清技术故障 vs 认知缺口?任一不过=偏离。致判据变化→决策日志;未致→note 或产物文档。
- **进行中工件任务 ≤1(软门)**:同一工件同时「doing」的任务 ≤1。开新工件先闭环当前或显式 wait(cond=暂缓原因+复查时机)。

## 10. 可观测性(可重新加载 + 可重新验证)

- **可观测**:任意读者仅凭 dag.jsonl+脚本重建「在哪/卡哪/下一步」(`ready`/`who`/`card`),不依赖写事件时的原上下文。
- **可复现**:每个 done 带 criteria 凭据指针,照着能重验,非盲信标记。
- **读者无关**:不区分人/AI;失了这条=只有原写者能懂的自循环笔记,换 session 即失效。
- **AI 推断标源**:被当作阻塞推进的硬门/锁/前置的 AI 推断(非用户指令/代码事实/客观证据派生),必须标来源+可质疑;普通中间推断不必标(避噪音)。
- **「待确认」给可答形式**:选项 or 具体问题;新术语首现处定义。

## 11. 边界(判据不双源)

| 信息 | 归属 | 进度节点 |
|---|---|---|
| 完成判据/模版原文 | 对应 skill 模版(§12) | criteria 只存凭据指针 |
| 画面/工件事实 | 项目 doc | 引用 |
| 权威源映射 | 项目 doc/指令文件 | 指针 |
| 代码行为/当前值 | 代码 | 不记 |
| **验收经过/板面快照/局判读/事故** | **产物文档(报告/复盘 doc)** | **禁入账本**(criteria/note 只存指针) |
| **防跑偏教训/方法论缺口** | **skill 反馈队列** | **禁入** |
| 状态变化 why | **status 事件自带**(正本内天然留痕) | — |
| 产物成熟度(草案/未验证) | 产物标注 | 不进状态机 |
| 任务状态+依赖+卡点 | **dag.jsonl(本方法)** | **唯一归属** |

> 在飞板面(哪个 agent 正跑哪个任务)以子 agent 系统实况为准;账本 doing 的 assignee/since 管**可恢复与挂了检测**,不追求实时精确。

## 12. 叶子任务类型 → skill 模版映射(落实 skill)

> 进度方法论**不发明判据,只组织各 skill 的模版成 criteria**。

| 叶子任务类型 | skill 模版 | 完成判据 |
|---|---|---|
| 画面建档 | od-dev-screen-onboarding | analyze+视觉大模型+doc+核实area+归档fixture(建档9步=拆子任务,别早标 done) |
| operation 编写/调试 | od-dev-write-operation | 节点图+round结果+探索式主线 |
| run_op 实测 | od-dev-write-operation(run_op 微循环) | 单 op `run_operation` 实测过 |
| 代码测试 | od-dev-write-operation/references/testing | fixture+unit 测试过 |
| 分支覆盖 | 对应流程 skill + 罕见态机制 | 主分支覆盖+连续 M 次无新分支 |
| UI 区域坐标检测 | od-dev-screen-onboarding §4.5 | 视觉直读默认,像素级精准才 OpenCV |
| app 编排/factory/config/GUI | od-dev-write-application | Application=Operation+factory注册(五步=拆子任务,自底向上) |
| 端到端验证/测试/成文 | 对应流程 skill | run_standalone_app跑通+ruff+测试仓+docs |
| 罕见路径验证 | 本方法自身 | 无法主动验证→`wait`(cond=实机再现,复查=定期盘点);声明 fallback |

> 各项目/玩法可能有额外叶子类型——在对应流程 skill 的 reference 里定义。
> ⚠️ **别早标 done**:多步流程没走完全部子步骤(尤其交互验证/实测类)前标 done=假绿;多子步任务拆成独立任务串链,或主任务保持 doing+note 记子项进度。

## 13. 涌现任务与账本外待办

- 运行中冒出的新任务,**直接 `dag.py add` 写进账本**——写入零摩擦,不需要暂存区。
- 唯一保留的纪律:**账本外不允许藏活任务**——报告/复盘 doc/对话里出现的待办措辞,盘点轮扫到而账本无对应任务=登记缺口,当场 add。

## 14. 交付与验收记账协议

- **交付=文件,不是会话消息**:worker 完成报告落 `reports/`,验收结论落 `reviews/`,命名 `T-<N>-r<K>.md`,返工轮次递增不覆盖;账本 criteria/note 只存指针(目录图见 §2)。
- **完成报告五节**:①结论 ②判据对照表(判据/结果/凭据) ③变更面(commit hash+逐文件清单) ④验证记录(可复制命令+耗时+结果摘录,对比数字带符号定义/n/误差) ⑤偏差与未尽事项(新问题给立项建议)。小件可合并章节,判据对照/变更面/凭据三件不可省。报告是给 reviewer 降成本的对照材料,不是被信的证据。**交付含 commit**:worker 完工先提交自己文件面内的改动(逐文件点名 add、message 含任务 id、只 commit 不 push),hash 记入变更面;reviewer 验收边界按 commit(`git show`)对照,不看工作树。
- **返工熔断**:同一任务打回 ≥3 次=规格问题,停派返工,立「规格重审」新任务(新 id,note 注明承接),计数以 `dag.py log <id>` 为准。
- **兜底对账**:报告文件存在但账本无对应 pending_review 态=登记缺口,盘点轮扫到当场补(会话消息会丢,账本+文件双源对得上才算数)。
