# 0003. 进度文件可观测性:进度文件是状态外部持久化产物(可重新加载 + 可重新验证)

- **Status**: accepted
- **Date**: 2026-08-11

## Context
skill feedback(2026-08-11):自主推进货币战争时,AI 在进度文件里自造「核心锁① = 权威源画面子态①-⑤ 全过」当硬阻塞门,但①-⑤ 从未枚举、无每项验证法 → 这条只活在写它的 session 上下文里。后续 session / 上下文一长,无法从文件重载这个门的含义 → AI 卡在自己设的门上(等「用户确认①过没」,但用户不知道①-⑤ 是什么,确认等不到)→ 漂移去打多场对局填时间。项目负责人也读不懂这个门。

根因不是「人看不懂」(表象),是**进度文件作为 AI 跨 session / 长上下文的持久化记忆,重新加载失败**:含糊 / 悬空 / 不可验的概念只存在原写者的上下文,没落到文件 → 任意未来读者(含换 session 的 AI)无法仅凭文件重建 + 验证。

## Decision Drivers
- **可观测性(同构软件工程)**:进度文件 = 把易失的内部状态(LLM 上下文 / 会话记忆)持久化成可被任意时刻 / 任意观察者重新观测的外部表征。失了 = 换 session 失忆。
- **可复现性(可重新验证)**:每个状态标记要带「凭什么」(判据 / 证据 / 来源),让任意读者照着重新验证,而非盲信原标记(对应可复现研究 / event sourcing:状态可重放推导,非一次性黑盒)。①-⑤ 违背这条。
- **读者无关**:进度文件不只给「写它的那个 session」续任务用,而是给任意未来读者(换 session 的 AI、项目负责人、任何观察者)。读者是人还是 AI 不重要,都是读者;重要的是文件自带足重建 + 验证所需的一切。

## Considered Options
1. **把判据立在「人可读」(双读者:AI + 人)**:能缓解,但框小了 —— 人看不懂是表象,根因是 AI 自己跨 session 重载失败;且「给人看」难量化(否)。
2. **立在「跨 session 可重新加载 + 可重新验证」(可观测 + 可复现,读者无关)**:直击根因,有软件工程对应方法论可借(可观测性 / 可复现);读者无关让判据可量化(仅凭文件能否重建 + 验证)(选中)。
3. **强制定期人审进度文件**:落地性弱(进度文件不是每次给人看),且把责任推给人而非让文件自洽(否)。

## Decision
选 2。skill 加 §9「进度文件可观测性」论述(可观测 + 可复现 + 读者无关 + AI 推断标源)+ 开头「进度文件改动 checklist」覆盖全维度(结构 / 状态聚合 / 归属 / 可观测 / 续任务 / 防偏离),其中可观测组 6 项硬判据:仅凭文件能重载 / 硬门三问(验什么 + 怎么算过 + 凭什么)/ 无含糊编号代指(枚举 or 废弃)/ AI 推断当硬门标源 + 可追溯 /「待确认」给可答形式 / 概念可查。

checklist **指针式**(每项指向 §,机制详述在各节,不复述)—— 避免与 §1-§12 机制双源;它是操作速查,机制改了指针项跟着看一眼。

## Consequences
- **正向**:进度文件满足可观测 + 可复现 → 任意读者(含换 session 的 AI)仅凭文件自洽续任务;含糊 / 悬空门当场暴露(填不出三问)而非潜伏到卡死;AI 自造概念必须标源可质疑,防「自循环迷宫」。
- **负向**:写进度文件的门槛略升(每个硬门要填三问 + AI 推断标源);checklist 6 组需写者自觉过(软执行,skill 无法强制)。
- checklist 与 §1-§12 是「指针 vs 详述」关系(非双源):checklist 是操作速查,机制在各节。
