# 0002. 目录 vs 行:明确判据(半完成/进行中任务 = 目录;>20 是再深拆非唯一门槛)

- **Status**: accepted
- **Date**: 2026-08-09

## Context
本 skill 原 §2(每层一目录 + 叶子当行)与 §5(>~20 子项才拆子目录,否则子节点 = 各一进度行)**冲突**:§2 暗示每层一目录,§5 说小节点都当行。实际使用(货币战争进度)产生歧义 → 把**半完成任务**(如「检测方法验证了、集成没做」)当成叶子塞进父阶段表的一行,**没建任务子目录**,被用户连续纠正(「又没按 skill 建子目录结构」)。

根因:skill 没给「**节点何时是目录(层)、何时是行(叶子)**」的明确判据,尤其对「部分完成」的任务。

## Decision Drivers
- **可追踪**:半完成/进行中任务有未做子步骤,需自己的目录把子步骤展开追踪,塞进行里丢细节。
- **消歧**:§2/§5 冲突必须消,否则每次建文件都要猜。

## Considered Options
1. **保持歧义**(§2/§5 不动):每次猜,反复错(否)。
2. **只有终端叶子是行,其余都目录;>20 才更深**:接近 §2,但需明确「半完成 = 非叶子」(选中)。
3. **每个编号任务都建目录(无论叶子)**:最机械,但终端已过叶子建空目录是噪音(否)。

## Decision
选 2,明确写进 §2:**非叶子节点(有 ≥2 子步骤 / 进行中未闭环 / 多判据)= 独立目录**;**终端叶子(单一判据已验证完成 / 未开始占位)= 父表一行**;**半完成任务 = 非叶子 = 目录**(关键纠错)。§5 的 >~20 改为「**再深拆一层**」的规模门槛,**非唯一建目录条件**(建目录主判据是「非叶子」,见 §2)。

## Consequences
- **正向**:半完成/进行中任务有目录追踪子步骤;消 §2/§5 歧义;防「塞进父表当行」。
- **负向**:任务目录数增多(进行中任务都建);终端叶子仍当行控制噪音。
- 终端已过叶子(单一判据)不建目录(避免空目录噪音);规模大(>~20)再深拆。
