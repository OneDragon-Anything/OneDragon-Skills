# ADR-0010:状态词补「待激活」+ 入口三小节内容纪律

- Status: accepted
- Date: 2026-08-27

## Context

货币战争进度树治理(2026-08-27)暴露两个缺口:

1. **状态词表缺「等外部条件」的词**:已知未来工作,等的不是树内前置节点而是外部条件(实机样本积累/实机判读/排期决定/用户裁决)。执行者只能挪用「锁定」(定义=前置节点未过)或私造新词(实证:「待核」「半销」)。缺词必然挪用,不全是执行者的错。
2. **入口「工作状态」三小节的内容纪律无归属**:本 skill §1 说三小节的消费协议归 autonomous-mode 不管;autonomous-mode 管行为(派发节奏)不管文件卫生——两个 skill 都不拥有内容纪律。结果叙事堆积:完成批次的约 600 字过程叙事(内嵌 3 个真待办)、按 commit 的补记、十几个局的逐局结论摘要全进了入口。其中叙事内待办没有池行,而恢复流程按状态词 grep 全树(§7)——只活在叙事行里的待办=扫不到=丢任务。

## Considered Options

- **扩「锁定」定义,加 条件= 键**:否决——锁定与待激活的派发判法不同(看前置过没 vs 看条件到了没),混一个词后「下一个待派」的选择依据与依赖回算的辖域都变模糊。
- **补新词「待激活」(选中)**:格内容 `待激活 条件=<条件+怎么判条件到了>`;聚合计入未满足侧;恢复 grep 纳入。排期即可派的排队项仍用「未做」,防待激活滥用成新垃圾桶。
- **三小节纪律归 autonomous-mode**:否决——那是行为协议(触发/补位/盘点);内容卫生是文件层面,本 skill §1 已声明文件层面归本 skill,在此补齐即闭环。

## Decision

- §3 状态机表加「待激活」行 + 锁定 vs 待激活区分注;§4 序 2 扩为「全锁定或待激活」;§6 写完自查/§7 恢复 grep/§2.5 检索待办的 grep 模式全量纳入待激活。
- §2.5 加「三小节内容纪律」块:活状态判据(这行以后还会被消费或更新吗)+ 合法行清单 + 不进清单(过程叙事/按 commit 补记/逐局结论摘要,沉淀位=ADR/docs/commit)+ 两条硬规则:**行内待办必须入池**(否则恢复 grep 盲区)、**删叙事先清扫**(扫待办/锚点/未沉淀结论,逐个判去处再删)。
- 使用入口 checklist 加「入口三小节内容」组与「待激活别挪用锁定」条目。

## Consequences

- 正:等外部条件的工作有了诚实落点,不再挪用锁定;入口叙事堆积有判据可拒;叙事内待办入池硬规则堵住恢复盲区。
- 负:状态词 +1,记忆面微增;「未做 vs 待激活」边界(排期即可派=未做)需执行者判一次。
